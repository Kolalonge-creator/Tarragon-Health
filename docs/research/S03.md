# S03 research notes (1.1 to 1.6)

Behaviour and risks only. Original flows; nothing copied.

**1.1 Sign-up.** Health apps (Samsung Health, Apple Health) lean on an existing platform account; Tarragon has none, so the form must be short. Good: one identifier first (phone or email), password second, name later. Fails: a long form on a slow network; a typo'd phone that is silently stored; one phone shared by a family (same number on two accounts).
**1.2 Phone verification.** Good: code entry that accepts paste, a visible resend countdown, a clear "wrong number?" path. Fails: SMS delayed or blocked on DND numbers (use the OTP route, show "we'll keep trying"), `+2340...` and `0803...` typos, a code arriving after the screen timed out, SIM swap (a new SIM receives the code). Nigerian numbers: 070/080/081/090/091 prefixes, `234...` and `+234...` inputs.
**1.3 Sign-in and biometrics.** Good: biometric unlocks a stored session on that device only, password always available. Fails: shared phones (another person's fingerprint enrolled on the device passes the OS check), biometric removed after enabling (fail open to device passcode, never lock out), low-end Android without a sensor.
**1.4 Email verification.** Good: code or link with a clear "check spam" line. Fails: links opened on a different device from the one signing up, email typos, link prefetching by mail scanners consuming a one-time link (prefer a code or a confirm page).
**1.5 Passwords and rate limits.** Good: length over composition rules, a breached check that never sends the password, plain limit messages. Fails: per-IP limits alone (mobile carriers share IPs, attackers rotate them), limits that reveal whether an account exists, lockouts that let an attacker lock a real user out (prefer slowing down over locking).
**1.6 Recovery.** Good: recovery only to a verified channel, identical response whether or not the account exists. Fails: recovery by a phone number never verified, support resets with no audit, SIM swap used to take over an account by phone (recommend extra friction for accounts with a recent number change, noted in OPEN-QUESTIONS).
