# S59 research note: Module 12, assessment half (Track A only), functions 12.1 to 12.7

Sources: the build plan section 4.4 (`docs/design/S55-S60-build-plan.md`), which carries the verified and unverified markings below, and the S60 research. No product was copied; this is what shaped the design. **V** verified in the plan, **U** unverified.

- **12.1 Adaptive questions (Ada, Ubie, Infermedica).** Good products stop asking once the next step is clear and show progress. Complaints in the literature: long question runs, repeated questions, a hard stop at an alarming answer with no way back (Semigran 2015, 23 checkers, triage right 57 percent of the time, **V**). Unsuitable here: long chains on a slow or shared phone. Tarragon: the question graph ends at the first outcome node (early stop is the graph itself), and when the signed pathway equals the copy bundled with the app the whole walk runs on the device and the server is called once (a single small request). English only (D-14). Text first; voice is recorded as deferred.
- **12.2 Using the record (Infermedica; Nigeria-specific).** Age, sex, pregnancy, conditions, medicines and recent readings improve a result. Risk: an input that can also relax a result hides danger. Tarragon: inputs can only raise, by construction (an unknown value never matches, so more input only adds matches), proved by a 3000-case property test. Pregnancy is read from the person's own record only, never for someone acted for, and never copied into a summary (reproductive_health). All thresholds live in unsigned draft config.
- **12.3 Possible causes.** Not built (founder decision 2026-10-07). No possible-causes screen, mock differential or licensed adapter. The interface has no field for it and the safe wrapper drops one if an adapter sends it.
- **12.4 Six urgency levels (Buoy, Infermedica).** Products grade finely; the evidence on accuracy is vendor-claimed (**U**). Tarragon: the four-category result stays the source of truth; the six levels are a derived wording from a mapping table the CMO signs. Unsigned or invalid map: only the four-category result is shown (tested).
- **12.5 Next step (Buoy, Altibbi).** Good products end with a concrete action and a summary for the clinician. Complaint: summaries sent without the user knowing. Tarragon: the summary exists only after the patient clicks send, after seeing it; it is built in the database from the stored check; staff see it only inside the audited patient summary, and only once tied to a booked consultation. Consultations are adults only (OQ-129), so a check for a child offers messaging, labs and clinics instead of a booking.
- **12.6 Children (Ada).** A parent or carer answers through the existing acting-for model. IMCI general danger signs are public and widely taught; the three paediatric pathways (fever, dehydration with diarrhoea, breathing) are transcribed as UNSIGNED draft protocol content, not independently reviewed. Until signed, a known child is never reassured below a configured category (a proposed config) and a clinician is asked to look. The pregnancy branch is a set of draft tightening entries.
- **12.7 Photos (SkinVision; Nigeria-specific).** Automated skin cancer scoring is forbidden by the spec and its regulatory status is unverified (**U**). Tarragon: photo for a clinician only, no score, a private bucket, per-patient storage RLS, server-side metadata stripping, consent recorded, limits and retention in proposed config, review under a task, patient copy says a clinician reviews it and it is not a diagnosis. Intimate areas are not offered.
- **Decision.** Premium here means safe and honest rather than clever: floor first, only ever tighten, nothing shown that a human has not signed, nothing sent that the patient did not choose to send.
