# S70 research: Module 18, devices, wearables and data connections

Basis and honesty note. Competitor behaviour below comes from my own knowledge of the products and the S70 to S75 review (`docs/research/S70-S75-review-and-build-plan.md`, which tagged vendor claims as vendor or press claims). I could not browse in this session, so nothing here was re-verified on a live page. Clinical figures come from the CMO pack (`docs/plans/S70-S75-cmo-signoff-pack.md`), whose citations are secondary; no guideline text was read. What I did check directly is the repository: the files named in each section.

## 18.1 Bluetooth pairing (Withings, DarioHealth)
- Best products pair in one tap and hide the profile. Complaints: devices that use a vendor protocol never appear, pairing silently fails, and a patient cannot tell why.
- Checked in code: `packages/shared/src/device-readings.ts` and `apps/mobile/src/lib/ble.ts` decode five standard GATT profiles; the Devices screen already says pairing is in early testing and that typing a reading is equivalent. Never run on real hardware (CLAUDE.md, OQ-313).
- Nigeria: shared phones and Android Bluetooth permission prompts; most affordable cuffs are not standard GATT.
- Decision: keep, add nothing that implies it works. The real test of one UA-651BLE and one Accu-Chek Guide on an EAS build is still owed.

## 18.2 Recommended validated devices (Tarragon decision)
- Best practice is a short list with the validation source named (ValidateBP for cuffs). Users complain about unvalidated wrist cuffs and lists that are really adverts.
- Checked: `device_catalog` has 3 seeded rows, all inactive; affiliate links were removed (20260826174702); `apps/web/.../device-shop.tsx` already existed.
- Decision: make the CMO criteria (C5) a database constraint, so a model cannot be listed without a validation reference, NAFDAC status or authorised distributor, and a distributor name. Show the distributor and how it connects. Manual entry is the first line on both screens. Seed nothing; the founder supplies models.

## 18.3 Photo capture of a device screen (Nigeria-specific)
- Closest products read a meter or cuff with the camera and ask the user to confirm. Complaints: misread digits saved silently, glare, seven-segment displays.
- Nigeria: many home cuffs have no Bluetooth; low bandwidth means the photo must not upload.
- Decision: photo stays on the phone; parsing is a pure TypeScript layer behind a recogniser interface; the patient ticks that the numbers match; saved as a device-source reading with a photo-confirmed flag on the manual path. No recogniser is installed (needs a native module and a new EAS build), so today the screen shows the photo beside empty fields. I did not claim OCR works.

## 18.4 Wearable connections (Oura, WHOOP, Garmin, Fitbit, Withings)
- Checked: five cloud adapters, Health Connect and HealthKit bridges exist and wait on developer credentials. WHOOP v1 removal and Garmin Push versus Ping notes are in CLAUDE.md.
- Decision: a typed `DeviceSource` description over the existing adapters; Withings is a slot (enum value only), Samsung is reached through Health Connect. No flow is faked.

## 18.5 Continuous glucose (Abbott, Dexcom, Levels)
- Checked: Dexcom adapter writes `source = wearable`; the partner route writes `source = cgm`. `ingest.ts` skips the app-layer glucose assessor on purpose. The DB backstop (20260807090308) already raises an emergency for a single value under 3.0 mmol/L, which I found while reading; that means a one-sample sensor dropout can already page. Noted as OQ-345.
- Decision (C2): sustained-event rules in a trigger, thresholds in versioned `device_config`, a clinician task, the existing emergency record for a sustained severe low. The paid two-week programme is not built (OQ-318).

## 18.6 Single-lead ECG (KardiaMobile)
- Best products show their own cleared result and recommend clinician review. Unsafe: our own algorithm or diagnosis wording.
- Checked: `@kingstinct/react-native-healthkit` 14.0.2 exposes `queryElectrocardiogramSamples` (read in `node_modules`). The upload path (`ecg_report_*`) is a 12-lead report flow for clinicians.
- Decision (C3): the device's own classification is mapped, an irregular or inconclusive result becomes a routine task within one working day, the patient is told only that their care team will look. HealthKit read is on tap only, never at startup, and has never run on a device.

## 18.7 Inhaler sensors (Propeller)
No Nigerian distributor and no clinical protocol. Not built; the `DeviceSource` slot records why.

## 18.9 Source label and plausibility (Apple Health)
- Checked: `vitals_readings.source`, validation flags (20260828185821), the source lock trigger, S38 snapshots excluding flagged rows. The existing `duplicate_entry` flag only catches identical values within two minutes.
- Decision (C1): a link table (the source lock forbids editing the earlier row, and the better reading can arrive later), tolerance and windows in config, a counted view. Linking never touches the red-flag triggers.
