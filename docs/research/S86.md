# S86 research: adding languages safely

Method: public descriptions and the repo's own audit. Nothing was run against these products. Items marked (unverified) were not checked against a primary source in this session.

## Language-matched care (Practo)
- Practo is reported to have launched consultations in many Indian languages by matching patients to doctors who speak their language, rather than translating clinical content (unverified: taken from the S85-S87 plan, which cites a 2021 announcement).
- Lesson: the safest near-term answer to "serve a Yoruba, Hausa or Igbo speaker" needs no translated clinical strings. Tarragon already holds a free-text clinician `languages` field (kept by D-14). Recommend surfacing it in matching later (S64).
- Unsuitable for Nigeria as copied: a language filter that promises availability, because clinician supply by language is thin. Show it as a preference, never a guarantee.

## Forward and back translation (ISPOR task force guidance)
- The widely used process is forward translation by two translators, reconciliation, back translation, comparison with the source, then cognitive testing with real users (unverified in detail: recalled from the 2005 ISPOR principles of good practice, not re-read).
- Lesson: an independent back translation catches meaning drift that a fluent reviewer misses. The framework records one sign-off per string set, so back translation and reconciliation are process steps before the native review, not extra code.
- Unsuitable: a back translation done by a model is not independent. No model is called anywhere here.

## ISO 17100 (translation services)
- Requires a qualified translator, a second linguist who revises the work against the source, and a process record; review by a domain expert is an additional step (unverified: recalled, the standard text is paywalled).
- Lesson: revision must be by someone other than the translator, and the domain expert for Tarragon is a clinician. The registry therefore holds two separate sign-offs for a clinical feature (native review, then CMO).

## Versioned, owned, dated content (Healthily, Ada, Infermedica)
- These products publish clinically reviewed content per market, dated and owned (unverified in detail).
- Lesson already in the repo: `clinical-wording.json` and the audio manifest `script_hash` do exactly this. Reused, not reinvented. A sign-off here carries a fingerprint of the text signed, so a one word edit invalidates it.

## Audio
- A recording signed for one script is a different thing once the script changes. The manifest already drops approvals on a script change; the gate adds the same check for a translated clip against the English script it was made from.
- Unsuitable: text to speech in a language no native reviewer has heard. English only stands (D-14).
