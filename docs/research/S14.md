# S14 research: provider adapters

Written from the vendors' published documentation and public product behaviour as known at the time; nothing here was run against a live account. Every vendor limit below is a thing to re-check in the session that wires the real adapter (S21, S23, S25, S31), not a fact to build on today.

## Payments (Paystack; reference behaviour from Practo, Okadoc, Vezeeta checkout)
- A payment is a transaction with a caller-chosen unique reference. The browser callback is never proof of payment: confirm by signed webhook and by calling the verify endpoint, then compare amount, currency and reference with the order. Idempotent on the reference.
- Webhooks arrive more than once and out of order, so every handler must be safe to repeat. Paystack has no event id; derive the key from event type plus reference.
- Amounts are in the smallest unit (kobo). Refunds are asynchronous: "refund created" is not "refund settled".
- Nigeria: card, bank transfer and USSD all exist, and bank transfer and USSD can sit pending for minutes. A pending state is normal, not an error. Never show a failure screen on pending.
- Unsafe or unsuitable: any wallet, top-up or stored balance (INV-09); keeping card data; trusting `callback_url` query strings; a mock that can report success in production.

## Video (Teladoc, Kry, Doctolib, Okadoc, Vezeeta)
- Short-lived, role-scoped join tokens, a waiting room, and room names that carry no patient detail. The room id is opaque; the encounter id stays in our database.
- Providers (Daily, Agora, 100ms) all expose connection-quality events and let a client drop the camera track and keep audio. That is the audio-only fallback, and it must be triggered by sustained poor quality, not one bad sample.
- Nigeria: mobile data is paid per megabyte, 3G and power cuts are normal. Reconnect must resume the same room; audio-only must be one tap for the patient and automatic after sustained loss.
- Unsafe or unsuitable: recording by default (needs its own consent and retention decision); putting names or conditions in a room title or token claim.

## Speech to text (Abridge, Nabla, Suki)
- Ambient scribes ask for consent at the start of every visit, produce a draft, and a clinician edits and signs before anything reaches the record (INV-11). Transcript segments carry timestamps and, where the engine can, a speaker label.
- Streams drop. A good interface lets a caller stop, restart and keep the segments already received.
- Nigeria: Nigerian English and Pidgin accuracy is the open risk. No vendor is chosen (D-08) and none should be until it has been scored on real Nigerian consult audio, including drug names, which are the costliest errors.
- Unsafe or unsuitable: starting a stream without a recorded consent; keeping raw audio longer than the transcript needs; logging transcript text (it is health data).

## Email (Resend; Postmark and SES as comparators)
- Transactional email needs an idempotency key so a retried job never sends twice, and a delivery webhook (delivered, bounced, complained) so a hard-bounced address is suppressed. S13 already records those events.
- Nigeria: Gmail and Yahoo dominate and are strict on authentication, so the sending domain needs SPF, DKIM and DMARC before launch.
- Unsafe or unsuitable: subjects and preview text that name a condition or result (INV-07); attachments whose file name names the request (OQ-91).
