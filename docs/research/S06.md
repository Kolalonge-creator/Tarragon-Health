# S06 research: offline logging and sync (short)

Studied for behaviour only, nothing copied.

- **Local-first write**: MyTherapy, Strava and Oura save the entry on the phone first and show it at once; the user never waits on the network. Adopted.
- **Visible sync state**: Strava shows an upload queue with per-item status; WHOOP and Oura show "syncing" and last-synced time. Adopted as a per-row state and one banner. Unsafe: a bare spinner that hides a rejected item. Never silent.
- **Idempotency**: MyFitnessPal and Strava dedupe retries by a client-generated id. Adopted (`client_id`).
- **Conflicts**: patient-authored observations and doses are append-only; the server wins on clinician-authored rows (medications, care plan). Adopted.
- **Time**: Oura and WHOOP keep the sensor's time, not the upload time. Unsafe here: an unbounded client clock lets a patient backdate. Adopted a bounded window with the server time as fallback.
- **Reminders and doses (MyTherapy, CareClinic)**: allow logging a dose after the fact. Adopted within the window; never edit a prescription offline.
- **DarioHealth, Omada, Propeller Health**: readings sync later from a device and the care team sees them on arrival. Adopted the honest delay message; none of them promise instant clinician awareness offline, and neither do we.
- **Nigeria**: patchy signal, power cuts, 2 GB phones, data cost. Drafts saved on each change, tiny payloads, exponential backoff with a 30 minute cap, no auto-download. Unsuitable: always-on polling, large background pulls, silent drops after N failures.
- **Noom**: streak pressure copy ("you missed a day") is unsuitable; an unsynced row must never be described to the patient as a missed log.
