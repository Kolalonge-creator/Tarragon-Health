# S34 research: low-data mode, accessibility, performance, app size

Public docs and published guidance only. Adapted, not copied. Sources at the end. Product behaviour of named apps is from press coverage, not re-tested.

**Low-data mode.** Facebook Lite, YouTube Go and Google's Go apps cut data by showing text first, offering resolution choices, and letting people download over Wi-Fi to use later. YouTube Go shows a preview before a download, so people choose what to spend data on. Adopt: one profile switch (`profiles.low_data_mode`, already exists) that stops every automatic media fetch, with a size shown before any download and downloads on Wi-Fi only. Avoid: a lite mode that hides safety content; emergency guidance and red-flag checks never depend on it. Nigeria: data is expensive, so default the switch on when the phone is on mobile data at first run only if the patient agrees.

**Offline-first sync.** The lite apps keep the core job working with no signal. Tarragon already has this (outbox, mirror, S06). Adopt: show a plain "saved on your phone, will send later" state. Avoid: any spinner that blocks a reading from being saved.

**Text size.** Studies of older users report fewer reading errors with progressive text scaling. Adopt: follow the phone's text size up to 200 percent (already `MAX_FONT_SCALE = 2`), and keep key numbers (a blood pressure reading) readable at that size without clipping. Avoid: fixed pixel heights on text rows.

**Contrast and colour.** Guidance for older users points to the AAA ratio of 7 to 1 for important text and never using colour alone. Adopt: measure current ratios in tokens.test.ts first, then aim clinical status text at 7 to 1 where the palette allows, and pair every green, amber and red state with a word and an icon shape. Avoid: red and green dots with no label. Nigeria: bright sun on a cracked screen lowers real contrast, so margins matter.

**Touch targets.** WCAG 2.2 sets 24 px as the minimum, 44 as the enhanced level; iOS says 44 pt, Material says 48 dp. The kit already holds 44. Adopt: 48 for primary actions and for the dose and reading buttons, with spacing between them. Avoid: icon-only buttons without a label.

**Screen readers.** TalkBack and VoiceOver need a label, a role and a state on each control, and a sensible reading order. Adopt: a lint test that fails when a touchable has no label, and number fields that read the unit ("120 over 80 millimetres of mercury", not "120 slash 80").

**App size.** React Native size guides agree on the same levers: Hermes, per-architecture builds or an app bundle, R8 shrinking, trimming fonts and images, and no unused native modules. Reported savings are large but vary, so measure Tarragon's own build. Adopt: a size report in CI (APK and AAB per ABI), a budget that fails the build on growth, and an audit of native modules added in Phase 0.

**Cold start.** Adopt: measure time to first interactive screen on a real mid-range Android, keep the launch path to the local store, and defer audio, charts and fonts that the first screen does not need. Avoid: reporting a number from a simulator.
