# S11 research: triage engine

Reference platforms studied for behaviour only. Written from public product documentation and published guidance as known when this was written; no live browsing was done in this session, so re-check anything that matters for a clinical decision. Nothing copied.

**Traffic-light grading of a home reading (Omada Health, Livongo-style programmes, NHS "Hypertension at home" guidance).** Published home programmes split a reading into "keep going", "recheck" and "contact us now" bands and show one plain message per band. Adapted: three grades, one message key per outcome. Unsuitable as is: US 911 wording and per-band phone numbers; the app says "go to the nearest hospital" and never prints a number (repo decision, PR #785).

**Repeat reading before alerting (AHA and ESH home-measurement guidance; Omada's flag-then-recheck prompt).** An isolated high home reading is commonly a technique or rest problem, so programmes ask for a repeat after about 5 minutes of rest before raising a review. Adapted into BP-A1 and the 15 minute fallback. Unsafe if applied to a symptomatic or very high reading: those never wait for a repeat here (BP-R1, BP-R2 run first).

**Symptoms override numbers (WHO HEARTS, ESH/ESC emergency criteria).** A severe-range reading with headache, chest pain, breathlessness, weakness, confusion or visual change is a hypertensive emergency pathway; the same number without symptoms is urgent review. Adapted as BP-R1 versus BP-A1. The symptom list is a closed set of codes so a free-text symptom can never silently fail to match.

**Low pressure with faint or confusion (clinical practice; WellDoc and Glooko do this for glucose lows).** Low readings matter when paired with symptoms; a low number alone is usually not an emergency. Adapted as BP-R3 and BP-A3. Open for the CMO: no guideline fixes a home low-BP number (OQ-67).

**Average over a window with a minimum count (Omada eligibility rule, BeatO and Health2Sync trend cards, ESH home protocol).** Decisions use an average of several days, never one number, and only once enough readings exist. Adapted as BP-A2 (7 days, at least 5 readings). Readings the validator rejects are excluded from the average.

**Adherence and silence nudges (Noom, Lark Health, Oviva, DarioHealth).** Programmes watch missed doses and gone-quiet users and respond with a human check-in, not an alarm. Adapted as BP-A4 and BP-A5: amber review tasks for the care team, never a patient-facing warning, and one open task per cause (the engine returns a stable task key so a daily check cannot pile up duplicates).

**Pregnancy and children (Propeller Health and Kaia Health scope their rules to adults; obstetric BP bands differ).** Adult rules misgrade both groups, so the engine routes them to a clinician (amber referral) after the red rules, and never silently applies adult bands. Unsuitable for Nigeria as an assumption: pregnancy is common and under-booked; the CMO needs to decide whether severe-range pregnancy readings should be red (OQ-86).

**Determinism and audit (clinical decision-support practice, IEC 62304 style traceability).** Same input and same rule set give the same output; every result names the rule and rule-set version. No language model anywhere in the path (INV-01).
