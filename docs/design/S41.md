## 2. Data model (migration `20261007230154_s41_onboarding_answers_and_lga.sql`)

- `public.onboarding_answers(id, organisation_id, patient_id, question_code in ('goals','conditions'), answer jsonb array, answered_at, source = 'patient_self_report', recorded_by = patient_id, is_test)`, unique per patient and question. RLS: the patient reads their own rows; no insert, update or delete grant; `anon` has nothing. Written only by `public.save_onboarding_answers(text[], text[])` (SECURITY DEFINER, patient role only, validated, audited, one outbox event). Option codes live in `private.onboarding_option_ok`; `packages/shared/src/onboarding-answers.ts` mirrors them and a scan test fails on drift.
- `profiles.lga text` with a 2 to 60 character check. No canonical list (OQ-292).
- Event types `onboarding.answers_saved` (emitted, payload is a count only) and `cohort.joined` (registered; `join_cohort` should emit it once #988 is on the branch, OQ-293).

## 3. Edge functions and the entitlement seam

- No `cohort-join` edge function: `public.join_cohort` is the atomic path (row lock, same answer for unknown, expired, closed and full codes, ten bad tries an hour per person). A function in front of it would add a second place to get the limit wrong.
- **Entitlement seam (S26):** a code claims eligibility and nothing else. `join_cohort` creates no order, no entitlement and no discount, and S41 adds none. When S26's entitlement table is used for sponsored cohorts, the creation belongs inside or right after `join_cohort` in one transaction; until then onboarding says "anything your programme includes will show up here once it is switched on". There is no stub that grants.
- Sponsor reporting stays aggregate-only with a minimum cell (S38e): the larger of the platform `min_cell` and the sponsor's `min_cohort_size`, only members who agreed, test accounts out.

## 4. Screens

- Onboarding: `AnswersStep` (goals, conditions) first; consent; demographics; location (now with LGA); optional blood group and genotype card; optional programme code; questionnaire; plan preview. Answers are held in the page and saved after the terms are agreed, so a condition choice is never stored first. A failed save never blocks setup.
- Home: `YourFocusCard` (up to three cards, fixed order, links to existing pages) above Quick actions. Not shown when acting for someone, or with no answers.
- Sign-up: `EmailCodeBox` under "check your email" (optional, link still works).
- Narration seam: `OnboardingNarration` shows the S32 script text and says spoken help is not ready.

## 5. Safety rules

- The answers never change a threshold, a rule or a recommendation; a condition choice is the person's own words, not a diagnosis.
- Not stored before consent; not readable by staff (INV-12 spirit); the event payload carries a count, not a choice (INV-07 spirit).
- A code is eligibility only; joining shares nothing; failure of a code is one plain answer.
- Notifications: none added, so the INV-07 lint has nothing new to check.
- No language model anywhere in this path (INV-01).

## 6. Go-live guard

Nothing here is clinical content, so no new guard is needed: the answers only order existing cards. The sponsor consent text (`sponsor_reporting`) is a draft with `is_current = false` until counsel approves it (S38e), so no sponsor figure can exist yet.

## 7. USSD (1.7): not built, design note only

Seam, if it ever returns: `ussd_pins(profile_id, pin_hash, failed_attempts, locked_until)`, a PIN hashed with a per-row salt, five failures then a one hour lock, no clinical data in a session, verification only. Risks to settle first: the aggregator sees the PIN in clear (so it can never be a reused password), INV-08 allows SMS only for auth codes so a USSD session needs a recorded exception, SIM swap applies the same as to SMS codes, and an MNO short code has a cost and a licence that nobody has quoted. Founder decision 2026-10-07: no new vendor now.

## 8. Not done here (and why)

- OQ-41 (roster claim before verification) and OQ-52 (unverified accounts for any number) change a core trigger and the org assignment of a new account. Written up with a new finding in `docs/OPEN-QUESTIONS.md`, not changed (OQ-290).
- Mobile has no onboarding flow, so the answers step, the code box and the email code have no mobile screen. The shared module and the RPC are ready for it (OQ-294).
