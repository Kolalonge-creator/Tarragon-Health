# S58 design: Module 11, Rewards and engagement

Branch `s55-60/s58-rewards`, stacked on `s55-60/s55-learning-centre` (which carries F1: points non-monetary, and S55's `lesson.completed` and `course.completed`). Migrations `20261007170413`, `20261007171826`, `20261007173209`.

## Reconciliation (what already existed, reused)
`wellness_points_config` (singleton, rate dropped by F1), `wellness_points_balances`, `wellness_points_ledger` (with the `(patient, source, reason)` idempotency index), `wellness_points_redemptions` (F1: refuses inserts, history only), 10 badges with a generic evaluator, challenges with a daily cron evaluator, classes, earning triggers that typed their points into trigger bodies, patient web and mobile screens, an admin catalogue page. There were no unit tests: `s58_points_characterisation.sql` was written first against that state and still passes after the change (idempotency per source, balance maths, no negative balance, redeem RPC inert). Spec names map as in the plan: `points_ledger` is the ledger, `reward_rules` is new (the old config is a singleton), `reward_redemptions` is new (the old table stays as history).

## Data model
- `reward_config` (versioned PROPOSED values, mirrored in `packages/shared` proposed-config with a drift test): plausible ranges, daily points cap, minor age, tiers, streak grace, leaderboards (off), redemption (`max_share_bps`, `points_per_percent`, `min_points`), kobo cap (0), employer minimum group.
- `reward_rules` (code, version, trigger_event, points, points_source rule or catalogue, caps jsonb, verified_action, is_active, status): CHECK refuses body-metric words in code, trigger event and caps; `reward_kind` can only be `fixed`, so no chance-based reward can exist for anyone.
- Ledger gains `rule_code`, `rule_version`, `event_id`, `kind` (earn, spend, release) and becomes append-only (a cascade from a profile purge still works).
- `points_award_decisions` (event, rule): the replay record and the "why no points" trail. No patient grant.
- `reward_redemptions`: order-linked, unique per order, integer kobo, percentage based. Trigger plus CHECKs restate every cap.

## Events and awarding
Emitters (vitals except weight and waist, meals, medicine check-in, lifestyle task and goal, class, challenge, screening result) write ids-only domain events; failures are audited and open one incident, never raising into the patient's write. Subscribers (one per event type, handler `points.award`) call `points_award(event_id)` (service role only). It checks the decision record, eligibility (plausible range from config, never a body measure), per-day, per-week and lifetime caps, decay weights, the all-rule daily cap, writes the ledger, emits `points.awarded` (ids only) and runs badges. Existing events reused: `lesson.completed`, `course.completed`, `lab_result.released`, `encounter.completed`.

## Safety rules and where each is enforced
- Never for body size: table CHECK, emitter skips weight and waist, scan test over rules, copy test over strings.
- Plausible only: eligibility function reads `rewards.plausible_ranges`. A dangerous but plausible reading still earns (the points path never reads or alters triage).
- Red flow first: awarding is asynchronous off the outbox; the emitter trigger sorts last among the vitals triggers (test pins the name); a broken bus never refuses the reading and the triage event still exists (tested).
- No stored balance of money, no rate: points are a count; the discount is a percentage of one order; self-checks assert no column or function carries a points-to-kobo rate; app scan test too.
- Minors: no tier, no redemption; no variable reward exists (constraint).
- No streak guilt: a streak is only a badge condition with grace; no counter resets; no notification is sent for points at all (INV-07 by absence); copy test bans loss wording.
- Leaderboards off (config), RLS gives each person only their own rows (tested).
- Redemption go-live guard: `reward_config.points_redemption_cap_kobo = 0`. `apply_points_discount` refuses until the founder sets it.

## Screens
Patient web (`/patient/wellness`) and mobile wellness screen: balance, level (computed by `my_points_status`), how you earn (verified actions first, daily-limit note), "use points at checkout: coming soon", recent activity, badges. Admin `/admin/settings/reward-rules` (rules as new proposed versions, 30-day aggregate summary) with a search entry and keywords. i18n namespace `points` (English only: the repo removed Pidgin on 2026-10-06; the brief's `pcm` does not apply).
