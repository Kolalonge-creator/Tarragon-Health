# S59d design note: more symptom pathways (drafts) and the automatic accuracy-audit feed

Branch `feat/s59-pathways-and-audit-feed`, off `origin/main-dev`. Nothing is applied to production, deployed, signed or switched on. `symptom_checker_enabled` stays OFF.

## 1. Reused, not rebuilt
The triage engine and pathway schema, the S59 paediatric/adult-v2 merged draft migration pattern, `risk_tightening` and `context_tightening` (raise-only), the bundled red-flag floor, `triage_protocols` signing (`sign_triage_protocols`, CMO), the S60 audit (`run_symptom_accuracy_audit`, Wilson intervals, suppression), S59 summaries, S21 appointments and encounters, S22 amendments, `can_staff_read_clinical`, `audit_chart_read`, the S10 outbox, the S39d data registry, the S04b-1 minor guard.

## 2. Pathways (part 1)
Four DRAFT pathways in ONE unsigned, inactive `triage_protocols` version (migration `20261022095021`), a strict superset of the S59 draft: `fever` (redraft of the v2 draft, same key, every old rule key kept; an untested fever can no longer end in self-care), `pregnancy_danger_signs`, `hypertension_complication`, `diabetes_complication`. Source of truth `packages/symptom-triage-engine/src/protocols/s59d-drafts.ts`; the migration JSON is a byte-compared copy. Sources, what could not be verified and the CMO's questions: `docs/research/S59d-pathway-coverage.md`, also shown beside every rule on the CMO sign-off panel (`ProtocolRulesDetail`, a read-only "read every rule" view added to the triage-protocols manager; it changes and signs nothing).
Safety properties (tests): a red flag is final; no red flag below urgent; no walk outcome is an emergency; complication and pregnancy pathways never end in self-care; more input never lowers urgency (4,000 random pairs plus a sabotage case); chest pain with sweating stays an emergency; a draft is never live: `liveProtocolConfig` needs an ACTIVE row with `approved_at` and `approved_by`, `livePathways` gives nothing for a draft and the safe engine escalates; the web loader `getActiveTriageProtocolConfig` now uses it. Hooks: `symptom.risk_tightening` v3 (travel via the new optional `any_trigger`, rainy season, Lassa, all matched on the fever complaint) and `symptom.context_tightening` v3 (recent blood pressure, glucose, pregnancy with fever or belly pain); all draft, unsigned, inert. Forty new `symptom.opt.*` labels. Reproductive-health pathways were NOT drafted (OQ-S59d-06).

## 3. Data model: the audit feed (part 2, migration `20261022095845`)
`clinical_encounter_notes.diagnosis_code` (ICD-10 shape, set on a draft by `set_encounter_note_diagnosis_code`, frozen by the existing signed-note immutability). `symptom_encounter_outcomes`: one row per assessment and signed note, with the signer as `recorded_by`, the code, the checker's category and the category the patient was given (snapshot), and `mapped_category`/`mapping_version`/`agrees` which are NULL until the CMO confirms a map. `symptom_diagnosis_urgency_maps`: v1 is an unsigned, inactive draft mirroring the PROPOSED `symptom.diagnosis_urgency_map`; `confirm_symptom_diagnosis_urgency_map` (CMO only) activates one and fills the NULLs once. RLS on, NO policy and NO grant on the outcome table; guard trigger (no delete, only retract or fill the map); registered in the data registry and the under-18 guard.
Chain: assessment -> sent summary tied to a booking -> `appointments.video_consultation_id` -> completed S21 encounter -> finalized note of that consultation with a code. Written when the last of "encounter completed" and "note signed" happens (two AFTER triggers, one function), idempotent. A signed amendment retracts the original's row; a coded amendment writes its own. Both triggers swallow their errors (audit row plus incident): signing and completion never depend on the feed.

## 4. Events and reads
`symptom_outcome.recorded` and `symptom_outcome.retracted` on the outbox, ids only. Staff read one assessment's outcome through `read_symptom_outcome_audited` (reviewing clinician, per-patient tie, audited allow and deny). No staff-wide list, no patient read, no `is_org_staff`.

## 5. The audit
`run_symptom_accuracy_audit` now takes manual completed reviews plus active auto rows that have a computed category (each assessment once, manual wins) and adds a `source` dimension (`manual_review`, `encounter_auto`) with the same Wilson intervals, minimum cell size and complementary suppression. Still immutable, never publishable, first non-empty report is the baseline; an unmapped row can never make one. The monthly job also picks organisations with only auto rows. A retraction after a report was generated does not rewrite it.

## 6. Safety rules that did not move
Nothing alters the patient-facing result or any clinician decision. Only signed diagnoses count. No LLM. No guard flipped. Third migration `20261022100048` adds NOT VALID `triage_protocols_active_requires_signature` (active needs a signature).
