## 2. Decisions for this session

- **`profiles.language`, not `preferred_language`.** Live column is `language` (text). The spec name loses to live (OQ-23). No rename.
- **SMS stays code-only.** OQ-32 (remove every other patient SMS path) is its own session. S03 does not touch those paths. INV-08 test in S03: the new provider module is importable only from the hook, and a **ratchet** lists the five files that actually hold the Termii key or URL (`send-pending-notifications`, `abnormal-result-handler`, `paystack-webhook/handler.ts` sponsor invite, `send-patient-link.ts`, and `check-dependencies.ts`, which only reports "configured") so none can be added and OQ-32 can only shrink the list. The clinician escalation actions, admin page, claim page and status route only mention Termii in comments.
- **Termii is not live.** Hook ships with `SMS_PROVIDER=mock` default. Flipping to `termii` is a configuration act after the sender ID is approved (D-05, OQ-21).
- **Device-recognition notice** goes in-app and by email only (already the case); wording stays neutral (INV-07).
- **Assisted recovery approver:** superadmin only, reason of 20+ characters, written to `audit_log`, never sets a password itself: it issues a one-time recovery link to the **verified** email or re-verifies a **new** phone by code, so nobody can silently take over an account. No new account role (OQ-24).
- **Console sign-in (OQ-34):** unchanged, email and password plus TOTP.

## 3. What S01c and S01d already changed

S01c removed WhatsApp, so there is no WhatsApp branch to extend. S01d moved staff sign-in to `apps/console` and shared credentials to `@tarragon/auth`; new shared validation goes in `@tarragon/auth` and `packages/shared`, not `apps/web/src/lib`.

## 4. Manual steps (not doable from code or this session)

1. Supabase dashboard: enable Auth hook "Send SMS" pointing at `auth-send-sms-hook`, set the hook secret (`SEND_SMS_HOOK_SECRET`), set minimum password length 8, phone OTP length 6 with 60s resend, and confirm "Confirm email" is on.
2. Do not set `SMS_PROVIDER=termii` until the sender ID is approved.
3. Provision Upstash (limiter is per-instance until then).
4. A fresh EAS build is required before any OTA publish if a native dependency changes (none added by S03).
