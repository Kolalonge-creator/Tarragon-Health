# S59 design note: Module 12, assessment half, Track A only (spec lines 1386 to 1440, functions 12.1 to 12.7)

Branch `s55-60/s59-assessment`, stacked on `s55-60/s60-symptom-safety` (which stacks on F1). `symptom_checker_enabled` stays OFF and every new patient entry point is unreachable while it is off (database refusal 42501 plus app check, both tested). Nothing is applied to production.

## 1. Reused, not rebuilt
The triage engine and signed v1 pathways, `symptom_triage_assessments` and its triggers, S60 fail-safe wrapper, bundled red-flag floor, `risk_tightening`, `symptom_reviews`, `NotADiagnosis`, F1 guard, S16 tasks (`symptom_review` type reused for photos), S35 patient summary, S21 appointments, acting-for (`resolveSubjectId`), `can_read_clinical`, `audit_chart_read`, S10 outbox, the proposed-config registry.

## 2. SymptomEngine (12.1)
`packages/symptom-triage-engine/src/adapter`: interface `start`, `answer`, `result`; the in-house adapter over `runTriage`; `createSafeEngine` wrapper (floor first, an adapter cannot downgrade a red flag or swap the capture, error or timeout escalates, only contract fields pass, so possible causes never reach a caller, no model). `contract-suite.ts` (import path `@tarragon/symptom-triage-engine/contract`) is the suite every future adapter must pass: it applies eight faults to the adapter and checks chest pain with sweating is always emergency. Sabotage proof: removing the floor fails the suite. A source scan test forbids model or network use. The web `runSymptomCheck` now goes through this wrapper; the older engine-function test seam is wrapped as an adapter.

## 3. Tightening layers (12.2, 12.4, 12.6)
Inputs from `symptom_check_context` (own record whole; acted-for record category-scoped and never pregnancy). `applyContextTightening` (PROPOSED `symptom.context_tightening`, all entries unsigned drafts, inert), `symptom.dependant_policy` (live proposed value: known child never below routine, a clinician asked to look), S60 `risk_tightening`. Property test: more input never lowers urgency (an unknown value never matches). Urgency levels: `symptom.urgency_map` unsigned draft; valid only when signed, total, monotone and emergency maps to the top level; otherwise only the four-category result shows (tested on the shipped draft). Derived level stored on the row as `urgency_level` with `urgency_map_version`; nothing reads it back.

## 4. Data (migrations 20261007181407, 182139, 183052, 184418)
1. Assessment columns `engine`, `engine_version`, `inputs_used` (names only), `raised_by`, `urgency_level`, `urgency_map_version`; view `symptom_sessions` (security_invoker, patient or the person who ran it or a care-circle grantee, no staff path, no possible_causes column); `symptom_check_context`; `read_symptom_session_audited`.

Shown only while the linked appointment is open.

Clinician: `/clinician/skin-photo-reviews`, summary card inside the patient summary. Admin search entry and navigation added. Strings under `symptom.*`.
