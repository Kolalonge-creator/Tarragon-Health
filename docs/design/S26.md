## 2. Decisions for this build

1. **Entitlement lifecycle** is a state machine on `entitlements.state`: `active -> expired | used | revoked`. A pg_cron job (`private.expire_entitlements`) runs daily and moves past-`ends_at` rows to `expired`. `remaining_uses` decrement is done by `public.consume_entitlement(entitlement_id)` (service role); hitting 0 sets `used`. `revoked` is set by `public.revoke_entitlement(entitlement_id, reason)` (admin, on a refund).
2. **Care pack is 3 months (90 days, PROPOSED).** `catalog_items.duration_days = 90` for the care_pack kind. Never auto-renews. A new purchase is a new order and a new entitlement; no extension, no rollover.
3. **7-day renewal reminder (CON-010).** `private.queue_entitlement_expiry_reminders()` runs daily via pg_cron. For every `active` entitlement with `ends_at` between now and now + 7 days that has not already been reminded (a `reminded_at` column), it queues an in-app notification (template `entitlement_expiring_soon`, content_class `transactional`) and sets `reminded_at`. The notification says the pack is ending soon and links to the purchase page. No auto-charge.
4. **Refunds table** (`public.refunds`): `order_id`, `amount_kobo`, `reason`, `state` (pending/processing/completed/failed), `provider_reference`, `requested_by`, `decided_by`, `decided_at`. A refund moves the order to `refunded`, revokes the entitlement, cancels the revenue schedule (S25b trigger handles schedule), and posts a reversing journal entry (Dr deferred-revenue or revenue / Cr clearing). The Paystack call is made by a server action (admin-only), not a cron.
5. **OQ-127 cancellation refund rule** (decided 2026-10-06): full refund >= 2 hours before consultation; fixed retention inside 2 hours (PROPOSED config). Clinician cancel or no-show: always full refund or free rebook. The rule text is shown before pay.
6. **Pay-for-a-loved-one** (OQ-171): S25 columns exist. S26 opens `create_order` to accept `p_beneficiary` different from the caller. The beneficiary must be a profile the buyer has `profile_access` to (a dependent, a care circle member). The entitlement lands on the beneficiary; the buyer sees the order in "my orders".
7. **Refund of fee**: per OQ-97 decision, a full refund when Tarragon cancels returns the price only (the processing fee was Paystack's, not Tarragon's revenue). A patient-requested refund after 14 days is not offered. The 14-day cooling-off (consumer protection norm) is honoured as full price refund. PROPOSED config values for the retention amount and the 14-day window.

## 3. Data model changes (one migration)

### New columns on `entitlements`
- `reminded_at timestamptz` -- set when the 7-day expiry reminder fires; prevents duplicates.

### New table: `refunds`
```
refunds (
  id uuid PK,
  organisation_id uuid NOT NULL -> organisations,
  order_id uuid NOT NULL -> orders,
  amount_kobo bigint NOT NULL CHECK > 0,
  reason text NOT NULL,
  state text NOT NULL DEFAULT 'pending' CHECK in (pending, processing, completed, failed),
  provider text DEFAULT 'paystack',
  provider_reference text,
  provider_response jsonb DEFAULT '{}',
  requested_by uuid -> profiles,
  decided_by uuid -> profiles,
  decided_at timestamptz,
  is_test boolean NOT NULL DEFAULT false,
  created_at timestamptz DEFAULT now()
)
```
RLS: admin reads org refunds, buyer/beneficiary reads their order's refunds. No direct writes (RPC only).

### New functions
- `public.consume_entitlement(p_entitlement uuid)` -- service role, decrements `remaining_uses`, sets `used` at 0.
- `public.revoke_entitlement(p_entitlement uuid, p_reason text)` -- admin, sets state `revoked`.
- `public.request_order_refund(p_order uuid, p_reason text)` -- authenticated (buyer), creates a `pending` refund row. Guards: order is `paid`, no existing pending/processing refund.
- `public.decide_order_refund(p_refund uuid, p_approved boolean, p_note text)` -- admin. If approved: calls `refundTransaction`, records provider_reference, moves refund to `processing`/`completed`, order to `refunded`, entitlement to `revoked`, posts reversing journal.
- `private.queue_entitlement_expiry_reminders()` -- daily cron, queues CON-010 for entitlements expiring in 7 days.
- `private.expire_entitlements()` -- daily cron, `active` with `ends_at <= now()` -> `expired`.

### `create_order` change
- Remove the `beneficiary = self` guard. Add a `profile_access` check: the buyer must have an active `profile_access` row for the beneficiary if they differ.

## 4. Events
- `entitlement.expired` -- emitted when a cron expires an entitlement.
- `refund.completed` -- emitted when a refund succeeds.

## 5. Screens (web only, S26 scope)
- Patient `/patient/membership` or `/patient/care-pack`: show the active entitlement with its `ends_at`, a "renew" button (links to purchase page), and a "request refund" action (if within 14 days of purchase).
- Admin `/admin/refunds`: list pending refunds, approve/reject with a note.
- "Pay for someone" on `/patient/membership`: a dropdown of profiles the buyer has access to (from `profile_access`).

## 6. Safety rules
1. **Safety case 25**: care pack `ends_at = starts_at + 90 days`. No trigger, cron or function ever sets a new payment or extends the date. The cron only EXPIRES. The reminder only NOTIFIES.
2. **Refund idempotency**: `refunds` has a unique partial index `(order_id) where state in ('pending', 'processing', 'completed')` so an order gets at most one live refund.
3. **No stored balance** (INV-09): a refund goes back to Paystack (the card), never to a wallet.
4. **Entitlement revocation on refund**: the `decide_order_refund` function revokes in the same transaction.

## 7. Not built here
- Instalment payments, HMO eligibility, voucher-based refund (later releases).
- Mobile screens for refund request (S29 scope with Care Circle).
- GL posting of refund-specific accounts beyond the reversal (finance review needed for partial refunds).
