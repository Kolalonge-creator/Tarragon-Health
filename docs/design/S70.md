# S70 design note: Module 18, devices, wearables and data connections

## Reconciliation (what existed)
BLE parsers and mobile pairing, five cloud adapters, Health Connect and HealthKit bridges, Dexcom pull, `cgm_connections`, `device_catalog` (3 inactive rows), ECG report extraction, source labels, plausibility flags, the source lock, the S10 event bus, S16 tasks, S37 guards. Spec `device_connections` is satisfied by `wearable_connections`, `cgm_connections` and `patient_devices`; no fourth table.

## Data model (migration `20261007155314_s70_devices_dedup_events_cgm.sql`)
- `device_config(kind, version, rules)`: PROPOSED dedup, CGM and device-alert values, mirrored in `packages/shared` as `devices.*` with a drift test. All `proposed`; the CMO signs.
- `vitals_reading_links` (duplicate to canonical, config version, `is_test`): RLS like `vitals_readings`, no write grant. View `vitals_readings_counted` (security invoker). BP control and the weekly summary read it; S38 snapshot SQL is not yet switched (OQ-342).
- `vitals_readings.photo_confirmed`; `device_alerts` (no direct grant; read through `clinician_device_alerts`, audited and tie-checked); `device_catalog` criteria columns and a listing constraint; `wearable_provider` gains `withings`.
- Filename note: it sorts after origin/main-dev's newest because the sandbox clock reads earlier than that stamp.

## Events and tasks
`device.synced` (provider, kind, counts) and `device.alert` (id, code, kind) registered; neither carries a value. Task type `device_alert_review` (class 7, 1440 min, `medical_officer`, not `needs_confirmation`, so it does not block rule-set approval). Task creation sits behind guard `device_alerts_enabled`, born OFF; with it off an alert is recorded, the event emitted, the task held, and `release_held_device_alerts()` creates it later. Test patients pass the guard (S37 test rule).

## Behaviour
Dedup trigger on insert, either arrival order, rank device = photo = manual over cgm over wearable; equal rank first wins; never deletes; failures only warn (sweep re-links). CGM trigger evaluates sustained runs from config, once per episode, 6 hour suppression, severe low also calls the existing emergency record. ECG: `report_device_ecg_result`, capped at 10 a day.

## Screens
Mobile Devices tab: manual entry first, photo-of-screen modal, recommended list, ECG share (iOS), neutral review notice. Web device shop shows distributor, validation and connection. Strings in `packages/i18n` (English only, D-14).

## Safety rules held
Devices never required; device and photo values take the manual triage path (INV-01); notices neutral (INV-07); no AI call; INV-13 `is_test` on new tables; INV-16 config version on every decision; no production apply.

## Not built
Paid CGM programme (OQ-318), inhaler (18.7), band (18.8), Withings/Samsung flows, native OCR, vendor ECG connector.
