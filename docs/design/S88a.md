# S88a: mobile crash reporting (JS-only, OTA-safe, dormant)

Status: built, not deployed, not switched on. Date: 2026-10-27.

## What ships now

`apps/mobile/src/lib/crash-report.ts` (core, no native imports), `crash-scrub.ts` (PHI scrubber), `crash-reporting.ts` (React Native wiring), `src/root.tsx` (top-level error boundary), `index.js` (installs it).

- Hooks: `ErrorUtils.setGlobalHandler` (previous handler always called afterwards, so behaviour is unchanged), Hermes unhandled promise rejections, and the React error boundary.
- Transport: one fire-and-forget `fetch` of a Sentry envelope to the DSN in `EXPO_PUBLIC_SENTRY_DSN`. **Unset means dormant: no hook sends, no network, no state.** `EXPO_PUBLIC_SENTRY_ENVIRONMENT` is optional.
- Allowlist event only: error type, scrubbed message, parsed stack frames (function, file base name, line, column), app version, runtimeVersion, platform, OS major version, device brand (such as TECNO), a random install id kept in app storage (AsyncStorage, not the keychain, so it is removed with the app on both platforms and is not a persistent device identifier). No user, request, breadcrumbs, `extra`, component stack or device name.
- Never throws, never awaited on the caller's path, 3 second timeout, nothing queued to disk (a failed send is dropped), de-duplicated by fingerprint (the level is part of the fingerprint), capped at 10 non-fatal events per process with a separate budget of 5 fatals, 5 second gap between non-fatal sends. For a fatal the send starts synchronously and the previous handler (which lets native kill the process) is held for at most 800 ms, or until the request settles; nothing is persisted.
- Install order: `index.js` imports `src/lib/crash-install.ts` first. ES imports are hoisted, so a call placed after them would run after the whole app graph had evaluated; the first-import side-effect module installs the handler before it. `crash-hardening.test.ts` checks the order and that the install path imports nothing from the app.
- Message policy (`crash-scrub.ts`) is allowlist-first. A message is sent only when it matches a known system error (Network request failed, undefined is not a function, Cannot read property of undefined, JSON Parse error, ...), and then as the pattern's canonical text plus an HTTP status, never the original wording. Anything else is sent as `message withheld (ref <8 hex>)`, a hash of the digit-masked message, so it still groups; the error class is the event `type`. This is deliberate: lowercase or concatenated names ("adaobi is not a function") and bare first names cannot be detected by patterns. `scrubFreeText` is the strengthened pattern scrubber (quoted strings, emails, phones, tokens, UUIDs, URLs reduced to scheme and host, query strings and PostgREST filters, key=value pairs, numbers after health words including decimals, honorific and capitalised name pairs, vitals and units, remaining digit runs) used as defence in depth and before hashing. Frames keep function, file base name, line and column; Hermes `address at` prefixes are handled.
- Tests: `crash-report.test.ts` (12 PHI strings, allowlist event, dormancy, rate, dedupe, no storage import) and `crash-hardening.test.ts` (allowlist cases such as "Ada Obi has no profile", "adaobi is not a function", "weight was 82.5", "age 7"; URLs; Hermes frames; fatal grace and budget; rejection tracker; install order). Each block has a sabotage check: disabling the fix makes the matching tests fail.

Known limit: callers should still not interpolate patient values into error messages; the allowlist means such a message is withheld, not forwarded, but the error class and a hash still go out.

## What this cannot do

- Native crashes (SIGSEGV, OOM kills, JNI/Swift faults) and ANRs never reach JS. This reporter does not see them.
- No source maps, so frames are minified bundle positions.
- No release health or session tracking.

## Follow-up that needs an EAS build (founder go-ahead, DG-6)

Add the Sentry native SDK (`@sentry/react-native`, config plugin, source map upload in the EAS build). That is native-affecting, so `app.json` `runtimeVersion` must be bumped (currently `0.1.0-native8`) and a fresh `eas build` made before the next OTA reaches devices (see CLAUDE.md, mobile OTA note). When it lands: keep the scrubbing in `beforeSend` using `crash-scrub.ts`, disable breadcrumbs, `sendDefaultPii: false`, and re-run the scrubbing tests against the SDK's event. Remove the JS reporter then, so one error is not sent twice.

## Founder steps to switch it on (no build needed)

1. Create or reuse a Sentry project, copy the DSN (not a secret).
2. Set `EXPO_PUBLIC_SENTRY_DSN` in the EAS Update environment for the `preview` channel, then publish an OTA. Check one deliberate test error arrives with no patient text.
3. Name the privacy decision (the install id is random per install and stored in app storage, so it is removed on uninstall on iOS and Android and is not a persistent device identifier): the DSN host is outside Nigeria, so list Sentry in the data-flow register (processor, country, transfer basis) before pointing production at it.
