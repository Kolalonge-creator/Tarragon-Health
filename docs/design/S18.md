## 3. Design

### 3.1 Tables (one migration, real timestamp, `list_migrations` checked on live first)
- `availability_blocks` per spec 7.2. Add: `organisation_id`, `is_test`, 2-hour minimum granularity and no overlap per clinician (exclusion constraint), `kind` limited by competency (`on_call` needs `on_call` competency; `lead_clinician` not needed for blocks), `state` machine declared -> confirmed | cancelled (confirmed by clinical lead/ops, or auto-confirmed when a rule says so), `cancelled_reason`, `minimum_guarantee_eligible` stored only (money is S30).
- `on_call_rota`: `starts_at, ends_at, primary_clinician_id, backup_clinician_id` (both NOT NULL, different people, both on_call competent and eligible at write time), no overlapping rows per org, UTC instants plus IANA zone `Africa/Lagos` in config, `built_by`, `is_test`.
- `rota_swaps` (request, covering clinician accept, approve, audited). An unaccepted swap changes nothing.
- `conflicts` (name per spec and S16/S17 queries): `clinician_id, patient_id, reason, source` (`declared`, `handback`, `clinical_lead`), `state` (`active`, `lifted`), who/when. A hand-back with reason `conflict_of_interest` writes a pending conflict automatically.
- `lead_assignments` (history and current): `patient_id, clinician_id, state` (`active`, `ended`, `unassigned_pending`), `started_at, ended_at, end_reason` (`suspended`, `offboarded`, `licence_expired`, `competency_revoked`, `conflict`, `capacity_rebalance`, `clinician_request`, `patient_request`), `config_version` (INV-16), `source_order_id` nullable, `is_test`. Partial unique index: one active row per patient. Because `pathway_enrolments` does not exist, this is the lead record; see OQ-A.
- Versioned `lead_rules` (+ code mirror `queue.lead_rules`, drift test, same pattern as S15/S16): `max_lead_patients` default 60, candidate preference order, language rule, lead windows by task type (already in task_types), working-hours and post-call rest rule, fatigue guards (11 h rest, 7 consecutive, 3 on-calls per 7 days, all warnings with override reason), rota horizon 14 days, coverage-gap lookahead, reassignment notice texts keys. All PROPOSED, CMO owner.

### 3.2 Functions (SECURITY DEFINER, no anon/PUBLIC execute, audited)
- Availability: `declare_availability_block`, `cancel_availability_block` (a confirmed block cancelled inside a lead time raises a coverage-gap check), `confirm_availability_block`.
- Rota: `set_on_call_rota` (validates eligibility, competency, no conflict of dates, fatigue warnings returned, override needs reason), `request_rota_swap/accept/approve`, `rota_coverage_gaps(from,to)` (uncovered intervals, tiers with fewer than two eligible doctors per slot), `on_call_cover_status()` read only. S19 reads the rota; S37 builds the `on_call_cover_ok` guard on top. S18 enables no gate (INV-14).
- Conflicts: `declare_conflict`, `lift_conflict` (clinical lead), `private.has_conflict(clinician, patient)`; checked in lead assignment, reassignment, S16 offer routing, and (as the spec query expects) S17 claim.
- Lead: `private.choose_lead(patient, exclude[])` filter: status active, `clinician_is_eligible`, competencies `lead_clinician`+`hypertension`, doctor tier above Medical Officer floor (F-05: doctor tier is the gate, OQ-B), not on leave, no active conflict, active lead count (excluding `is_test`) below limit. Rank: existing treating clinician, then language match where possible, then fewest active leads, then highest reliability score, then stable id tiebreak. `assign_lead_clinician(patient, source)` (idempotent per patient, one transaction) writes `lead_assignments`, updates `care_team_assignment.clinician_id` in the same transaction (INV-12: old lead loses access at once), emits `lead.assigned`, notifies clinician and patient with neutral templates (INV-07). No eligible lead: state `unassigned_pending`, loud ops incident plus clinical lead alert, tasks flow to the pool, patient told "your care team is being arranged" (never silent).
- `reassign_leads_for_clinician(clinician, reason)`: ends each active lead row, re-chooses per patient with the same rules, moves open `offered_to_lead` tasks and `lead_clinician_id` to the new lead (or pool), emits events, notifies patient ("your care team lead has changed") and new lead. Per-patient isolation so one failure opens an incident and does not block the rest (S16 sweep lesson).
- Subscribers on S10 bus: `lead.reassign_on_clinician_removed` (`clinician.suspended`, incl. offboarded), `lead.recheck_on_competency_changed` (revoked `lead_clinician`/`hypertension`), `lead.assign_on_order_paid` (registered handler, no producer until S25; also callable by an admin/clinical-lead "assign lead" action for the pilot). Reinstatement never auto-restores old leads.
- Replace the OQ-111 stand-in inside `create_clinical_task`: lead = active `lead_assignments` row; employed-doctor push path unchanged. Add the OQ-112 rule: `private.clinician_in_rest_or_off_hours(clinician, at)` consulted by offer routing (offered task skips a freelancer in post-call rest or outside declared blocks; falls to pool at once rather than waiting out the window). S17 consumes the same function.
- Capacity read: `lead_capacity_status()` (free slots by language, fill percent) for S25 checkout and S37 guard; Babylon lesson, no sales past capacity. Not enforced here.
- Sweeps: nightly after the 06:00 credential sweep, `lead_rules` reconcile job (eligibility drift, any active lead now ineligible, over-cap warnings, rota gap report) writes ops incidents; also gap detection runs on every rota/block write.

### 3.3 Screens (apps/web, since console cannot serve the clinician role, OQ-99; full console versions are S35/S36)
- Clinician: availability declaration (queue, on-call, bookable blocks, 2-hour grid, see confirmed rota, swap request), conflict declaration, my lead patients count and cap. Extends `/clinician/availability` rather than a new area.
- Clinical lead and admin: rota builder with gap and fatigue warnings, availability confirmations, conflict list, lead pool and capacity, unassigned patients queue, assign/reassign with reason.
- Patient: the care team card is left as it is (it deliberately names nobody ahead of a real review, OQ-129, which records the conflict with spec 7.5's "name and photo"). The patient is told in neutral words when their lead is set, changes or is being arranged (`care_team_notice`, in-app and email). `my_care_team_lead()` exists for when the founder decides to show a name.
- All strings in `packages/i18n` (en, pcm). No em dashes. Staff screens English only per OQ-102 precedent.

## 4. Safety rules
1. A patient is never left without either a lead or a visible `unassigned_pending` with an alert. No silent drop.
2. Uncovered rota hours fail loudly (incident to clinical lead, admin), never "no one paged" (PagerDuty hazard). Red events with no cover go straight to level 2 (S19).
3. Lead change and `care_team_assignment` update are one transaction (INV-12).
4. Notifications carry no clinical term (INV-07 lint over new templates).
5. Conflicts are checked on assign, reassign, offer and claim; a declared conflict is never visible to the patient or ops beyond need.
6. Assignment records config version (INV-16); `is_test` excluded from caps and metrics (INV-13).
7. Eligibility drift (licence expiry etc.) triggers reassignment automatically; reinstatement never silently restores.
8. No money, no earnings in S18 (minimum guarantee is a flag only).

## 6. Proof
- DB proof `packages/db/tests/s18_lead_assignment_availability_rota.sql`, registered in `ci.manifest`, own BEGIN/ROLLBACK, simulated sessions:
  - Safety case 16 part: licence expires, nightly sweep suspends, leads reassigned the same run, patients notified, old lead loses chart access, tasks offered to old lead move.
  - Cap: clinician at limit never chosen; all at limit gives `unassigned_pending` plus incident, never an over-cap lead. Test patients excluded from the count.
  - Ranking: existing treating clinician, language, fewest leads, reliability, deterministic tiebreak.
  - Conflict: declared conflict blocks assign, reassign, offer, rota primary/backup; hand-back COI creates a pending conflict.
  - Rota: no overlap, primary differs from backup, ineligible or non on-call competent refused, gap detection after deleting a shift, unaccepted swap changes nothing, fatigue warning needs override reason.
  - Rest-window: freelancer in rest skipped for offered tasks.
  - RLS for every new table: patient, other clinician, tied clinician, clinical lead, admin, anon; execute grants (`has_function_privilege` for anon and PUBLIC false); live `pg_get_functiondef` checked, not the file.
  - Sabotage steps: drop the cap check, drop the conflict check, drop the same-transaction `care_team_assignment` update; each must flip a check.
  - Controls where each gate OPENS, not only closes.
- Jest: `packages/queue` chooseLead at 100 percent; drift tests for `queue.lead_rules`; handler idempotency test; notification lint; web component tests for the screens.
- Not applied to production without the founder's go-ahead (CI does not push migrations). Dry run rolled back against live, version pinned to filename on apply. Part D (spec 2205-2256) skim at close.

## 7. Open questions to raise (numbers continue after OQ-114)
- OQ-A: no `pathway_enrolments` table exists. Recommended: `lead_assignments` is the lead record, anchored to the care-pack purchase/`chronic_programme_enrolment`; a real `pathway_enrolments` only when S21/S25 need care-pack state.
- OQ-B: spec 7.5 says "tier 2" but F-05 collapsed tiers. Recommended: lead pool = `lead_clinician` + `hypertension` competencies + senior doctor tier or higher (Medical Officer excluded), no use of `credentialing_level`.
- OQ-C: `order.paid` has no emitter until S25. Recommended: subscriber now, plus clinical-lead/admin "assign lead" for the pilot; S25 emits.
- OQ-D: care-pack sale gate. Recommended: S18 exposes `lead_capacity_status()` and `rota_coverage_gaps()` only; S25/S37 wire the checkout block and `on_call_cover_ok`.
- OQ-E: fatigue and rest numbers (NHS-derived) need CMO review; plus what a freelancer's working hours are.
- OQ-F: patient wording on reassignment and spec 7.5 "name and photo of the lead" versus the CLAUDE.md rule never to promise one continuous named doctor; recommended: show the lead as "your care team lead" with the team behind them, and tell the patient on change.
- OQ-G: when a patient asks to change lead, and whether a clinician can request release from a patient (non-COI), needs a clinical-lead path.
