# S66 design note: Module 16 (1 of 3), menstrual and reproductive (16.1 to 16.4)

Branch `s66-cycle-private`, from `origin/main-dev` c7edfd7. Stage 1 gate waived by the founder. English only (D-14). Nothing is applied, pushed or switched on.

## 1. What already existed (extended, not rebuilt)
Tables `menstrual_cycles`, `menstrual_daily_logs`, `reproductive_health_profiles`, `contraception_plans`, `menopause_symptom_logs` (0 rows each live, so every change is structural). Web `patient/cycle/*`, `womens-health`, clinician `womens-health-panel`; mobile `cycle-screen`, `womens-health-screen`. Two near-identical prediction files (web `lib/rules/cycle-prediction.ts`, mobile `lib/cycle-prediction.ts`; the build plan said `cycle-insights`, in fact the duplicate was the prediction engine). INV-07 lint (S13). Spec names `cycles` and `pregnancies` map to the live tables above; none were duplicated.

## 2. Data model (3 migrations + 1 enum migration, timestamps from `date -u`)
- `..124153_s66_menopause_symptom_types`: enum adds `irregular_bleeding`, `vaginal_discomfort` (own file: ADD VALUE).
- `..124335_s66_private_cycle_foundations`: `reproductive_health_profiles.conception_planning_mode` (default false) with a trigger so only the patient turns it ON; `set_conception_planning_mode`; `menopause_symptom_logs.source/recorded_by` stamped from the session; `reproductive_deletion_requests` + request/cancel/status RPCs + service-role processor (`process_due_reproductive_tracker_deletions`); `reproductive_privacy_config` (versioned PROPOSED numbers).
- `..124831_s66_cycle_pattern_report_and_guard`: guard `reproductive_content_enabled` (born OFF); `private.reproductive_staff_tied` (fresh check: active credentialed clinician, same org, `clinician_has_patient_access` tie; no break-glass, support view or open-record window); `read_reproductive_pattern_report_audited` (audits every call and refusal); `my_reproductive_access_log` (the patient sees who looked).
- `..125002_s66_notification_terms_cycle_and_reproductive`: INV-07 term list gains period, cycle*, fertil*, ovulat*, menopaus*, perimenopaus*, menstru*, luteal, follicular, conceiv*.
No RLS policy is replaced: live policies were changed by S39b/S39g, which this base lacks. Types in `database.types.ts` were spliced by hand (only these additions).

## 3. Events and jobs
No outbox events. One cron: `/api/cron/reproductive-deletions` (daily 06:30) runs the deletion processor. The existing `cycle-reminders` cron now sends one generic in-app line and a payload of only `expected_date`; it runs the prediction with planning mode off.

## 4. Screens
Web: cycle page and Women's Health page and the Prevention card sit inside `PrivateSection`; planning card; privacy card (access list, deletion); contraception education page; clinician report panel (print/PDF) in the Women's Health tab, replacing the unaudited direct reads of cycle and menopause rows. Mobile: same lock, planning card, privacy card, contraception education (inside Women's Health), urgent bleeding prompt. Dashboard tile renamed "Your tracker".

## 5. Reusable lock (for S67, S68, S69)
`@tarragon/shared` `PrivateLockController` (PBKDF2-HMAC-SHA256 PIN or biometric, per-account record, persisted attempt counter with growing lockout, relock after background, `resetAfterReverification`). Web: `<PrivateSection accountId title outside>` in `apps/web/src/components/private-section`. Mobile: `<PrivateSection ...>` in `apps/mobile/src/ui/private-section.tsx` (SecureStore, expo-crypto, expo-local-authentication). `outside` is where emergency content goes: it is rendered in every state. Config: PROPOSED `private_section.lock` (optional but on by default; PIN 4 to 6 digits; 5 free tries; 30 s relock). Recovery: a code to the account's own phone (email if none), then only the local record is deleted; nothing on the server changes. Separate from `apps/mobile/src/lib/app-lock.ts`, which is untouched.

## 6. Safety rules
INV-07 lint over cycle words; no fertile day in any notification; planning mode off by default and enforced in the prediction function; "This is not contraception." on every window surface (acceptance test scans web and mobile); contraception page neutral (alphabetical, no dosing or ranking); no hormone advice; danger signs outside the lock; staff reads only through the audited function and only for a tied clinician (INV-10/12); a failed load is never shown as "nothing logged"; sponsors and employers have no path. All new patient-facing words are in `packages/i18n/src/cycle-copy.ts`, **PROPOSED, CMO review pending** (`CYCLE_COPY_REVIEW`); no agent signs anything.

## 7. Go-live guard
`reproductive_content_enabled` (CMO switch) stops the clinician report and the contraception page. Born off. It cannot yet be switched on: `private.go_live_conditions` has no branch for it (OQ-331). The tracker, menopause log, planning mode and lock are live features and are not gated.

## 8. Tests and proofs
Jest: shared 4 cycle suites (goldens, planning on/off, pattern report), lock controller, PBKDF2 against Node crypto and RFC 7914; notifications lint 270; i18n copy audit; web recovery actions, report reader, parsers, cron, not-contraception acceptance scan; mobile lock adapter, recovery, parsers. DB proofs registered in `ci.manifest`: `s66_private_cycle_foundations`, `s66_menopause_enum_values`, `s66_cycle_pattern_report`, each with a sabotage that flips.

## 9. Not built / follow-ups
Web biometric (WebAuthn); not run on a real phone; destruction of sealed data after retention (OQ-330); guard conditions (OQ-331); other reproductive tables still read directly by staff (OQ-332).
