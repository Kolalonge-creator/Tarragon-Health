# S31 Design: weekly payouts, approval, Paystack transfers, statements, bank verification

Spec 7.7 and D-09. Depends on S30 (merged). Invariants: INV-09 (a payout settles the ledger, there is no balance), INV-13 (test accounts never paid), INV-14 (`payouts_enabled` guard), INV-15 (bigint kobo), INV-16 (each payout records the config version), INV-07 (nothing clinical in any notice). Founder decision F-03: employed doctors are on salary and have no ledger lines, so no payouts. Research: `docs/research/S31.md`.

## 1. Reused, not rebuilt
`earnings_ledger` and its single-use `payout_id` door (`tarragon.earnings_payout_link`), `PaymentProvider` (`listBanks`, `resolveAccount`, `createTransferRecipient`, `initiateTransfer`, `verifyTransfer`, `parseWebhook`, mock and Paystack adapters), `paystack-webhook` (records every event; transfer events were only logged), S37 `go_live_guard_is_open`, S15 `clinical_staff.full_name` as the verified name, `private.log_audit`, the proposed-config registry, `/admin/earnings` and `/clinician/earnings`.

## 2. Data (one migration `*_s31_weekly_payouts.sql`)
- `payouts_config` (versioned, PROPOSED, mirrored as `payouts.rules`): weekday and hour (Lagos) of the draft job, minimum payout kobo, carry-over below the minimum.
- `clinician_bank_accounts`: clinician, `bank_code`, `bank_name`, `account_last4`, `resolved_name`, `recipient_code`, `bank_verified_at` (null until the name matches), `name_match` (`verified`, `mismatch`), `superseded_at`. One current row per clinician. No full account number is stored.
- `clinician_tax_profiles` (D-09, data only): `tin`, `contractor_status` (`unknown`, `individual`, `company`), `registered_name`, `vat_registered`, `note`. No rate, no amount.
- `payouts` (spec fields plus): `organisation_id`, `amount_kobo bigint > 0`, `line_count`, `bank_account_id`, `recipient_code` snapshot, `payouts_config_id`, `approved_by/at`, `failure_reason`, `is_test`. States `draft, approved, sent, succeeded, failed, reversed` plus `cancelled` (a draft discarded; spec lists six, one added so a draft can be thrown away without unlinking ledger lines).
- `payout_transfers` (one per attempt): `payout_id`, `attempt`, `reference` (unique, `tpo-<payout hex>-<nn>`), `paystack_transfer_code`, `state`, `reason`.
- `payout_events` (append only): every state change with actor and time.

## 3. Flow
1. Weekly `pg_cron` calls `build_payout_drafts()`: per contracted, non-test clinician, the sum of unpaid lines earned before the period end; a net at or below the minimum is not drafted (it carries over); one open draft per clinician. Nothing is linked yet, so a discarded draft costs nothing.
2. Admin `approve_payout(id)`: guard open; approver is not the payee; a verified bank account exists; the unpaid lines are re-read and must equal the draft amount and count, else the draft is refused ("ledger changed, rebuild"); lines are linked to the payout (the one-time door) in the same transaction; first `payout_transfers` row created.
3. Edge function `payouts` (`send`) calls `initiateTransfer` with the attempt reference. `pending` moves the payout to `sent`. An error stays `approved` and is retryable safely (same reference).
4. Webhook `transfer.*` goes to `apply_payout_transfer_event`. Keyed by event plus reference. `success` to `succeeded`; `failed` to `failed`; `reversed` to `reversed`. Illegal or unknown transitions are logged and ignored. Never retries on its own: an admin chooses `retry_payout`, which makes a new attempt reference and moves back to `approved`. Lines stay linked.
5. Bank: clinician enters bank and number in the console; edge function `payouts` (`bank`) resolves the name, `private.payout_names_match` compares it with the credentialed name, only a match creates the Paystack recipient and sets `bank_verified_at`. Changing the account supersedes the old row and requires verification again.

## 4. Screens
Clinician `/clinician/earnings`: bank account card, tax details form, payout statements with every line. Admin `/admin/earnings`: payouts table (draft, approve, discard, send, retry, reconcile) with a blocked reason shown per row. Console search entries added.

## 5. Safety rules
Money moves only after a person approves, with the guard on. The payee never approves their own payout. A payout never includes a test account (`is_test` on the line, the clinician and the payout). No payout to a bank account whose name has not matched. Writes only through security definer functions; tables are read-only to clients; the ledger link is single-use. No tax is calculated.

## 6. Tests
DB proof `s31_weekly_payouts.sql`: draft building, minimum carry-over, test exclusion (safety case 22), approval refusals (guard off, self-approval, no bank, ledger moved), exact linking, transfer-event idempotency and ordering including success then reversed, retry, name matching cases, RLS (clinician sees only their own, anon refused), two sabotages. Jest: model and webhook mapping. Not done: a live Paystack call.
