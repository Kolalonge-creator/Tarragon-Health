## Gaps to fill

### 1. Timeline: vitals + prescription events (spec 2.1)

**Problem**: the timeline has 15+ event types but no `vitals_recorded` or `prescription_signed`. A patient logging a blood pressure reading or having a prescription signed are important milestones not visible on the timeline.

**Solution**: add two event types and triggers.

- `vitals_recorded`: AFTER INSERT on `vitals_readings`. Title: "{vital_type} recorded" (e.g. "Blood pressure recorded"). Source from `vitals_readings.source` (manual/device/wearable). Only fires for real patient readings, not system-generated rows.
- `prescription_signed`: AFTER UPDATE on `medications` when `prescription_status` transitions to `'clinician_approved'`. Title: "Prescription signed: {drug_name}". Actor: the signing clinician.

Timeline event metadata carries a `source` key for vitals events so the UI can display "Manual", "Device", or "Wearable" as a badge.

### 2. Record sharing for selected sections (spec 2.8)

**Problem**: the emergency card shares a fixed minimal dataset (emergency facts only). Spec 2.8 asks for "time-limited share link for selected records" — the patient picks which sections to include.

**Solution**: new `record_shares` table and public page.

```
record_shares
  id                uuid PK
  organisation_id   uuid NOT NULL FK organisations
  patient_id        uuid NOT NULL FK profiles
  token             text NOT NULL UNIQUE (32-128 chars, like emergency_cards)
  sections          text[] NOT NULL (allowed values: vitals, medications, conditions,
                    allergies, lab_results, vaccinations, emergency_info)
  expires_at        timestamptz NOT NULL (max 30 days from creation)
  is_active         boolean NOT NULL DEFAULT true
  consented_at      timestamptz NOT NULL DEFAULT now()
  revoked_at        timestamptz
  view_count        integer NOT NULL DEFAULT 0
  last_viewed_at    timestamptz
  created_at        timestamptz NOT NULL DEFAULT now()

record_share_lookups
  id            uuid PK
  share_id      uuid NOT NULL FK record_shares
  looked_up_at  timestamptz NOT NULL DEFAULT now()
```

**RPCs**:
- `create_record_share(p_sections text[], p_expires_in_hours int)` — patient-only, max 30 days, returns token
- `revoke_record_share(p_share_id uuid)` — patient-only, sets is_active=false + revoked_at
- `record_share_by_token(p_token text)` — SECURITY DEFINER anon-callable, returns selected sections' data only, logs lookup, respects expiry

**RLS**: patient reads/inserts their own shares. Org staff can see shares exist (no token). Lookups follow the same pattern as emergency_card_lookups.

**Public page**: `/share/[token]` — force-dynamic, robots noindex, no-referrer. Shows only the selected sections' data, branded as TarragonHealth. A banner says "Shared by [name] — expires [date]".

**Patient UI**: a "Share my records" card on the My Health page. The patient picks sections via checkboxes, chooses expiry (1h, 24h, 7d, 30d), and gets a link + QR. Active shares are listed with view count and revoke button.

### 3. Mobile emergency card: add medications (bugfix)

**Problem**: `loadEmergencyFacts` in `apps/mobile/src/lib/emergency.ts` fetches allergies, conditions, blood, and emergency contact but NOT medications. The web version and the spec both include "medicines" in the emergency card.

**Fix**: add a medications query to `loadEmergencyFacts`.

### 4. My Health page consolidation (spec 8.4)

**Problem**: the spec's "My Health" tab (8.4) lists timeline, emergency card, and share records as one section. The web has these as separate pages.

**Solution**: add a `/patient/my-health` route that serves as the entry point, with cards linking to Timeline, Emergency Card, Health Passport, and Share Records. This is a thin navigation page, not a new feature — it ties existing pages together under one tab.

## Safety rules

- Record sharing is OFF BY DEFAULT (like emergency cards)
- Explicit consent recorded at share creation
- Maximum 30-day expiry, enforced in the DB
- Sections are a closed set (no arbitrary table access)
- `record_share_by_token` uses the same SECURITY DEFINER + anon pattern as `emergency_card_by_token`
- Every lookup is audited and shown back to the patient
- No reproductive health, mental health notes, or risk scores in the shareable sections
- Tokens are 32 random bytes (same as emergency cards)
- Revocation is instant and permanent
