## Decisions
1. **Own governed table**, `home_bp_programme_signoffs`, the shared single-active-row shape, seeded v1 UNSIGNED and INACTIVE. Registered in `GOVERNED_CONFIG_TABLES`, the sign-off queue's `VERSIONED_TABLES`, the `refuse-superseded` guard (DB trigger and app), `_signoff-panels/home-bp-programme-panel.tsx`, `CONFIG_PANELS`, admin read-only page and search entries. The panel shows the unsigned draft (an inactive row), not only the live one.
2. **Rules in three places that cannot drift**: TypeScript (`packages/clinical/src/home-bp.ts`, phone and web), SQL (`private.home_bp_assess_readings`, `private.bp_pattern_kind`; the server recounts from stored readings and never trusts a phone's number), and one parity block of 35 cases inside the DB proof, run through SQL by the proof and through TypeScript by `home-bp.test.ts`. The expected values were produced by an independent third implementation.
3. **Counting**: every manual or device blood pressure reading counts (not `validation_status`, because the live trigger marks any reading without position or arm as `requires_validation`, and an identical pair a minute apart as `duplicate_entry`). A reading less than `minGapMinutes` after the previous one is the same measurement saved twice and is not counted. Complete = at least 12 readings over at least 3 days; the mean averages every counted reading; below that there is no average at all.
4. **Completion is the patient's tap**, calls `complete_home_bp_check(window_start)`. It needs the guard open for her (or a test account) AND a signed configuration, records once (idempotent), and makes one class 8 task `home_bp_check_review` holding no value. The phone keeps a "send" request and retries; "with your care team" is shown only after the server confirms.
5. **Clinic readings**: own table, see OQ-S07X-1. Written only through `record_clinic_bp_reading` by an active clinician tied to the patient (`staff_may_write`); coordinators, untied clinicians and patients are refused. Fires nothing a home reading fires (proved by counting vitals, alerts, emergencies, observation events and notifications before and after).
6. **C3 rule** `private.evaluate_bp_pattern`: runs after a completed home check or a clinic reading, behind guard `bp_pattern_flag`. Nearest clinic reading to the end of the latest complete check, within 30 days. Masked (untreated) / masked uncontrolled (treated): clinic below 140/90 and home 135/85 or above. White-coat: untreated only. Not for pregnancy or under 18; unknown age is still evaluated. One flag and one class 8 task `bp_pattern_review` per pair. No patient policy exists on the flag table; nothing about it reaches a notification.
7. **C5**: `bp_care_triage` v4 is a DRAFT derived in SQL from the stored v3 (only BP-A7 changes: systolic under 90 with no symptom, and `onBpMedicines`). The engine gained an optional input field; the server context function is patched in place. See OQ-S07X-2 and OQ-S07X-4.
8. **C4** cuff guidance: `hc.cuff.*` strings shown on the card (collapsible), including the line that battery advice is practical, not a guideline statement. No row; wording needs the CMO's sign-off with the rest.
9. **Monthly PDF**: `/api/patient/bp-monthly-summary/pdf` reuses the Health Passport letterhead and styles (exported as `passportPdfStyles`). Built from the patient's stored monthly report (`my_monthly_reports`) and her own `home_bp_checks`; it reads no laboratory table, so an unreleased result cannot appear (a test pins the table list). Adherence reads "Doses you marked taken in the last 7 days of the month".

## Safety notes
- Fail closed everywhere: unsigned config, guard off, unknown guard on a phone that never learned it: nothing is recorded and no card shows.
- Alert volume: both new task types are class 8 routine; a pair is flagged once; a repeat call merges by dedup key.
- The existing BP, glucose, SpO2 and pulse red-flag triggers are untouched (no enum change, no trigger change). The only change to a live function is `triage_context_for_observation` (one added input key, patched from its current definition).
