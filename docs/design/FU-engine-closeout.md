## Code review (high): findings and what was done
Fixed: the v7 self-check no longer demands an approved row (a fresh replay has none); a second low after a recovery is graded (dedupe now looks at the most recent result only); stale drops and failed emits are recorded and the sweep covers fresh monitor readings; the BP-A4 cover helper fails open, checks the alert threshold is not above BP-A4's line, and cannot abort the alert run; the missing-guard case on the hub is a failure, not an all-clear, and a signed-but-not-shipped wording shows as an attention line; the dedupe reads its config once and uses the existing `triage_events (patient_id, created_at desc)` index; the v7 note now names the symptoms it does not cover.
Kept on purpose, raised below: only the latest reading of a bulk statement is graded (founder decision); the CDS priorities are lower for 160/100 to 179/109 (the approved rule set has no 160/100 line).

## Not done, and why
- The `symptom` trigger is not wired: no function sends a symptom report to the engine with the approved version (that is a follow-up after the CMO signs v7; signing v7 also signs the D1 180/120 line and retires v3). Version 6 stays a draft the CMO could not sign once v7 exists, because the panel signs the newest draft; to sign without the symptom rules ask for a v8 built from v6.
- Recording the fast-sugar attestation changes nothing a patient sees by itself: the proposed text reaches patients only when `GLUCOSE_WORDING_SIGNED` is set in the i18n JSON (a code change). The guard is the CMO's record and the hub line, not a runtime switch.
- CGM grading was never run against a real CGM or wearable feed (no provider credentials exist); a lost emit for a stream is not swept (the next reading arrives in minutes). Per-row inserts of monitor readings (not one batch statement) are each graded if fresh, then deduped per level in the writer; the guards cap pages and tasks, not the number of events.
- The deployed edge function and the real auto-apply workflow were not exercised.

## Proposed open questions

1b. Console priorities change with the CDS move: an average of 170/105 was high and is now medium; 148/88 against a target of 130/80 was medium and is now low. Tell clinicians, or add a CMO-signed line between target and 180/110?
2. Signing v7 bundles three decisions (180/120, the symptom rules, the old v3 retirement). Prefer separate versions?
3. The CDS bands now follow the approved rule set; when v7 or a later set is approved, the bundled import in `cds/engine.ts` must move with the phone bundle.
