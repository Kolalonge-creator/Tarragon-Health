# S21 design note: encounters, booking, consultation room with audio fallback

Founder decisions: OQ-124 to OQ-131 (2026-10-06). Research: `docs/research/S21.md`. Invariants in play: INV-05, 07, 08, 10, 11, 12, 14, 15, 16.

## 1. What is reused, what is new

Reused as is: `appointments` and its hold, confirm, cancel, reschedule functions and the `appointments_no_provider_overlap` constraint; `provider_availability_rules`, `provider_time_off`, the waiting list and the reminder cron; `service_products`, `service_purchases`, `redeem_available_service_purchase`, the Paystack checkout and resume-booking redirect; `clinical_encounter_notes` with the S05d audited functions; the S10 event bus; the S14 `VideoProvider`, mock, contract tests and `stepAudioFallback`.

Extended: `hold_appointment_slot`, `confirm_appointment_booking` and `cancel_appointment` (each repeats the live definition read with `pg_get_functiondef`, plus one clearly marked change); `VideoProvider` (a media mode, an assertion that recording is off, a link-only join result); `clinical_encounters` (becomes a projection fed from `encounters`).

New: `encounters`, `encounter_rooms`, `encounter_events`, `consultation_scribe_consents`, `consultation_policy_config`, the ladder state machine, the Zoom dial-in on the video adapter, the patient Care flow and clinician consultations page changes.

Deliberately not touched in S21: the second slot system (`consult_availability_slots` and `video_visit_requests`) and `video_consultations` read policies. Both have about 8 call sites each (PR 789 showed what narrowing a policy under live readers does). They are inventoried in OQ-132 and moved in a follow-up.

## 2. Data model (migration `s21_encounters`)

- `encounters`: `id`, `organisation_id`, `patient_id`, `clinician_id` (nullable until assigned), `type` (`video`, `audio`, `phone`, `async`), `status` (`scheduled`, `waiting`, `in_progress`, `completed`, `no_show_patient`, `no_show_clinician`, `cancelled`, `failed`), `scheduled_at`, `started_at`, `ended_at`, `appointment_id`, `async_consult_id`, `video_consultation_id`, `service_purchase_id` (the order), `task_id`, `final_media_mode`, `fallback_steps`, `is_test`, timestamps. One encounter per appointment (unique). Patient 18 or over is checked by a trigger (OQ-129), fail closed if no date of birth.
- `encounter_rooms`: `encounter_id` unique, `provider`, `provider_room_id`, `state`, `recording_enabled boolean not null default false check (not recording_enabled)`, `expires_at`. No join or host URL is stored here. A definer function issues a join token for the assigned clinician or the patient only and writes an event.
- `encounter_events`: append-only (no update or delete grant, trigger refuses both). Kinds: `room_created`, `joined`, `left`, `quality`, `mode_changed`, `fallback_offered`, `phone_requested`, `phone_connected`, `reconnect_grace_started`, `no_show_marked`, `completed`. Payload holds ids and numbers, never names or readings.
- `consultation_scribe_consents`: `encounter_id` unique, `patient_id`, `granted`, `asked_at`, `answered_at`, `method` (`in_app`). Written only by `record_scribe_consent(encounter, granted)` which requires the signed-in patient. A clinician cannot write or edit it. Closes OQ-38.
- `consultation_policy_config` (versioned, PROPOSED, mirrored in `packages/shared` as `consultations.policy`): cancel window 2 hours, retention inside the window (0 kobo until the founder sets it), hold 10 minutes, reconnect grace 120 seconds, wait before clinician no-show 15 minutes, patient no-show 10 minutes, session length 30 minutes, minimum age 18. Each encounter records the config version it used (INV-16).
- RLS: patient reads own encounter rows; clinician reads an encounter only if assigned (INV-12) and through the audited path for any chart data; admin and support read via the audited admin path. Writes only through definer functions. `anon` has no execute on anything (revoke from public).
- Price: `video_visit_credit` set to 1,000,000 kobo (NGN 10,000), one price for video, audio and phone (OQ-130).

## 3. Booking and money

- `hold_appointment_slot` gains the age gate for telemedicine. `confirm_appointment_booking` on confirm also creates the `encounters` row and `encounter_rooms` stub, and queues neutral notifications.
- `cancel_appointment` becomes policy-driven (OQ-127): patient cancels 2 hours or more before gives the credit back (the redeemed `service_purchases` row is un-redeemed in the same transaction); inside 2 hours the credit is kept unless the retention is zero in config; clinician cancel or clinician no-show always returns the credit and offers a free rebook. A cash refund of money already paid is S26's job (OQ-133); S21 never moves money and never stores a balance (INV-09).
- Slots: one RPC `list_bookable_consult_slots` over confirmed `bookable_consultations` blocks, time off and existing appointments. It waits for PR 931 (OQ-124). Everything else in S21 ships first.

## 4. Room and fallback ladder

- Ladder is pure code (`packages/integrations`, 100 percent coverage like S14): `video` to `audio_only` to `phone`. Downgrade uses `stepAudioFallback` and config `video.audio_fallback`. A lost connection longer than the reconnect grace asks the patient and the clinician to move to phone; the patient can also tap "call me" at any time. The consultation clock is paused during grace. Only the server writes the final mode.
- Join is audio-first when the pre-call probe is poor or data saver is on. The patient is told when the mode changes, never silently.
- Zoom in S21 is link based (OQ-126): the adapter returns a link plus a mode hint (`audioOnlyEnforced` is false: a Zoom link cannot keep a camera off, so the page tells the person). **What this cannot do, and the plan does not pretend otherwise:** the call runs in Zoom's own tab or app, so our page sees no quality samples, and Zoom's presence webhooks cannot tell patient from clinician (a link joiner types their own display name; clinicians host as the shared account owner). So in this phase the ladder is driven by people and by the server clock, not by measured quality: the patient chooses audio only or "call me", either side can report that the other did not come, and `stepLadder` is proved for when quality and presence arrive. Automatic downgrade and automatic phone callback on a dropped call need the in-app SDK (we set each participant's label), which is the next call-experience session.
- Phone fallback is Zoom's own dial-in (OQ-131 revised): `VideoProvider.dialIn` returns the Nigerian number, meeting id and phone passcode for the same room, the person rings in, and nothing is rung from our side or held. Zoom call-out is not used (cost) and no second vendor is needed. Webhooks move onto the adapter's `parseWebhook` and write `encounter_events`.
- Recording is off by default and asserted off in the room row (OQ-128).

## 5. Screens

Patient (web and mobile Care flow): choose video, audio or written question; clinician cards with language, sex, price and next slot, MDCN badge with the last-verified date; slots in Africa/Lagos; price and the cancel and refund rule above the pay button; 10 minute hold; confirmed only on the Paystack webhook, with a "paid, not yet confirmed" state; reminders at 24 hours and 2 hours; waiting room with device check, scribe consent prompt CON-001 (en and pcm) and a "use audio only" and "call me" control; mid-call mode notices; a post-visit "flag a problem" action within 3 days.
Clinician: Consultations page (today, join, waiting room status, no-show, scribe controls disabled until consent is granted, note editor handoff).

## 6. Events and notifications

New event types (owner S21): `encounter.scheduled`, `encounter.started`, `encounter.fallback`, `encounter.no_show`; `encounter.completed` exists. Ids and neutral facts only. New in-app and push templates (`consult_confirmed`, `consult_reminder`, `consult_join_ready`, `consult_fallback_offered`, `consult_missed`, `consult_credit_returned`) pass the INV-07 lint and the en and pcm i18n tests. No SMS (INV-08). The escalation action stops texting the raw join link and stops putting the patient name in the Zoom topic.

## 7. Safety rules

Red events never wait for a booking (INV-05): nothing in the consultation path can delay a page. Nothing sent names a condition (INV-07). Consent is written only from the patient's own answer, never defaulted, and a withdrawal mid-call stops capture and is logged (INV-11). A clinician sees only their own encounters (INV-12) and every chart read goes through the audited path (INV-10). The go-live guard (INV-14) is S37's: the spec's `clinical_operations_enabled` guard blocks consultations, and S37 creates `app_config.go_live`. Until then booking is gated only by there being bookable slots and a purchased credit; see OQ-135. Dates in NGN kobo, bigint (INV-15). Test data is `is_test`.

## 7b. Review fixes (2026-10-06, `/code-review high`)
A person cannot report their own join (the server records it, inside the join window); only the server can put a consultation on the phone (the dial-in alone never does, because we cannot see who dialled); dial-in numbers are not given outside the join window or to anyone but the two people on the consultation, and are never stored; reschedule, a provider's leave and staff status changes move the encounter, the credit and the consultation row together; the adults-only rule also covers the older video-visit booking path; the no-show wait fails closed when no policy is active; the room shows the join link as a tappable link and shows an error when a consent or no-show save fails. Still open: OQ-159 (clinician access after Finish), OQ-160 (join means link issued).

## 8. Proof plan

DB proof `s21_encounters.sql` (BEGIN/ROLLBACK, registered in `ci.manifest`): age gate (17 refused, 18 allowed, no date of birth refused); one encounter per appointment; a stranger and another clinician read nothing; scribe consent writable only by the patient; events append-only; recording cannot be turned on; cancel at 3 hours returns the credit, at 1 hour keeps it, clinician cancel always returns it; `anon` and `public` have no execute; price is 1,000,000. Each check has a sabotage run. Jest: ladder state machine (every transition, hysteresis, grace), policy mirror drift, templates lint, i18n. End to end: mock provider join test that goes video, audio, phone and completes, plus a no-show.

## 9. Follow-up: the Zoom Meeting SDK inside the room (OQ-136, OQ-160; 2026-10-06, stacked on PR 942)

Founder decision: the Zoom Meeting SDK, not LiveKit, so the call keeps the same Zoom room, dial-in numbers and waiting room. Section 4's "link based" limits now have an answer, but only where the SDK can run; the link remains the fallback and the default when the SDK is unavailable.

- **Embedding.** Component View (`ZoomMtgEmbedded`), loaded at run time from `source.zoom.us` pinned to 6.5.0 (`lib/consultations/zoom-sdk.ts`), only when the person taps join. Not an npm dependency (about 120 MB, peers on React 18 while the app runs 19). Component View over Client View because Client View takes over the whole page and cannot sit beside our waiting-room controls and the dial-in card. `use-in-app-call.ts` owns the lifecycle; every failure returns "fallback" and the room opens the link as before. Environment: `ZOOM_SDK_KEY`, `ZOOM_SDK_SECRET` (server only), `ZOOM_PRESENCE_WEBHOOK` (see below).
- **Joining.** `prepareSdkJoinAction` reuses the room's own checks (`lookup`: the signed-in person is one of the two, the consultation is live, the window is open), then `VideoProvider.joinToken`, which now also returns the room passcode and, for the clinician only, the host key (ZAK). The person joins with the role word as their label. Nothing is stored; recording stays off (asserted at room creation).
- **Ladder.** `CallController` (`lib/consultations/call-controller.ts`) maps `connection-change`, `network-quality-change` and `audio-statistic-data-change` to `stepLadder` inputs using pure functions in `consultation-call.ts` (100 percent covered, browser-safe through `@tarragon/integrations/client`). Samples are thinned to one per `sampleIntervalSeconds`, a reading older than one interval is dropped, and only a person's own link counts. Actions: audio only is recorded and announced; offer video asks the patient (never automatic); a drop shows the held-place message and ticks the grace clock once a second; running out shows the dial-in card. Reports go through the person's own session (`report_encounter_event`) and a refusal is shown.
- **Camera.** The web SDK has no stop-video call, so the page cannot turn a camera off. The notice tells the person to.
- **Presence.** `POST /api/zoom/webhook` -> `handleVideoWebhook` (`lib/consultations/presence.ts`). Identity is the server-minted `customerKey` (`participant-key.ts`), never the display name. Off by default behind `ZOOM_PRESENCE_WEBHOOK=1`; until then the in-app join records the join when the person is given the way in. Full reasoning and residual weaknesses: OQ-160.
- **Headers.** The Content-Security-Policy is widened for `/(patient|clinician)/consultation/:encounterId` only: scripts from `source.zoom.us` alone plus `'wasm-unsafe-eval'` (no blob scripts, no wildcard script host), connect and media to `*.zoom.us` and `*.zoom.com` including wss, blob for media and workers, no new frame source. Declared after the global rule so it wins on those paths; `csp.test.ts` proves every other path keeps the strict policy. No cross-origin isolation: it would break other embeds, and the SDK runs without it (no gallery view, lower send resolution).
- **Not built here:** mobile (OQ-158), any database change (none needed: `service_record_join` and the `left` event already exist; the room is found by `provider_room_id`, a scan of a small table).
- **Not verified:** nothing in this section has run against a live Zoom account or a real browser call (no SDK keys; the account is on the Free plan). See the checklist in OQ-136.
