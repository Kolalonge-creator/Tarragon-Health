## 1. Emergency card cover

`emergency_card_coverage` (patient_id PK; scheme `hmo` or `nhia`; optional member number and plan name; provenance fixed `patient_entered`; `entered_by`). Own-row SELECT only; no client write grant; the one door is `set_emergency_card_coverage(scheme, number, plan)` (both blank removes). Audit rows name fields set, never values. The live card wrapper adds a `coverage` key only when filled, so the key set is unchanged for everyone else. Printed card, QR text line, phone offline card (cached with the rest) and live view show it only when filled and say "Entered by the patient. Not checked with the scheme." Not in the lock-screen payload; a migration assertion and a proof check enforce that.

## 2. Immunisation card

`/patient/my-health/immunisation-card` (web, read-only, printable) and an Immunisations block in the phone's My Health section. Both use `buildImmunisationCard` from `@tarragon/shared` over the vaccination module's records and next doses. A dose is "checked by your care team" only when its status is `verified`; a rejected certificate is not shown as a dose. A failed read says so, never an empty card.

## 3. Outside records

No new table. `patient_documents.verification_status` (`unchecked` default, `verified`, `not_verified`, `not_applicable` for clinician-filed documents) with a stamp constraint (`verified` / `not_verified` exactly when `reviewed_at` is set), an insert trigger that forces `unchecked`, and an update guard that allows the status to move only inside `verify_outside_record`. `verify_outside_record`: clinical-tier doctor of the organisation (care coordinators and the patient refused), care tie via `can_staff_read_clinical`, once only, reviewed_by / reviewed_at server-derived, audited; a doctor with no tie gets `refused` and a kept denied-read audit row (returned, not raised, because a raise would roll the audit row back). `open_outside_record_for_check` is the one audited open that returns the path and a few facts; the page signs the URL server-side.

Nothing is ever copied into a structured clinical table, by anyone, whichever way the doctor decides. "Verified" only changes the label and who is named. The FHIR export lists the status; the timeline no longer says "added to your record"; the staff `documents` view carries the status.

Patient labels (web, phone) come from `outsideRecordLabel` in `@tarragon/shared`: null-gated, so "checked" needs status, reviewer and time together; anything less reads "supplied by you, not yet checked".

Queue: `outside_records` in `clinical_worklist()` and the org totals; the shared work queue page links each item to `/clinician/outside-records/[documentId]`.

## 4. Verification gaps closed

`apps/web/src/app/share/[token]/pin-gate.test.tsx`: the real PIN form and the real server action over a fake door that follows the rules the S09x SQL proof pins (five tries, the fifth locks, a locked link answers like any dead link, a right PIN opens, a malformed PIN never reaches the door).
