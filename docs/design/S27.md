# S27 Design: partner portal, lab orders, result entry, release rules

Spec 4.4, 9.6, safety cases 11 to 13. Depends on S25 (paid lab orders), S13 (neutral notices), S16 (tasks), S10 (events). Invariants: INV-03, 04, 07, 10, 13, 15, 16.

## 1. What exists (extended, not rebuilt)
- `lab_orders` (live, 48 columns: provider, status `payment_confirmed, ordered, sample_collected, processing, resulted`, `partner_reference`, `sample_collected_at`), `lab_providers`, `lab_specimens`, the `lab_partner` role bound to one provider (`private.lab_partner_provider()`), the `/lab-partner` area and worklist RPC `lab_partner_orders`.
- `lab_result_documents` is the old PDF path. **It conflicts with INV-03** (a patient reads the row at once and a partner PDF notifies them at once). Not changed; recorded as OQ-177. The new path never writes to it.
- S16 `create_clinical_task` and task types `critical_result_review`, `routine_result_review`; S10 `emit_domain_event`; S13 templates; `private.log_audit`.
- Not present: `lab_results`, `lab_result_items` (created here).

## 2. Decisions
1. **Panels are versioned data.** `lab_panel_versions(panel_code, version, analytes jsonb)` seeded from the registry entry `lab.panels` (mirror test). Every result stores `panel_version_id` (INV-16). Values are PROPOSED and need CMO signature (OQ-176).
2. **The database is the classifier.** A submitter sends analyte, value and unit only. The unit must match the panel; range and flag are computed from the stored panel version. A client flag is never read.
3. **Release rule** (one function, `private.classify_lab_result`, mirrored by the pure TypeScript `packages/clinical` module and tested on the same fixtures): any `sensitive_positive` -> `clinician_disclosure_required`; else any item not `normal`/`negative`, or a required analyte missing -> `awaiting_review`; else `released` (reason RES-001, reviewed_by null, an audit row). Critical values make a `critical_result_review` task, other abnormal ones `routine_result_review`, a sensitive positive a new task type `sensitive_result_disclosure` (class 2, senior doctor, 120 minutes).
4. **Release is a clinician act.** `release_lab_result(id, note)` for `awaiting_review` only; `record_disclosure(id, note)` for `clinician_disclosure_required` only, after the clinician has told the patient in person (attestation text recorded). Both audited, both refuse a clinician with no task or lead link to the patient (INV-12 via `private.clinician_may_read_patient`). `withhold_lab_result(id, reason)` keeps a result back (wrong patient, lab error). A released result is immutable; a correction is a new result that supersedes it.
5. **Patient sees only released rows** (INV-03): RLS on both tables, plus the PDF lives in a private bucket `lab-results` with no patient policy and is handed out by `lab_result_file_path(id)` only when released. The patient's own uploaded file is visible to them (they supplied it) and marked unreviewed.
6. **Sensitive items never explain**: `my_lab_results()` returns `explain_allowed = false` for any result with a sensitive analyte, and the AI/audio layers must read that flag. The notice template is one neutral line (`lab_result_ready`), sent on release only, never on receipt.
7. **Three writers, one core.** `lab_partner_submit_result` (partner, own provider only, own order), `patient_add_lab_result` (patient PDF, held), `team_submit_lab_result` (staff roles, structured or PDF). All call `private.submit_lab_result`.
8. Test accounts carry `is_test` through (INV-13). No money.

## 3. Screens
Partner `/lab-partner/results`: paid orders, booking reference, mark collected, structured entry form (analyte list from the panel, unit and range shown read-only), PDF attach, submit, then a plain "received, released or held" line (never the clinical reason). Clinician `/clinician/lab-results`: queue of held results with values, release or withhold; disclosure page with the attestation. Patient: results list reads `my_lab_results()`; held shows "your care team is reviewing this", disclosure-required shows "your care team will contact you". English and Pidgin strings in `packages/i18n`.

## 4. Proof
`packages/db/tests/s27_lab_results_release.sql`: cases 11, 12, 13, RLS (patient, other patient, other lab, anon), tasks, template wording, sabotage of the release rule and of the patient policy. Jest: classifier fixtures, mirror test, template lint.
