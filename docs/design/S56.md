# S56 design note: Module 10 (1 of 2), check-ins, screening, crisis, human care

Functions 10.1, 10.2, 10.3, 10.13. Spec lines 1280 to 1334. Plan: `docs/design/S55-S60-build-plan.md` 4.2 and 9. Founder decision 2026-10-07 (point 4): all mental-health tables move to per-patient access (INV-12) with audited reads (INV-10).

## Reused (not rebuilt)
`mental_health_screens` (PHQ-9, GAD-7, AUDIT-C, EPDS, bands, crisis flag), `mental_health_screening_cadences` and schedules, `classify_mental_health_screen_concern`, `wellbeing_checkins` and preferences, `therapy_sessions` and the network, F1's crisis task, urgent `crisis.detected` event and neutral page, the S19 on-call page, `clinical_tasks` types (`symptom_review`, `admin_clinical`), `private.clinician_has_patient_access` (the INV-12 tie), break-glass (`emergency_record_access_grants`), `profile_access_categories` and `set_care_access_categories` (owner-only, logged consent), S37 go-live guards, `private.emit_domain_event`, the INV-07 template lint.

## Data model (migrations 20261007150213 to 20261007152231, none applied to production)
1. `care_access_category` gains `mental_health` (own migration; an enum value is unusable in the transaction that adds it). Granted to nobody on creation.
2. Per-patient access: policies on `mental_health_screens`, `mental_health_screening_schedules`, `wellbeing_checkins`, `wellbeing_checkin_preferences`, `therapy_sessions` admit only the patient and a supporter with the explicit `mental_health` category (no dependent bypass, expiry honoured). Staff read through `public.read_patient_mental_health_audited` (sections: screens, checkins, therapy_sessions, schedules, handoffs): an active clinician who is not a care coordinator, with a tie or an active break-glass grant; every read and every refusal is an `audit_log` row (`staff.mental_health_read`). Admin, ops, finance, analyst, corporate, sponsor, the CMO without a tie, and support-view sessions are refused. Therapy queue and count are audited functions; `approve_therapy_session` now needs prescribing authority AND the tie (it admitted any org staff); a patient may only cancel their own booking; a psychiatry request creates an `admin_clinical` task so a clinician can claim it (the claim creates the tie).
3. New: `wellbeing_checkins.tags` (fixed list, CHECK), `mental_health_handoffs` (patient-sent summary, task id), `mental_health_follow_up_config` (DRAFT, PROPOSED, unsigned), `crisis_card_config` (PROPOSED: 112, 30-minute callback shown only once confirmed). No helpline table: founder decision 2026-10-07, there are no usable crisis helplines in Nigeria, so the card shows none (they can be added later with a verified-only gate).
4. Leaks closed: the concern alert and the emergency event no longer carry the instrument, score, band or self-harm wording (and the generic emergency alert masks the source name for the two mental-health sources); a one-off function rewrites existing alert text; `sponsor_care_report` no longer treats a mental-health alert as a clinical review; `corporate_wellbeing_cohort` is an aggregate with the organisation's minimum cohort size applied to respondents, test accounts excluded.

## Events
`questionnaire.completed` (ids only: screen_id), emitted by an after-insert trigger so every insert path emits it. `crisis.detected` is F1's.

## Functions and edge functions
Database functions only: `read_patient_mental_health_audited`, `list_therapy_approvals_audited`, `count_therapy_approvals_waiting`, `request_mental_health_handoff`, `get_crisis_card`, `corporate_wellbeing_cohort` (service role). No edge function changed or added, so nothing to deploy. The spec's `crisis-route` edge function is the F1 database trigger path; a second, parallel route would only duplicate it.

## Screens
Web: wellbeing page (crisis card always reachable and outside the shared-phone gate, shared-phone settings, tags on the check-in, mood next to readings, hand-off card, change over time on the clinician summary), clinician chart and pre-visit summary through the audited read with an explicit "not available" state, therapy approvals queue, Care Circle visibility (separate mental wellbeing switch, never bundled), Mobile: the same on the wellbeing screen (crisis card cached for offline, hand-off, tags, mood beside readings, shared-phone controls) and a separate mental wellbeing switch in family visibility.

## Safety rules
No model in the crisis path (INV-01). No AI presented as therapy. Notifications name nothing (INV-07): there is no mental-health notification template and this session adds none. Crisis flows are never behind a guard. No helpline is shown at all. Callback time never promised while a draft. The follow-up pathway is behind `mental_health_follow_up_enabled` (CMO, OFF; test accounts only until then). No analytics or ad SDK is reachable from a wellbeing screen (scan test).

## Seams for later sessions
S57: `media_library`, journal, breathing, sleep tools plug into the wellbeing page inside `SharedPhoneGate`. Module 15: reads `mental_health_handoffs where state = 'open'`. S29 Care Circle: its supporter views must call `private.supporter_has_mental_health_consent` before showing anything from the five tables. S58 rewards: subscribe to `questionnaire.completed` (ids only).

## Conventions
RLS on every table with its own grant and per-role proof; `recorded_by`/`source` n/a (patient-entered, service-scored); configuration for every clinical value (follow-up timings, crisis card) in versioned PROPOSED config mirrored by a test; go-live guard for the clinical pathway; strings in `packages/i18n` namespaces `mood` and `crisis` (English only: D-14 removed Pidgin, so the brief's `pcm` does not apply).
