# S15 Design: Clinician network data model and credentialing workflow

Spec 7.1 and 7.2, 9.1 (Training and profile, credentialing screens). Depends on S02. Invariants touched: INV-10 (every document open is logged), INV-12 (a clinician reads only their own application and documents), INV-13 (`is_test`), INV-16 (versioned config). Founder decisions applied: F-03 (hybrid, employed and freelance), F-05 (one doctor tier plus the CMO), D-10 (the clinician provides the indemnity certificate), OQ-24 (no `ops` role, a separate credentialing level). Research: `docs/research/S15.md`.

## What already exists (extended, not rebuilt)
- `clinical_staff` is the spec's `clinicians` (live wins): MDCN folio as `credential_number`, `license_verified_at/by`, `license_expires_at`, `indemnity_*` with exemptions, `employment_type`, `doctor_tier`. Two live rows, no licence or indemnity dates on file.
- Two notify-only sweeps (licence, indemnity: admins, 30 days) are superseded by the new sweep; their cron jobs are unscheduled, the functions stay.
- An older provider quality ladder (`provider_restrictions`, `advance_provider_credential_ladder`, 20260829093830) warns, then restricts new appointment bookings, on a CMO-signed policy. It is left untouched; `clinician_is_eligible()` also checks it so it can only tighten (OQ-100).
- `is_org_staff()` admits any active non-patient role, which is why an applicant must never hold `clinician` early (below).

## Data model (one migration, `*_s15_clinician_credentialing.sql`, not yet applied)
- `clinical_staff` gains `status` (active, suspended, offboarded), `credentialing_level` (1 or 2, separate from `doctor_tier`), `audited_task_count`, `max_concurrent_claims`, `max_lead_patients`, `languages`, `reliability_score`; a live-folio uniqueness index; a trigger so a suspended or offboarded clinician can never be active. Paystack and bank columns wait for S31.
- `clinician_applications` and a rule table of the only valid moves (`clinician_application_transition_rules`). State changes only through `private.apply_application_transition()`, which logs to the append-only `clinician_application_transitions`, audits, and emits an S10 event; a guard trigger refuses any other change, including by the table owner.
- `clinician_documents` (private bucket `clinician-documents`, no direct download), append-only `clinician_document_access_log`, `clinician_checks` (licence, qualifications, identity, practice years, two referees), `competencies` (7) and `clinician_competencies`, `training_modules` and `training_progress`, `credential_test_cases` and `credential_test_attempts`, `credential_grace_periods`, `credential_expiry_notices`.
- `credentialing_config` (versioned, mirrored as `credentialing.rules` in the code registry; a Jest test fails if the two drift).

## States (spec 7.1, enforced in the database)
started, documents_submitted (applicant), checks_in_progress (reviewer), training (automatic when all six checks pass), test_passed (automatic on a passing test), approved_tier1 (CMO), active (reviewer switches on), suspended, offboarded, and rejected from any state before active. No back edges: a document can be replaced while checks run without changing state.

## Evidence the licence check rests on (founder, 2026-10-06)
The current-year MDCN practising licence and a screenshot of the clinician's own MDCN portal page (there is no register to query), the graduation licence or degree certificate, the NYSC certificate, a government ID and a CV; a freelance clinician adds their own indemnity certificate. The licence check cannot pass without the expiry date printed on the licence, and cannot pass while the folio is held by another live clinician.

## Safety rules
1. **An applicant is never `role = clinician` before activation.** `activate_clinician()` flips the role in the same transaction that switches them on; suspension and offboarding flip it back to `patient`. Approval alone changes nothing, because `is_org_staff()` would otherwise admit them to patient-scoped data.
2. **Maker-checker.** A reviewer cannot verify their own application; the approver must be an active CMO, not the applicant, and (config) not anyone who verified a check on that application. A sole founder needs two accounts (OQ-107).
3. **The answer key never leaves the database.** Test cases are readable by reviewers only; the test is scored in SQL (one source of truth, no TypeScript copy to drift). Pass = 80 percent AND every safety-critical scenario right; a red miss is kept for audit but not named to the applicant. Three attempts, a 24 hour cooldown, a fresh set each retake where the bank allows, an extra attempt only from the CMO.
4. **Documents.** The bucket has no policy for signed-in users at all. The web action checks the real file type from the first bytes and the size, stores the file with the service role, then calls `register_clinician_document()`, which confirms the object exists with the declared size and type and that the path is in the caller's own folder. Replacing a document whose check already passed sends that check back to pending. A failed registration removes the stored file (a failed removal goes to Sentry). A document opens only through `/api/credentialing/documents/[id]`, which asks the database first (owner or reviewer) and writes an access-log row; anyone else gets the same 404 as a missing file.
5. **Expiry** (`private.credential_expiry_sweep()`, 06:00 Lagos): the clinician is told 90 days before, 30 days before and on the day, by in-app and email; reviewers hear at 30 and 0. A late sweep sends one notice, not a burst. After the expiry day, with no audited grace period and no exemption, the clinician is suspended (access paused, role back to patient, application suspended, `clinician.suspended` event for S18/S19 to reassign). A missing date never suspends (the two live rows). An audited grace period (reason of at least 10 characters, capped at 14 days, the reviewer named) holds suspension and is told to the clinician. Failures open an ops incident, never silence. Reinstatement needs the renewed document recorded and checked.
6. **Eligibility.** `private.clinician_is_eligible(profile_id)` is the one function S16 to S19 call: active, status active, licence in date or in grace, indemnity in date or in grace where required and not exempt, and no live restriction from the older ladder.

## Screens
Built in `apps/web`, not the console (OQ-99): the clinician area has not been extracted, and the console may not be widened to a role whose area has not moved. Applicant and renewal at `/account/clinician` (details, documents, training, test); the reviewer queue, application review and licences-and-cover dashboard at `/admin/credentialing` (admin) and `/clinician/credentialing` (CMO, whose account role cannot open `/admin`); the CMO writes and approves training and test content at `/clinician/credentialing/content`; a clinician's own page at `/clinician/credentials`; `/credentialing` is a role-aware doorway for notification links. All forms are plain server-action forms (no client script), so they work on a slow connection. Staff-area copy is English like the existing staff pages (OQ-102).

## Not built (belongs elsewhere)
Availability blocks and the on-call rota (S18, S19), conflict enforcement against a patient (S17; S15 only records the declaration), earnings and bank verification (S30, S31), enforcing level 1 task limits and the audited-task counter (S16, S17, S20), reassigning patients when someone is suspended (S18, S19, which subscribe to `clinician.suspended`), an automatic purge of documents past `retain_until` (OQ-108), generated database types (the screens parse every result with Zod instead).
