# S85b design note: web offline emergency guidance and the journeys refresh

Status: built locally on `s85/journeys-refresh-web-offline`, 2026-10-27. Not pushed. No migration.

## Problem
INV-06 says a red reading shows emergency guidance with no network. The phone meets it with an on-device engine. The web did not: `vitals-form.tsx` only refused to save offline, and `sw.js` cached an offline page with no guidance. Separately, the S85 journeys carried pending steps and event-map gaps whose owner sessions had since landed.

## Web offline guidance
- `lib/vitals/offline-emergency.ts` runs the shared pure engine (`@tarragon/clinical` `grade`) over the bundled draft `BP_CARE_V5`, the same fallback the phone uses, with no request. It shows guidance when the engine says red, when the reading is at or above the question line (the web cannot ask the symptom question, so guidance is the safe error, as `bpAckWebCode` already does online), when the web classifier says crisis, or when any listed symptom is ticked.
- Never weaker than the server: a Jest grid compares it with rule sets v3, v5, v6 and v7 over readings and symptom sets and fails on any red it misses; two sabotage variants prove the grid can fail. The journey repeats the comparison against the stored server grade.
- Words: only `activeWording(code)` for the engine's own code (EMG-001, or EMG-001L). The one text this work owns is "your reading has not been saved", which is about the save, not clinical.
- The form shows five symptom ticks only while offline (they are not posted), opens the dialog on a tick or a blocked save, and still refuses to save. No outbox exists on the web, so it does not claim a save; see OQ-S85B-3.
- `public/offline.html` carries the same wording as static text; a test keeps it identical to the wording in force and free of script and URLs. `sw.js` cache name moved to v2 so installed workers refetch the page.
