# S39d: registry, test-account purge, complete export, retention report

Founder direction 2026-10-07 (OQ-262 to OQ-264): do not erase real data, but test data must be deletable; retention by international standard; export from the same registry with a 30-day review clock.

## Design
- `data_registry`: one row per patient-keyed table (a `patient_id` column, or listed in `staff_read_scope` with its own expression): retention class, end of retention (review or delete), export flag, `reviewed` (false until the CMO and DPO confirm). Built from the catalog; the migration and the proof fail if a patient table is missing.
- `purge_test_account(profile)`: refuses a real account (`is_test` false), a caller who is not an admin or the service role, anon and the caller's own account. It walks every foreign key that points at the rows: a nullable authorship column is set to null, any other row is deleted after its children. A first pass learns which tables are touched; only the enabled user triggers on those tables are switched off (append-only guards), the second pass changes them, and the same triggers are switched back on. Then the login is deleted. The purge is audited. Real data has no such path.
- `export_patient_data(patient)`: admin only, every table with `in_export`, JSON per table, any key matching token, secret, password, hash, api_key or passcode removed, audited. `data_export_requests.due_at` is the review clock (30 days, config v3).
- `retention_review_report()`: per table, rows older than the class period (config). Report only; deletes nothing.
- Screens: `/admin/access-review`, `/clinician/access-review` (CMO): per-clinician access review, latest openings, retention report. Both are in the console search.

## Limits
Rows are counted by age, not by the patient's last contact, so the report over-counts for an active patient. Files in storage owned by a purged account are not removed. The export route `/api/patient/data-export` is not yet connected to the new function (OQ-285). The registry classification is by table name and needs review (OQ-284).

## Proof
31 checks and two sabotages. The purge also ran against the live `is_test` accounts in a rolled-back transaction.
