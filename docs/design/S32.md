# S32 design note: audio manifest, bundling and number stitching

Section S32 of `docs/BUILD-SPEC-v5.md` (8.8 Audio, 12 Internationalisation and content). Depends on S12 (done). Sources: `TH-NUM-number-list.csv` (copied to `audio/source/`) and the ElevenLabs Audio Production List v1.0 (read by the import script; the .docx stays outside the repo).

## 1. What exists today (reconciliation)

- No audio files, no manifest, no audio library in `apps/mobile` (no `expo-audio`, `expo-av`, `expo-file-system`). `docs/RECONCILIATION.md` row 9 and the "/audio manifest" gap confirm it.
- S12 left one seam: `triageAudioId()` in `apps/mobile/src/lib/triage-device.ts` returned `audio-pending:<code>`. S32 replaces it with the real clip id.
- `packages/i18n` has `en` and `pcm` catalogues; the live boundary (OQ-19, OQ-87) holds clinical Pidgin as English until a clinician signs it and a native speaker reviews it. This design keeps that rule.
- No recordings exist, so nothing is playable yet. That is the honest state; the build is the machinery and the proof that it fails safe.

## 2. Data model

No database table, so no RLS test. The data is a file, `audio/manifest.json`, generated by `scripts/audio/import-production-list.py` and edited afterwards only by `scripts/audio/ingest-recordings.mjs` and by a person adding a sign-off.

- 835 clips: 195 scripted clips (ONB, NAV, HLP, EMG, TRI, SYM, CON, SYS, REM, RES, plus 22 NUM phrase clips and the decimal word) and 640 number clips (`NUM-000` to `NUM-600`, `NUM-S1000` to `NUM-S20000`). Long-form groups (BPC, DMC and the Release 2 and 3 libraries) have no scripts yet and are added by their own sessions.
- Per clip: `bundle_group` (`bundled` for ONB, EMG, TRI, NUM, SYM; `post_signup` for NAV, HLP, CON, SYS, REM; `on_demand` for RES and later-release help), `clinical`, `legal`, `language_neutral`, `pcm_text`, and per language `{file, sha256, bytes, duration_ms, approvals[]}`. Whole numbers are one shared recording (`TH-NUM-148.mp3`); everything else has `-EN` and `-PCM` files.
- Review state is data. A recording may play only if it exists (checksum and size) AND carries every sign-off it needs: brand always, clinical for clinical clips, legal for CON-001 and ONB-010, a native Pidgin listener for any Pidgin file. The import script never writes an approval; the validator rejects an approval on a file with no recording, and rejects approving Pidgin that is still held as English.
- Script text lives in `packages/i18n/src/audio-scripts.ts` (generated), which is also the text shown when a clip cannot play. Clinical Pidgin there equals the English text.
- PROPOSED values in `packages/shared/src/proposed-config`: `audio.bundled_max_bytes` (15 MB), `audio.mono_bitrate_kbps` (48), `audio.speech_chars_per_minute` (900), `audio.number_clip_seconds` (2).

## 3. Behaviour

- **Resolve** (`packages/audio`, pure): a list of clip ids and a language become a play plan or text only. All or nothing: if any clip of a phrase cannot play, none do. A Pidgin request falls back to English audio only when every clip's Pidgin text is held as English, so the voice always says what the screen says. Problems are reported as non-fatal issues and never thrown.
- **Stitch**: blood pressure, glucose (mg/dL or mmol/L with the decimal word), weight, pulse, HbA1c, weekly average with comparison, adherence, streak, steps. A value the kit cannot say exactly gives null (text only): over 600, negative, not a number, 601 to 999 or above 20,500 steps.
- **Bundle**: `filesInGroup`, `bundleReport` (clips, recorded, pending, bytes), `projectedBundleBytes` (real bytes where recorded, an estimate from script length otherwise). A test fails if the projection exceeds `audio.bundled_max_bytes`; today it projects about 13.1 MB for the bundled groups without SYM and 13.9 MB with it (budget 15 MB, so the headroom is small). SYM ships only when the symptom checker is switched on (`--with-sym`, spec 8.8).
- **Download planning**: post-sign-up files only for signed-up users, on Wi-Fi, never in low-data mode, only in the person's language plus shared files, skipping what is on the phone. On-demand clips are never fetched ahead. Files are addressed by checksum, so a re-recorded clip never serves a stale file.
- **Language switching**: the language is chosen per request from the app language and the platform Pidgin switch (`audioLang`), so a switch needs no restart; the service stops what is playing.
- **Mobile**: `apps/mobile/src/lib/audio/` has the service, a manifest loader that treats a bad manifest as "no audio", an issue log, and an empty generated asset map. The native player is a port (`AudioEngine`).

## 4. Safety rules (what must hold)

1. INV-06: emergency, triage and number clips are bundled, resolved from the phone only, with the text returned alongside.
2. INV-04: no clip explains a positive HIV, hepatitis B or hepatitis C result; a test reads the RES scripts.
3. INV-01: no language model anywhere in the path; nothing here calls a model or a network.
4. A half-spoken reading never plays; a number out of the kit's range is never rounded into a different number.
5. Unsigned or unrecorded audio never plays, and unreviewed Pidgin is never voiced.
6. Missing audio is never fatal: the text is shown and one issue is logged.

## 5. What this session did not do (see OQ-197 to OQ-202)

No recordings exist. The native audio module needs a new build and `runtimeVersion` bump. No Listen button is wired into a screen, because the recorded EMG and TRI scripts differ from the text the app shows today and the voice must say what the screen says.

Today the proof is for the machinery; the recordings are the missing half.
