# S47b: Today plan, streak, weekly cards, trend bands, readiness (spec 4.1, 4.5, 4.6)

Gate: one governed config row, `home_card_config` (registry `today.home_cards`), born unsigned and inactive. While unsigned, `my_home_card_config()` returns null and every surface keeps today's behaviour. The CMO signs on the sign-off hub.

- today-build: `packages/clinical/src/today-build.ts`. Picks cards from facts (counts and yes or no only). Primary actions: only `primary_eligible` cards with something to do, ranked overdue task first then configured priority, hard cap 2 (config validator, SQL validator and the function). Everything else is secondary and collapsed. Phone runs it; `POST /api/mobile/today-build` is the same function on the server.
- Streak: existing `computeStreak`, now drawn. Done days = any logged vital (Lagos days); proposed freezes are stored on the phone before the day rolls over. Words only, no shame state.
- Weekly cards: blood pressure (cuff readings under the person's own target, min readings from config), activity (S48a week), meals (S49a days), medicines (adherence report formula). Labelled as what was logged.
- Bands: glucose and weight on the phone via `trend-bands`, same eligibility as the web.
- Readiness: median of the person's own earlier days; sleep, HRV, resting heart rate; estimate label; none unless a device and fresh data exist.
- No notifications added (INV-07). No language model anywhere.
