# S44 design note: interoperability (spec 2.10 to 2.14), closing Module 2

Invariants in play: INV-02 (nothing from outside is the record until a clinician files it), INV-03/04 (released, non-sensitive results only; lab push rides the S27 writer), INV-07 (events carry ids only), INV-10/12 (staff export and external-record reads are audited and tied), INV-13 (`is_test`), INV-14 (lab push guard), INV-16 (versioned mapping config). Research: `docs/research/S44.md`. Founder waiver of the S40 gate is recorded in `docs/BUILD-PROGRESS.md`. Four migrations (`20261007152041`, `...152318`, `...152547`, `...152802`), later than S43's and S45's newest and than live `list_migrations` (newest `20261007124418`); **none applied to production**.

## 1. What already existed (reused, not rebuilt)
`fhir_import_batches`, `fhir_import_proposed_resources` (clinician confirm trigger), `fhir_loinc_vital_type_mappings`, `/api/v1/fhir/import` + parser + `/clinician/fhir-review`; S43 tables (`procedures`, `immunisations` view, `patient_documents`), audited helpers (`can_staff_read_clinical`, `audit_chart_read`), share-link section data shapes; S27 `lab_panel_versions`, `private.submit_lab_result`, release rules; `enforce_vitals_reading_source_lock`; `data_correction_requests`; `wearable_device_data` consent type; the PROPOSED-config registry; S37 go-live guards; the S10 outbox.

## 2. Data model
- `external_exchange_consents` (per system, direction, placeholder wording key, withdrawn_at); `external_records` (immutable evidence with source, batch, consent, disposition); `patient_item_notes`; `fhir_export_log`; `lab_code_mappings` (per lab LOINC + UCUM, proposed then CMO-confirmed); `lab_result_pushes` (idempotent on the lab's message id). `data_correction_requests` gains `item_table`/`item_id`.
- No client role can write any new table directly (asserted in each migration and in the proof).

## 3. Functions and services
- `fhir_import_accept` (service role): consent check inside the database, batch + proposals + evidence + event in one transaction, supersedes an older unreviewed copy. No consent: nothing stored, audited.
- `fhir_export_snapshot(patient, sections, reason)`: self, supporter per category, or staff through the tie with a reason and an audit row; released-only labs; documents as metadata only; reproductive and mental health are not sections; private notes never included. `apps/web/src/lib/fhir` maps the snapshot to Patient, Observation, MedicationStatement, Condition, Immunization, DocumentReference (and AllergyIntolerance) using the versioned `fhir.mapping`; `GET /api/patient/fhir-export`.
- Import hardening: units checked and converted (`units.ts`), a missing or unknown unit is a skip with a reason (the old parser ignored units), every received resource kept as evidence, `x-fhir-source-system` required, parser version 2.
- `lab_partner_push_result` + `POST /api/lab-partner/results/push`; mapping propose/confirm/retire functions; guard `lab_structured_push_enabled` (OFF).
- `consent_in_force` + `deviceDataConsentRefusal` on the health-store route (both calls).
- Notes: `set_item_note`, `my_item_notes`, `request_item_correction`. Adapter seam: `lib/fhir/adapters` (Helium Health "not configured").

## 4. Screens
`/patient/data-exchange` (download, per-system consent with a placeholder wording line, received records, who made a copy); an "add a note / this looks wrong" control on each timeline item of the person's own timeline. Not built: a staff screen to propose and confirm lab mappings (database functions only), a lab-portal form for the push (API route only), mobile screens.

## 5. Safety rules (each has a test)
Import without consent stores nothing; a replay is idempotent; a unit is never assumed; export cannot name reproductive or mental health; a held, withheld or sensitive-positive result is never exported; a supporter gets only categories granted; an untied clinician is denied and audited; an unmapped lab item rejects the push; only the CMO confirms a mapping; the lab is never told why a result is held; a locked device reading stays locked while still annotatable; the health-store route fails closed without consent.

## 6. Go-live and gates
Lab push: `lab_structured_push_enabled` OFF, cannot be switched on until conditions exist in `private.go_live_conditions` (not restated here; OQ-S44-2). Import and export need no flag: they only narrow access (consent, scope).

## 7. Acceptance tests of Module 2 (see BUILD-PROGRESS for results)
Expired share link 410 and logs the attempt (S43 proof 5u); OCR rejection leaves no record (S43 proof 2); FHIR round trip preserves values and units (`round-trip.test.ts`).
