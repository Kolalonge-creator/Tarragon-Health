# S64 design note: consultations gaps (Module 15, functions 15.1 to 15.7)

Decisions in play: CMO Q19 (licence number and checked-on date), Q23 (doctor consultations follow the membership rule; dietitian, pharmacist and specialist bookings are priced per item), OQ-133 (cash refund of a cancelled consultation stays undecided). Invariants in play: INV-01, 02, 07, 09, 10, 11, 12, 13, 14, 15. Migrations: `20261007123557_s64a_pharmacist_appointment_type.sql`, `20261007123607_s64b_consultation_gaps.sql` (NOT applied to production). Proof: `packages/db/tests/s64_consultation_gaps.sql`. No new events; nothing here calls a language model.

## 1. What already exists (reused, not rebuilt)
Encounters, rooms and events (S21); declared bookable time and `list_bookable_consult_slots` (which already took language and sex); hold, confirm, cancel and the consultation policy (`consultation_policy_config`, cancel window 2 hours, credit returned, never cash); one price NGN 10,000 (`video_visit_credit`); VideoProvider with Zoom, audio-only and the dial-in phone fallback with its ladder state machine and `CallController` tests (S21, S14); written questions (S22); scribe consent per consultation, transcripts, the two-stage draft and `scribe_review_events` (S23, S35c); prescriptions, referrals and `care_plan_changes` (S24, S05e); the appointment reminder job with two-way replies (confirm, reschedule, cancel, need help). Where a spec function was already met, this session only adds the gap.

## 2. Gaps closed
| Fn | Change |
|---|---|
| 15.1 | `list_bookable_consult_slots` gains specialty and role filters and returns sex, the MDCN number and the checked-on date. The number is returned only when a credential check is on record (`credential_verified_at`), and the screen shows it only with its date (null-gated, Q19). Price is shown, never filtered. Spoken language is clinician data (`clinical_staff.languages`), not UI localisation. New `clinical_staff.care_role` (doctor, dietitian, pharmacist); a non-doctor role must sit on the `care_coordinator` tier, so auto-assignment, prescribing and signing never reach it. `pharmacist` added to `appointment_type`. Per-item products `dietitian_consult_credit` and `pharmacist_consult_credit` are seeded INACTIVE at price 0: hold refuses them and the listing is empty until a price is set (OQ-S64-1). hold and confirm repeat the live definitions with marked changes; `private.booking_product_code` is the one type-to-product map. |
| 15.3 | `consultation_intakes`: reason, duration, up to five fixed-key answers, in the patient's own words. Draft has no summary. `send_consultation_intake` writes the summary by plain code (`private.build_intake_summary`) and the row becomes permanent. The assigned clinician reads it through `clinician_consultation_intake` (audited, INV-10, INV-12); a draft is never visible to them. The screen carries the standing "go to the nearest hospital now" line; the text is not screened for danger (OQ-S64-3). `source`/`source_ref` is the typed seam for a later symptom-checker summary (the table refuses such a row without a reference). |
| 15.4 | An AI-drafted note cannot be signed until `confirm_scribe_safety_lines` has been called (trigger on finalise); any edit to the note text clears it (trigger); a note with no AI draft is unaffected. The sign-off view lists allergy and medicine lines first (plain text matching, deliberately generous, never decides anything) with one explicit confirmation. A visible "Write the note myself" path loses nothing; consent stays one row per consultation. |
| 15.5 | Verified, no new code: the patient reads notes through `my_released_notes`/`my_note_index` (signed only), prescriptions through a policy that excludes drafts, care plan changes through `my_care_plan_changes` (never proposed or rejected). The proof asserts each. |
| 15.6 | `specialist_referrals.facility_id` (nullable FK to `facilities`, restrict) with `facility_name_text` as the free-text fallback, never both (CHECK). `set_referral_facility` follows the same visibility rule as other referral writes, accepts only an active listing, refuses once signed (a referral is signed when its draft is submitted, so the facility is named on the draft). The referral letter's "To:" block names the facility. |
| 15.7 | `my_booking_terms(type)` returns price, cancel window and refund basis `credit`. `BookingTermsCard` is shown on every path that ends in a payment button (new booking, awaiting-payment list, the older video-visit request), and the pay button in the booking flow stays off until the terms have loaded. The text promises the visit credit back, never cash (OQ-133). |
| reminders | `queue_appointment_reminders` gains a 7 day milestone, sent only for a visit booked 7 or more days ahead; the existing 24 hour and 2 hour milestones remain. Replies are the existing confirm and cancel buttons. In-app, push and email via `patient_reminder_channel`; never required for any flow; no no-show ban exists anywhere. |
| ladder | Already covered by `consultation-ladder.test.ts`, `consultation-call.test.ts` and `call-controller.test.ts`; S64 adds an end-to-end walk test. Not run on a real phone (OQ-158). |

## 3. Safety rules kept
RLS on the new table with explicit `grant select to authenticated` and all writes through definer functions; `anon` has no execute on any new function (asserted in the migration); `is_test` copied from the patient; every clinician read audited; nothing writes AI output anywhere; INV-07: reminder payload carries only ids, time and appointment type. PROPOSED values live in `consultations.access` (drift-tested against the migration); no price is assumed.

## 4. Not built, on purpose
Specialist booking priced per item (no specialist booking product exists; the decision is recorded, the build is S65's directory half); a caregiver-written intake; symptom-checker intake (needs S60); a patient-side screen for the facility on a referral beyond the letter; the scribe safety panel does not read the patient's recorded allergy list (it shows the draft's own lines).
