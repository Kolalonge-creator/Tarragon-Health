# S11 Design: triage engine (`packages/clinical`)

Spec Sections 6.1 and 6.2, safety cases 1 to 7 and 20. Depends on S10 (closed). Invariants touched: INV-01 (pure code, no model), INV-05 (red always carries `page_on_call`), INV-06 (runs on device, no I/O), INV-07 (action message keys are neutral), INV-16 (every result carries the rule set code and version), INV-13 (nothing here writes data).

## What already exists
- `apps/mobile/src/lib/bp-log.ts` `TriageEvaluator` seam wraps `classifyVitalOffline` (live bands, OQ-67). Left alone: S12 swaps it for this engine.
- `private.classify_bp_level` and the live red-flag triggers (stricter in places than the spec). Unchanged; OQ-67 says S12 aligns them.
- `packages/symptom-triage-engine` is the older symptom checker. Unrelated; untouched.
- `proposed-config` registry (`triage.silence_rule_days`, `adherence.threshold`, `bp.starting_suggestion_target`). The silence and adherence lines are read from the rule set's own parameters, which a test ties to those registry values so they cannot drift.
- No `triage_rule_sets` or `triage_events` table. This session adds only `triage_rule_sets`; `triage_events` belongs to S12.

## Package
Pure TypeScript, no imports from other workspace packages, no `Date.now`, no I/O, no randomness. `now` is an input.
- `grade(input, ruleSet) -> TriageResult` (`engine.ts`).
- `validateInput` (implausible and malformed readings, TRI-006) and `validateRuleSet` (a rule set that is malformed is refused, never half-applied) (`validate.ts`).
- A tiny declarative condition language (`all`, `any`, `not`, `cmp`, `symptomAny`, `inSet`) over a derived context (`context.ts`), so the thresholds are JSON data, not code.
- `rules/bp-care-v1.json` is the bundled rule set (device copy) and the seed of the server row; a test fails if they differ.

## Input and output
Input: `trigger` (observation with reading, symptoms and recheck state, or adherence, or silence), `history` (previous readings, last 14 days, current reading excluded), `target`, `adherence`, `pathway` (`state`, `carePack`), `pregnant`, `age`, `now`, `existingOpenTaskKeys`.
Output: `status` (`graded`, `recheck_required`, `rejected`), `grade` (`green|amber|red|null`), `ruleId`, `explanationKey`, `actions[]` (structured, each with a string form like `show_emergency_guidance:EMG-001`), `taskKey` and `duplicateSuppressed`, `recheck` (`afterMinutes`, `windowMinutes`), `ruleSet` (`code`, `version`), `matchedRuleIds`.

## Behaviour
1. Validate the input; implausible readings give `rejected` with TRI-006 and no grade (case 5).
2. Evaluate rules in file order for the trigger. First red wins and is never held back by a recheck. Otherwise the highest grade wins, earliest rule on a tie. A rule marked `recheck` does not grade; if it is the only match the result is `recheck_required` with no grade.
3. Recheck (BP-A1): first elevated reading with no red flag asks for a repeat after 5 minutes (case 3). A repeat that is too soon asks again with the minutes left. A valid repeat that is also elevated confirms A1 (amber, due in 4 hours). A repeat that is lower is graded on its own. No repeat within 15 minutes: the caller sends `timed_out`, and the first reading is graded as if repeated.
4. Task keys are stable per cause and anchor (silence anchors on the last reading date), and a key already open drops the `create_task` action (case 7).
5. Pregnancy and age under the adult line route to a clinician after the red rules (amber, `route_referral`). They never silently use adult bands.

## Safety rules
- No model call, no network, no clock. Identical input and rule set give identical output.
- Every value in the rule set is PROPOSED and awaits CMO sign-off (`status` of the DB row is `draft`; the seed is never `approved`). The registry entry `triage.bp_rule_set` lists it on the go-live dashboard.
- Notification keys on actions are neutral; a lint test scans the English and Pidgin text for clinical terms (case 20, INV-07).
- Pidgin safety strings are held as English until a native reviewer signs them (OQ-74).

## Data model
`triage_rule_sets` (code, version, status `draft|approved|retired`, rules jsonb, approved_by, approved_at, timestamps). Unique on code and version. Approval requires `approved_by` and `approved_at` (CHECK). Rules are immutable once approved (trigger). Staff with the admin role read; clinicians read approved sets only; patients nothing; writes through service role or admin. RLS proof in `packages/db/tests`.

## Events and screens
None. S12 wires `observation.recorded` to this engine and emits `triage.graded`; S12 builds the device flow.

## Tests
