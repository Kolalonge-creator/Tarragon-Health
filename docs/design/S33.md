# S33 design note: BP care course, breathing exercise BRE-01, en/pcm catalogues

> **Update 2026-10-07 (founder decision D-14, English only):** every Pidgin part of this note was removed from the build: no `pcm` text, no held-in-English ledger, no translation row or column, and `learning_course()` serves English only (migration `20261007123419_s33_course_english_only.sql`). The Pidgin passages below are kept as the record of the original design and no longer describe the code.

Stacked on S32 (PR #961, open). Research: `docs/research/S33.md` (most named-product behaviour is UNVERIFIED there; the design leans only on the three verified items and on the platform's own rules).

| Programmes and modules, `health_education_programmes_list/_detail` RPCs, progress with `check_score/check_total` | `health_education_programmes`, `_programme_modules`, `_progress` | the course is a programme |

Live counts (2026-10-06): 235 content rows, 219 active, 6 clinician reviewed, 0 translations, 0 progress rows, 0 rows with a review date. A review-date rule therefore changes nothing that is live today.

## 2. Gaps S33 closes

1. No BPC lessons exist (the production list holds briefs only; scripts are "written from WHO HEARTS and approved before recording").
2. A lesson has no audio clip id, no single "what can I do next" action, and translations cannot carry their own knowledge check or a review state.
3. `review_due` content is still served; spec 9 says an expired review hides the item.
4. No guided breathing anywhere.
5. Mobile has no course view, no lesson audio player with transcript, no completion event.
6. No way to show that Pidgin is genuinely translated versus held in English.

## 3. Data model (one migration, additive)

- `health_education_content`: add `audio_clip_id text` (a manifest id such as `BPC-04`), `next_action text` (one concrete thing to do today).
- `health_education_translations`: add `knowledge_check jsonb`, `next_action text`, `review_state text` (`needs_native_review` default, `native_reviewed`). No existing RPC is rewritten.
- New `public.learning_course(p_programme_code text)`: one call returns the ordered lessons with language-resolved text, audio id, progress, reviewer credit only when `clinician_reviewed` and `reviewed_by_name` are both set, and the review-due date. Strict at read time: a lesson is returned only if `content_status = 'published'` and `next_review_due` is null or in the future (Lagos date). Anon cannot execute.
- Hourly job `private.learning_hide_overdue_course_lessons()` moves a course lesson that passed `next_review_due` back to `clinical_review` with a status-history note, so the older feed, library and the AI Coach retrieval also stop serving it. It touches only programme-linked lessons. The rest of the library keeps today's `review_due` behaviour (OQ filed).
- Events `lesson.completed` and `course.completed` emitted from a trigger on `health_education_progress` when a lesson reaches `understood` or `seen` for the first time and when the last lesson of a programme completes (S10 bus). Payload has codes and counts only, never a reading.
- Seed (generated from `packages/i18n/src/bpc-course.ts`, drift-tested): programme `bp_care_course`, modules 1 to 14 for BPC-01 to BPC-14, **all lessons `draft`**, so none is visible until the CMO moves them through clinical review. The programme row stays **inactive for good** (found while building: the older programme functions check only that flag and would serve drafts, OQ-301); `learning_course()` does not read it. BPC-15 (pregnancy) is Release 3 and not seeded. No reviewer name, no `clinician_reviewed`, no approval is invented.
- Audio manifest: BPC-01 to BPC-14 and BRE-01 added by extending `scripts/audio/import-production-list.py` (long-form tables 7.1 and 7.6): group `BPC`/`BRE`, `on_demand`, clinical true, not recorded. Script hash is the hash of the lesson text, so an edit invalidates a recording.

No new table, so no new RLS surface beyond the function; a DB proof covers the function (gating, language, held Pidgin, anon refused, review-due hide) with a sabotage check.

## 4. Course content rules

- 14 lessons, one per brief in the production list, 3 to 5 minutes at about 130 words a minute (so 390 to 650 words), plain English first, grade 8 or lower.
- Every lesson ends with one `next_action` and one teach-back question (`knowledge_check`, never pass or fail).
- No dose, no named medicine, no numeric target, no claim about a herb being good or bad. Medicines, side effects, salt/potassium cautions, red flags and thresholds are wording the CMO must sign. Lessons point to "your care team" and, for warning signs, to the existing emergency guidance.
- Pidgin: written for tone, myths and everyday action (BPC-01, 03 lessons without thresholds, 07, 08, 09, 10, 11, 14) and marked `needs_native_review`. BPC-02 (numbers), 04, 05, 06, 12, 13 are held in English.
- A build-time lint (`readability.ts`): words per sentence, estimated minutes from word count, banned words, em dashes, forbidden claims ("cure", "your doctor"), and a numeric-threshold detector that fails any lesson not on the signed-wording list.

## 5. Breathing exercise BRE-01

- Pure model in `packages/shared/src/breathing.ts`: `buildSession(config)` and `stateAt(config, elapsedMs)` return phase (`in` or `out`), seconds left, cycle count, finished. No timers inside.
- Values are PROPOSED (`breathing.bre01`, owner CMO): in 4 s, out 6 s, 3 minutes, 1 minute short version, gentler option. Not hard-coded; the registry scan test stays green. Pace is about six breaths a minute, with the longer exhale.
- Spec says BRE-01 is the Stage 1 exercise; the production list names BRE-01 "Three minute calm" and the BP-specific one BRE-03 (Release 2). Built as the production list's BRE-01 with a config that BRE-03 can reuse (OQ filed).
- Screens: mobile `breathing-screen.tsx`, web `/patient/breathing`. Safety card before first use (stop if dizzy, tingling, chest pain, new breathlessness; ask your care team first with lung disease, heart rhythm problems or pregnancy complications; keep taking your medicines and measuring as agreed). Stop button always visible. Silent visual pacer (circle or bar), text cue in the chosen language, haptics optional and off by default, audio optional and only if BRE-01 is recorded and signed. Reduced motion shows a bar that steps instead of animating. Never says it lowers BP; never asks for a reading.
- Works offline; completion is local and written to progress on next sync. Nothing here touches triage.

## 6. Screens

- Mobile Learn gets a "Blood pressure course" card (resume, day x of 14 as days you did something, no loss framing), a lesson screen (transcript always shown, audio button when the clip is playable per S32, text fallback and a quiet logged issue when not, speed 0.75/1/1.25, no autoplay), the teach-back question, the one next action, "was this clear?" (existing feedback), and the reviewer credit only from a real record.
- Web: the existing programme view already renders modules; add `next_action`, audio clip and the same credit rule.

## 7. i18n

New keys for course, lesson, breathing and safety card in `en.ts` and `pcm.ts` (parity test already fails on a missing key). A `held-in-english` ledger test lists every key whose Pidgin equals English; a new such key fails the build unless it is on the ledger with a reason. That is the honest meaning of "no untranslated keys".

## 8. Understandability test build

- Gate 1 (automatic): readability lint above on every lesson, both languages where Pidgin exists.
- Gate 2 (manual, kit committed): PEMAT and Clear Communication Index scoring sheets and the 10 to 15 person protocol with the pass rule (80 percent recall of message and action, zero unsafe misunderstandings), interviewer-read items, English and Pidgin, one non-Lagos site, in `docs/research/s33-understandability/`.
- Gate 3 (in app): one-tap clarity and teach-back first-try correctness, aggregate only through the existing analytics RPC. A test run uses `is_test` accounts (INV-13) so it never enters metrics.
- Not run: no participant has seen anything. "Ready" means the kit and build exist.

## 9. Safety rules and invariants

INV-01 untouched (no triage code, no model). INV-04 and results are not involved. INV-06: emergency guidance stays bundled; the urgent-care lesson links to it, never replaces it. INV-07: no notification names a condition; course reminders, if any later, use neutral templates. INV-13: test accounts excluded. INV-14: the course is hidden by default through draft status (the CMO publishes). Nothing is written to a patient record. No AI output in the path (lessons are human-written text; any AI drafting would need a named clinician reviewer).

## 10. Out of scope

Recording audio, native Pidgin review, CMO review of any lesson, BRE-02 to BRE-06, BPC-15, the full Learning Centre (Release 2), DMC and other courses.

## 11. What changed during the build (kept so the note matches the code)

- Lesson text is written with numbers as words ("one one two", "thirty minutes") because the same text becomes the recording script (Production List 3.5). Events carry the clip id (`BPC-04`), not the topic slug, so no event names a condition (INV-07); the DB proof found this.
- Pidgin drafts are not seeded (above). Audio: no playback speed control and no voice for BRE-01 yet, because the S32 engine port has neither a rate nor a position (OQ-304). BRE-01 is silent with optional haptics.
- BPC and BRE-01 are added to the S32 manifest by extending the importer (`scripts/audio/import-production-list.py`): 15 clips, group BPC or BRE, on demand, clinical, not recorded. Their scripts also enter `AUDIO_SCRIPTS` so the text fallback works the same way as every other clip.
- The web has the course and the breathing page; the audio buttons are app-only.
- Understandability tooling added: a scorer (`packages/i18n/src/understandability.ts`, command line in `scripts/learning/`) and the PROPOSED `learning.understandability_pass_rule`.
- Open questions OQ-300 to OQ-307.
