# S73 design note: pricing engine (Module 20)

Founder decisions: `docs/DECISIONS.md` S73-1, S72-1; OQ-324, OQ-321, OQ-08. Research: `docs/research/S73.md`. Invariants touched: INV-09, INV-13, INV-14, INV-15, INV-16.

## 1. What exists and is reused
`catalog_items`, `prices` (versioned, immutable, no overlap), `orders`, `payments`, `entitlements`, `create_order`, `record_order_payment`, `set_item_price`, `set_catalog_item_active` (S25, S26, S29c); `platform_modules.v5_checkout`; S10 `event_types`/`emit_domain_event`; S37 `go_live_guards`, `go_live_conditions`, `attest_go_live_condition`; S38e `sponsor_cohorts`/`profile_cohorts`; wellness points tables; `/patient/membership`, `/admin/catalogue`, `order-checkout`. Legacy `promo_codes` and the retired `subscription_plans` are not touched.

## 2. Data model (migration `20261007164447_s73_pricing_engine.sql`)
- `pricing_config` (versioned PROPOSED rules, one active row, mirrored as `pricing.rules` in the code registry, drift test).
- `catalog_items.audience` (`patient` | `institution`) and two new kinds: `institutional_protocol`, `concierge_coordinator`. Seeded OFF. A CHECK ties kind to audience.
- `price_books` (per sponsor organisation: hmo, corporate, ngo) and `price_book_entries` (rate per covered life, sponsor share percent, effective-dated, exclusion constraint, immutable).
- `discount_codes`, `discount_redemptions` (order-linked: reserved, redeemed, released), `discount_code_attempts` (guess limit).
- `orders` gains the pricing decision: `list_amount_kobo`, `sponsor_share_kobo`, `discount_code_id`, `discount_kobo`, `points_applied`, `points_reduction_kobo`, `price_book_entry_id`, `pricing_rules_version`, `quote`; all immutable afterwards, plus an arithmetic CHECK.
- No new table has a grant to `authenticated` or `anon`; staff use audited security-definer functions.

## 3. The quote
`private.price_quote_calc()` is the only place a price is decided. Order of rules: list price, institutional price book (via the beneficiary's active sponsor cohort), hardship (seam), sponsor coverage, discount code (one per order), points. Each step works on what the buyer would still pay. Tarragon-funded reductions (book, hardship, code, points) never take the buyer plus sponsor below the third-party cost (components `clinician_fee`, `partner_fee`) and never leave the buyer under `min_payable_kobo`; rounding is down; integer kobo throughout. It returns every line with an i18n label key and a running amount.
`public.price_quote()` is the buyer-facing wrapper (records failed code tries, hides row ids). `create_order()` calls the same calc, stores its result, and refuses (`quote_changed`) if the caller sent a total that differs. `create_order` was dropped and re-created with three defaulted parameters (one signature only, avoiding the 42725 overload ambiguity). Edge wrapper `price-quote` is thin; `order-checkout` passes the code, points wish and shown total.

## 4. Events
`price.changed` v1 (required keys scope, catalog_item_code, price_id) registered; emitted by `set_item_price` (scope list) and `admin_set_price_book_entry` (scope price_book). Ids and amounts only.

## 5. Subscriptions (S73-1)
No `subscription_plans` rebuild. Enabling the Membership: `set_catalog_item_active` (admin only, reason, audit row) now also requires the new go-live guard `membership_billing_enabled` (conditions: price set, checkout open, Paystack plan codes disabled and refund path tested as attestations). The quote refuses a real patient the Membership while the guard is off (test patients pass, S37 rule). The concierge item has its own CMO guard. No renewal column exists anywhere (proved).

## 6. Screens
`/patient/membership`: quote lines, discount code entry, "See what is included"; `/patient/membership/[code]`: standalone what-is-included page (same quote as checkout); `/admin/catalogue`: audience badge, guard status, plain error for a closed guard. Strings in `packages/i18n` (English only, D-14), no em dashes.

## 7. Safety rules
Third-party cost floor; points affect Tarragon's fee only, are OFF until the founder signs `pricing.rules`, are reserved across open orders, spent once on payment, and never become a balance (INV-09); an unusable code never says why; failed tries are kept (the order function returns the error instead of raising); sponsor-covered orders are refused until S71 can bill the sponsor (`sponsor_billing_not_open`).

## 8. Not built (see OQ-328 to OQ-333)
Sponsor billing and entitlement (S71), hardship grants (S72), removal of the kobo conversion in `redeem_wellness_points`, mobile what-is-included screen, admin screens for price books and codes (functions exist, tested), public (logged-out) what-is-included page.
