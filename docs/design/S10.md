# S10 Design: Event bus and outbox processor

Spec Section 5. Depends on S05 (closed). Invariants touched: INV-05 (a red event must not wait for a pull; the urgent path), INV-10 (events carry ids only; handlers read through audited paths), INV-13 (`is_test` carried on every event), INV-16 (event versions).

## What already exists
- No `domain_events`, outbox or subscriber table. The mobile `outbox` (S06) is the phone's write queue and is unrelated.
- `integration_outbound_events` (partner webhooks, claim with `SKIP LOCKED`, backoff, dead letter, cron every minute) is the closest pattern. It is partner-facing and stays as is; the bus can later feed it through a subscriber.
- pg_cron 1.6.4 (supports "15 seconds") and pg_net are live; Vault secrets `project_url` and `edge_function_publishable_key` are the existing wiring for cron-to-edge calls.
- Edge functions are self-contained; shared code goes in `supabase/functions/_shared/`.

## Data model (all data, so new types and subscribers need no schema change, Section 18)
- `event_types` (type, description, owner section, `is_urgent`, `current_version`, `is_active`) and `event_type_versions` (type, version, required payload keys, deprecated_at). Seeded with the 13 spec events.
- `domain_events` (append only): id, type, version, organisation_id, patient_id, aggregate type and id, payload (ids and neutral facts, 8 KB cap), priority `normal|urgent`, idempotency key (unique per type), causation_id, `is_test`, occurred_at.
- `event_subscribers` (key, event type, handler key, min and max version, active). A subscriber is a row; its code is a handler registered by `handler_key` in the processor.
- `domain_event_deliveries` (one per event and subscriber, unique): status `pending|processing|done|dead`, attempts, `next_attempt_at`, `locked_until`, `lease_token`, last error, replay count. An AFTER INSERT trigger on `domain_events` creates them in the producer's transaction.
- `event_effects` (effect key primary key): handlers record a side effect once; a repeat or replay sees it and skips.
- `event_bus_config` (versioned, one active; PROPOSED values): batch 50, lease 60 s, max attempts 8, backoff base 15 s doubling to a 900 s cap with up to 20 percent jitter. Mirrored in the code registry as `events.bus_rules`.

## Behaviour
- `private.emit_domain_event(...)` (used by triggers and functions) and `public.emit_domain_event(...)` (service role only) validate the type, version and required keys, insert, and return the existing id on a repeated idempotency key.
- `public.claim_event_deliveries(limit, urgent_only)`: `FOR UPDATE SKIP LOCKED`, takes pending rows due now and processing rows whose lease expired, sets lease and token, counts the attempt, returns urgent events first.
- `complete_event_delivery` and `fail_event_delivery` require the lease token. Fail applies backoff, or goes to `dead` at max attempts or when marked permanent. `record_event_effect(key)` returns true the first time only; `release_event_effect(key)` undoes it when the side effect itself threw (so the retry runs it again).
- `replay_event_delivery` and `requeue_dead_deliveries` are admin only and write `audit_log`. `event_bus_health()` (admin only) reports counts, oldest pending age and dead letters.
- Urgent events: a trigger makes a best-effort `pg_net` call to `process-events` with `urgent_only`. It is wrapped so it can never fail the producer. Cron every 15 seconds is the guaranteed path.
- Edge function `process-events` is a thin shell over `_shared/event-bus/dispatch.ts` (pure, injected ports, 100 percent covered from `packages/events`). A handler that throws is retried; one that throws `PermanentHandlerError` or has no registered handler goes dead; a handler returning `skip` completes.

## Safety rules
- RLS on every table. Patients and clinicians have no access. Admin may read events and deliveries for investigation. All claim, complete, fail and emit RPCs are service role only; `anon` and `PUBLIC` have no execute.
- Events are append only (a trigger refuses UPDATE and DELETE).
- A dead delivery is never silent: it stays in `dead`, is counted in `event_bus_health()`, and the processor logs it. A dashboard tile and paging for a dead urgent delivery belong to S19 and S37 (recorded as follow-up).
- No handlers for the spec subscribers are written here; S11 onward register them. S10 ships the framework and one built-in handler (`bus.noop`) used by the tests.

## Screens
None. Admin reads go through `event_bus_health()`; a console tile is a follow-up for S37.

## Tests
DB proof (`s10_event_bus.sql`): exactly once under two claimers, duplicate emission, lease expiry recovery, stale-token completion refused, backoff and dead letter, replay, version range, RLS and execute grants, append-only, sabotage. Jest (`packages/events`): dispatch loop, 100 percent. The loop's source is `supabase/functions/_shared/event-bus/dispatch.ts` (edge functions cannot import workspace packages); `packages/events/src/dispatch.ts` is a copy made by `pnpm sync` and a test fails if they differ.

Not proved by a test: real two-connection contention on `SKIP LOCKED` (no local database in this session; the lease proof is sequential). Recorded as a follow-up.
