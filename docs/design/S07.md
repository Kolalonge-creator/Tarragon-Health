## 2. Data model

**Server (one migration, to be checked against live `list_migrations` before applying, never hand-typed):**
- `care_tasks`: add `kind text` with a CHECK (`log_bp`, `take_medicine`, `book_test`, `join_consultation`, `read_lesson`; null allowed for existing rows) and `source_event_id uuid null`. Both nullable, so no data conversion step and no existing row changes meaning.
- `public.patient_tasks` view, `security_invoker = true` (a view over RLS runs as its owner otherwise), exposing `id, patient_id, kind, due_at, state, source_event_id` where `state` maps the eight `care_task_status` values to the spec's states. Explicit grant to `authenticated`, none to `anon`.
- `take_medicine` is not stored: S08 computes pending dose slots from `schedule_times` (OQ-56). The Today list merges stored tasks and computed slots on the device.
- BP payload gains optional `pulse`, `symptoms[]`, `body_position`. Recommended landing: pulse as a companion `pulse` vitals row and symptoms through the existing `symptoms` table, each with its own `client_id`. The device writes them in one SQLite transaction, but S06's flush sends one row at a time and a refusal marks only that row, so the rows need a shared `group_id` in the outbox payload and one rule: a group counts as synced only when every member has synced, a partially synced group shows the "not yet reached your care team" notice for the unsent member (a ticked red-flag symptom must never be lost behind an accepted BP), and a rejected member is surfaced with its support code, never dropped. This keeps the existing pulse and symptom red-flag triggers working instead of hiding data in a JSON column. To confirm against the live schema before building.
- Proof script in `packages/db/tests/`, registered in `ci.manifest`: patient reads own task only, cannot insert or update, another patient and `anon` read nothing, plus a sabotage step. `private.roll_recurring_care_task()` re-inserts the next occurrence with an explicit column list (`20260828222447_care_tasks.sql`), so the migration must also replace it to copy `kind` (otherwise a recurring BP task loses its kind after the first occurrence and drops off Today with no error), and the proof must roll a recurring task and assert `kind` survives. Other trigger and RPC behaviour on `care_tasks` is untouched.

**Device (`tarragon-offline.db`, new tables via the existing user_version migration):**
- `local_tasks` (mirror of the patient's own tasks, cursor pull like S06).
- `reminders(id, kind, label_key, times, days, active)` and `reminder_instances(id, reminder_id, due_local_date, due_at_utc, status scheduled|taken|skipped|snoozed|missed, acted_at_utc)`.
- `streak_events(id, local_date, kind done|freeze|excused, created_at_utc)` authoritative; `streak_state` is a cache derived from it.
- Every new event row: `*_at_utc`, `tz` (Africa/Lagos stored as IANA), `local_date` computed at write, `clock_skew_ms` when known. Today and streaks bucket on `local_date`.

## 3. Rules

- **Save first**: a reading is durable in the outbox before any network call (S06). The result message reads the device classification and says plainly when the care team has not yet received it.
- **Plausibility**: pure function with limits in versioned configuration; defaults equal today's live behaviour (60-260, 30-160, systolic above diastolic). A blocked high value adds a safety line pointing to the existing emergency content (OQ-66, option a). The wording is NOT final: it needs Chief Medical Officer review, the house voice (no fear-based urgency) and native Pidgin review before it ships, and it must not read as an emergency alarm for an obvious typo such as 2700.
- **Triage hook**: `TriageEvaluator.evaluate(reading, symptoms) -> { level, ruleVersion, guidanceKey }`. v1 wraps `classifyVitalOffline` and records the threshold version. No new rules, no language model (INV-01). S11/S12 replace the implementation.
- **Red-flag symptom ticked**: shows the existing emergency guidance on device (INV-06), same path as the symptom screen. This reuses existing behaviour and does not grade BP. To verify in the build that the symptom path applies as described.
- **Averages**: shown only above the averaging gate (PROPOSED: 3 readings over 3 days, or 4 over 2); otherwise "not enough readings yet". Trends read the resolved effective time (S06-1), never raw `taken_at`.
- **Reminders**: scheduled as a rolling window (iOS 64 cap), channel created before scheduling, reconciled on launch and foreground. "Overdue" comes from the schedule, not notification delivery. Copy is generic and keyed; no condition, reading or medicine name (INV-07). A reminder change for a prescribed medicine does not queue offline (S06-2).
- **Streaks**: pure function over `local_date`; weekly "days done" with a best-ever figure and a grace window; a freeze is earned and shown as a freeze, never a reading; a high reading counts; patient can turn it off; never a red zero or "you missed a day" copy.
- **Edit history**: append-only; no destructive edit of a synced reading; correction through `data_correction_requests`; erasable on account deletion (NDPA).
- **Copy**: all new strings in `packages/i18n` en and pcm; no em dashes; "your care team", never "your doctor"; Pidgin strings flagged for native review (OQ-61 pattern). Existing hard-coded English on these screens is moved when the screen is touched; untouched legacy strings stay in the copy-lint baseline.

## 4. Screens

1. **Today** (Home tab, extends the existing kit screen): the current hero and next-step card stay; adds a due list (tasks plus computed dose slots plus reminders), quick-log button, small streak card (hideable), sync banner. Reads one local query; remote refresh after first paint.
2. **Log blood pressure**: two big numbers, optional pulse, position, symptoms checklist, "Before you measure" technique sheet (HLP-003), result message after save.
3. **Trends**: the existing 7 and 30 day `TrendChart` on the Vitals screen, extended with the personal target band, summary sentence, "show as list" toggle and averages with counts.
4. **Reminders**: list, add, edit, quiet hours, battery-settings help step for Android.
5. **History**: own readings with correction status and "ask for a correction".

## 5. Events

No new domain events. The server already emits the reading event consumed by S11. S07 adds client-side diagnostics rows through `sync-diagnostics` only. The triage hook is the single seam S11 and S12 attach to.

## 6. Tests and budgets

- Pure-logic Jest tests (testMatch is `src/**/*.test.ts` only, so no component rendering): plausibility, averaging gate, trend aggregation and gaps, streak function across Lagos, New York and London with clock skew, reminder state machine and rolling window, the offline transaction for BP plus pulse plus symptoms, outbox replay of the new payload.
- DB proof for `patient_tasks` and the new columns, with a sabotage step.
- Offline logging: airplane-mode path covered by outbox tests; Maestro flow is an iOS-only scaffold today, so a device run is a follow-up.
- Budgets: extend `lib/offline-budget.ts` with tap-to-saved (starting target about 100 ms p95 on the stand-in, to be set from measurement). Cold start and logging speed on a real phone are **not measured** (Design Phase 1 also lists Android device, screen reader and large-text checks as not done) and will be reported as such. Spec D.1 (3 s, 40 MB) is stated against a 2 GB class; DG-1 raised the floor to 4 GB and D.1 is not yet updated.

## 7. Out of scope

Triage rules and paging (S11, S12); audio clips (S32); voice logging (interface only); wearable readiness; medicine schedules beyond reading the S08 slots; BLE (separate path, untouched); starting any new native build (S07 adds no native dependency).

## 8. The three recommendations (details in `docs/OPEN-QUESTIONS.md`)

- **OQ-65** build `patient_tasks` as a view over `care_tasks`, not a new table.
- **OQ-66** keep the live 60-260 / 30-160 plausibility limits (signed pathway TH-CP-HTN-001 section 5.4); mark the spec's 300/200 superseded; add a safety line to the blocked-value message.
- **OQ-67** leave BP grading bands untouched in S07; S12 aligns them to the spec through versioned configuration signed by the Chief Medical Officer.
