# S98 design note: the preventive engine issues the test request

Founder requirement 2026-10-27: when a patient is due a specific test they are alerted, download the PDF request, take it to any lab, upload the result; the request must be issued automatically. Invariants in play: INV-03 (uploaded document hidden from patient until reviewed), INV-04 (sensitive tests), INV-07 (ids only in events and generic inbox text), INV-10/12 (tied staff reads), INV-14 (guards off).

## Hop-by-hop audit (live project checked read-only 2026-10-27)
| Hop | Status |
|---|---|
| Due detection (`run_screening_scheduler`, S45) | OFF-BY-GUARD (`screening_scheduler_enabled` off) and UNSIGNED-CONFIG (rule sets v1 to v3 unsigned); 0 `screening_schedules` rows live |
| Alert (`queue_screening_reminders`: upcoming, due, overdue, escalated; `patient_reminder_channel` + in-app) | WORKS |
| Request created with no click | MISSING (fixed here, behind a new guard) |
| PDF from the alert | PARTLY: an order insert already emails the PDF (`lab_order_requested_patient`, order_id in payload); reminders had no link to the request (fixed) |
| Take to any lab | WORKS (`/api/patient/lab-order/[id]/request`, mobile route) |
| Upload tied to the request | WORKS (`lab_result_documents.lab_order_id`; web `PatientResultUpload`, mobile Labs screen); not shown on the calendar (fixed) |
| Awaiting result / result received | `awaiting_result` care gap WORKS (21 days, no document). "Result received" was MISSING: schedule stayed booked and reminders kept chasing (fixed) |
| Appears in tests and record | Document is kept and read into a draft by the governed reader (OQ-BUNDLE-1); structured values are NOT created from a patient upload (no OCR built) |
| Doctor can see it | WORKS (`staff_may_read`, tied, results inbox); no unverified marker (badge added) |
| Care-gap closure | WORKS only after a clinician records the result or the patient confirms done (OQ-S98-4) |
| Sensitive tests | Not auto-issued. Existing manual path unchanged; `home_kit_sensitive_enabled` still governs home collection |

## Why a nightly sweep and not a `screening.due` subscriber
`enforce_lab_order_origin` refuses a self-service order before the schedule's due date, but the scheduler creates rows up to 30 days early and bus handlers are TS workers. A sweep keyed on the schedule rows is idempotent, needs no worker, and reuses the existing patient-initiated due-screening path (no new origin, no doctor, nothing billed).

## Human-owned
CMO signs a screening rule set; a founder or CMO switches `screening_scheduler_enabled` and then `screening_request_automation_enabled`; redeploy `send-pending-notifications` if the email wording should mention the request. No lab partner contract is needed (self-arranged).
