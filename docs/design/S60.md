# S60 design note: Module 12, symptom checker safety half (spec lines 1405 to 1440, functions 12.8 to 12.13)

Branch `s55-60/s60-symptom-safety`, stacked on `s55-60/f1-fix-first`. The checker stays behind go-live guard `symptom_checker_enabled` (OFF). Nothing is applied to production.

## 1. What already existed (reused, not rebuilt)
`packages/symptom-triage-engine` (deterministic interpreter, signed v1 pathways headache, chest pain, breathlessness), `symptom_triage_assessments` with its escalation trigger and guard trigger (F1), `triage_protocols`, `escalation_slas` (v7 lacks `symptom_triage`; unsigned draft from F1), `clinical_tasks` with the existing `symptom_review` task type (S16), the S10 outbox, the S37 guard dashboard and `attest_go_live_condition`, `private.clinician_has_patient_access`, `private.audit_chart_read`, the F1 guard action, `runBestEffort`, the proposed-config registry, `packages/i18n`.

## 2. Data model (three migrations, 20261007130417, 20261007131052, 20261007131744)
- `symptom_reviews` (spec 12.10): one per assessment; status requested or completed; `source`, `recorded_by`; stated time copied from the active signed SLA (null when none); clinician side (`clinician_id`, `final_diagnosis_code` ICD-10 shape, `clinician_category`, `agrees`, `patient_message`, `internal_note`, `reviewed_at`); `protocol_version` (INV-16). No staff policy; patient reads only status, times and the plain message by column grant. Completed rows cannot be changed or deleted.
- `symptom_accuracy_config` (versioned) and `symptom_accuracy_reports` (aggregate JSON cells, `is_baseline`, `includes_test_accounts`, `publishable` CHECK false, immutable).
- `regulatory_positions` (append-only): topic, text, classification, counsel, date, document reference, `attached_by`.
- `symptom_check.completed` and `symptom_review.completed` registered on the outbox; ids only (INV-07).

## 3. Safety rules (the core of this session)
- Fail toward escalation (12.8): `runTriageFailSafe` runs the bundled red-flag floor first and independently, bounds the engine with a timeout, and treats an error, a timeout, a malformed answer or a missing protocol as the more urgent of the (degraded) floor and `urgent` with human review, never reassurance. The floor can only raise the engine's answer. The web action returns the result even when the row cannot be recorded, reports the failure, and raises the emergency event directly in that one case.
- On-device (INV-06): the floor is a frozen copy of the signed rules, parity-tested against the database seed fixture; the wizard evaluates it in the browser before any server call and shows an emergency at once; `apps/mobile/src/lib/symptom-red-flags.ts` exposes the same floor. No mobile screen is built (guard off, wording needs CMO sign-off).
- Degraded values are PROPOSED config `symptom.degraded_mode` (severity floors ignored, unclassifiable is urgent, 3 s timeout).
- Prevalence (12.11): PROPOSED config `symptom.risk_tightening`, entries can only name a minimum category; all shipped entries are unsigned drafts and inert; a property test shows no entry can lower a category; schema is strict.
- Label (12.9): one `NotADiagnosis` component and one catalogue entry, with a scan test.
- Guard: closed means closed. The new fail-safe never answers while the guard is off; `request_symptom_review` refuses with 42501 while closed.

## 4. Review (12.10) and who sees what (INV-10, INV-12)
Patient asks via `request_symptom_review` (idempotent, creates the `symptom_review` task, loud on failure). Clinicians list via `list_my_symptom_reviews` (patient number and times only), read via `read_symptom_review_audited` (tie via `can_staff_read_clinical`, every read and every refusal audited), complete via `complete_symptom_review` (medical officer and above, tie required, "agrees" cannot contradict the category). A care coordinator is refused. The stated time comes only from `escalation_slas` and is absent today.

## 5. Accuracy audit (12.12)
Monthly pg_cron job (2nd, 03:30 UTC) for organisations with completed non-test reviews in the previous month; also callable by an admin or the CMO for a finished month. Cells: overall, age band, sex, region; matched, under-triaged (unsafe), over-triaged; Wilson intervals; suppression below the configured minimum plus complementary suppression. First report is the baseline. Never publishable.

## 6. Regulatory position and guard wiring (12.13)
`record_regulatory_position` (admin or CMO). `attest_go_live_condition` now refuses `nafdac_position_recorded` without a determined position on record and `accuracy_baseline_recorded` without a baseline report; the dashboard condition shows what the record says. The other two attestations stay plain. The guard is not switched on by any of this.

## 7. Screens
Patient wizard (safety checklist, on-device result, degraded and not-saved states, review request with stated time, shared label); clinician `/clinician/symptom-reviews`; admin `/admin/symptom-safety` and CMO `/clinician/symptom-safety`. Admin-search entries and nav items added; strings under `symptom.*` in `packages/i18n` (English only, see OQ-S60-06).

## 8. Not built, and why
Possible causes, licensed or mock differential (founder decision), photo upload and the six-level urgency map (S59), Pidgin (repository is English-only), a mobile checker screen, notifications to the patient on review completion (a neutral template needs content approval; the in-app state shows it), signing the SLA, protocols or prevalence entries, helpline numbers (none shipped).
