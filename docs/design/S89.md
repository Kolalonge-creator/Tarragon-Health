## Invariants held

- No new AI call site, no `ai_systems` row, no `runtime_governed` change. AI-017 stays OFF and AI-014 is untouched.
- INV-11: nothing writes AI text to the record. `AiDraftBlock` hands text back to a caller; the scribe "Use in note" still only fills the note form and the clinician still signs there.
- INV-10/12: the brief and the checker drop any row matching a sensitive category (reproductive health, mental health, sensitive positive) unless access for that category is confirmed. Access defaults to denied. The number of dropped rows is never shown. Today the pre-visit summary confirms only mental-health access (from the existing refused-read signal); reproductive and sensitive-positive rows stay out (OQ-S89-02).
- "Not enough in the record" is the only output when the record is thin (below the minimum count, or no rows). A refused read shows "Not available to you", never "none".
- The checker returns `blocksSigning: false` as a literal type and its panel renders no control. It decides nothing.
- The attestation is a gate on the browser-side use of a draft. `reviewed_by` / `reviewed_at` still come only from the existing server-side finalise and review-record path (null-gated); this component never supplies them.

## Shadow measurement design (not yet run; nothing here creates data)

Goal: Tarragon's own measured minutes saved per review, never a vendor figure (acceptable-use 4.1).

1. Unit: one review task (one pre-visit read, or one note, or one reply). Each logs: task type, clinician id (server-derived), start and end instants, whether the copilot surface was available, and the edit-rate figures from `ai-spans.ts` (`aiWords`, `changedWords`, `editRate`, `leftUnedited`).
2. Arms: within-clinician alternation by week (copilot surfaces on, then off), so each clinician is their own control. Do not randomise across patients; case mix differs.
3. Minutes per review: the median and interquartile range per arm per task type, with the number of reviews. Report the difference only when each arm has at least the shadow-mode floor from 4.1 (at least 8 weeks and at least 200 reviewed drafts, whichever is later).
4. Safety side: `leftUnedited` rate (rubber-stamp alarm), edit rate by section, and every draft that would have been unsafe if signed, logged as an AI safety incident, which pauses go-live.
5. Where it is stored: needs a table (the existing `record_scribe_review` takes per-section outcomes and a hash only). Not built; see OQ-S89-01.
6. The CMO reviews the edit rate and every unsafe-draft report before go-live.

## Evaluation set outline (for the CMO and a reviewer to build; nothing seeded)

- Pre-visit brief (deterministic): 40 synthetic records covering thin data, dense data, conflicting readings, refused reads, sensitive rows with and without access. Pass: every line's numbers equal a hand count from the record; every cited source exists; zero sensitive rows without access.
- Omission checker: 60 note and record pairs with a known planted issue each (allergy clash, missed abnormal result, missing interval, missed medicine) plus 30 clean pairs. Report flag recall and false-flag rate per rule. Flags only, so the bar is usefulness, not a decision threshold.
- AI-drafted text (when a model is enabled later): omission and invention checked against transcripts, the 2026 JMIR error classes as the rubric (omission, hallucination, serious-risk error).
- All sets written, run and signed by a human. This session creates no evaluation run, prompt approval or knowledge-source approval.
