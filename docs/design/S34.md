# S34 design note: low-data mode, accessibility, performance, app size

Status: prep only (research, reconciliation, plan). No code yet. Blocked on S32 (PR 961) and S33 merging.

## Already exists (extend, do not rebuild)
- `profiles.low_data_mode` boolean (S02 migration). Nothing in mobile reads it yet.
- S32 `packages/audio` bundle planner already refuses downloads in low-data mode; HLP-038 explains the mode.
- `apps/mobile/src/lib/offline-budget.ts` and its tests: pull sizes and the 1 MB daily stand-in.
- Design kit: `MIN_TARGET = 44`, `MAX_FONT_SCALE = 2`, `contrastRatio()` with `tokens.test.ts` enforcing contrast, `text-scaling.test.ts`.
- Dark mode and Sora and Inter fonts (DG-2, DG-3). The app is English only since #984.

## Conflict, recorded as OQ-252
Spec D.1 and DG-1 supersede the 40 MB, 3 second, 2 GB targets (floor is now 4 GB Android 10+). The S34 prompt still says 40 MB on a 2 GB phone. Founder decision 2026-10-07: no targets. The plan tracks size and start time in a report and fails nothing on them.

## Plan
1. **Low-data setting**: a `useLowData()` hook reading the profile flag (local mirror, works offline), a switch in the profile menu, auto-suggest when on mobile data. Gates: no auto images or audio, video on tap, Wi-Fi-only downloads. Emergency content ignores it.
2. **Accessibility**: kit-level labels, roles and states; a scan test that fails on a touchable with no `accessibilityLabel` or visible text; 48 point check on the dose and reading buttons (Button already has 48); status always word plus icon; clinical text at 7 to 1; reading numbers spoken with units; reduce-motion respected; font scale test at 200 percent for the reading card and dose card.
3. **Performance and size**: size report script (APK and AAB per ABI) with a PROPOSED budget in `proposed-config`; native-module audit; R8 and ABI settings through a config plugin (needs the next native build, DG-6); cold-start and logging-speed timings recorded on a device lab run, never claimed from Jest.
4. **Data model**: none new. No new table, so no RLS test; the existing profile column is owner-editable already.
5. **Safety rules**: INV-06 (emergency works offline) is untouched; low-data never hides red-flag guidance; no AI in any path.

## Out of scope until a device exists
Cold start, installed size and memory stay "not measured" (as S06 states).

## Built (2026-10-07, branch s34b/low-data-a11y-build)
- **Low-data setting**: the on-phone preference and pull budget from PR 979 (carried as the same diff so the two merge cleanly), plus `subscribeLowData`/`isLowDataActive` in `offline-budget.ts` and `useLowData()` (`use-low-data.ts`) so a screen re-renders when the switch flips.
- **Media policy**: `media-policy.ts`, one pure function every screen asks. Audio and video never start by themselves; images wait for a tap in low-data mode; downloads need Wi-Fi unless mobile data was allowed; an unknown connection counts as not Wi-Fi; emergency content is never gated (INV-06). 5 tests.
- **No call site yet**: main-dev has no remote image or audio loads (the images are bundled logos and the patient's own photos). The audio player in S32b (PR 980) is the first consumer and must call `mediaDecision`. Wi-Fi detection needs `@react-native-community/netinfo` or `expo-network`, a native module, so it waits for the DG-6 native build; until then screens pass `connection: "unknown"`.
- **Accessibility**: 16 touchables had no screen-reader role; all now have one (links, chip selected state, labelled close buttons, `Remove 08:00`, `Rate 3 out of 5`). The 26 point rating buttons now have a 44 point hit area. `a11y-scan.test.ts` fails on any new touchable without a role, any icon-only touchable without a label, any `allowFontScaling={false}`, and any small fixed-size touchable without hit padding. Sabotage check done: removing one label fails the scan.
- **Size and start report**: `apps/mobile/scripts/size-report.mjs` writes `build-reports/size-report.json`, always exits 0 (OQ-252: tracked, never a gate).
- **Not done**: the server flag `profiles.low_data_mode` is not written from the app (the preference is per phone and lives in secure storage); font scale at 200 percent on the reading and dose cards, reduce-motion behaviour, screen-reader reading order, cold start and logging speed all need a device (listed in `docs/STAGE-1-SIGNOFF.md`).
