# S85 design note: end-to-end journeys (D.7)

Status: audit half. Written 2026-10-07. Full tables are in `docs/audit-D7-journeys.md`.

## Scope
Turn the four D.7.3 journeys into automated tests across modules built so far, and verify the D.7.2 event map against the
real bus. No new tables, no migrations, no new events in this half. Nothing runs against the live project.

## What already exists (reused, not rebuilt)
- Event bus (S10): `event_types`, `domain_events`, `event_subscribers`, `process-events`. Six subscribers only.
- Playwright suite `apps/web/e2e-browser` with a local-stack guard (`global-setup.ts`) and `helpers/supabase-admin.ts`.
- Maestro flows in `apps/mobile/.maestro/flows` (Android offline pattern in `medicines-add-remind-take-offline.yaml`).
- DB proofs in `packages/db/tests` for triage (S12), paging (S19), Care Circle (S29), lab release (S27), prescriptions
  (S24), pharmacy (S28), outcomes (S38). Each journey step with a DB proof is linked from the audit tables.

## Data model
No change. Journey tests create their own is_test patient and organisation through `createJourneyPatient` and delete them in
`afterAll`. Rows carry `is_test` (INV-13); the bus stamps `is_test` from the patient, which journey 2 asserts.

## Events asserted
`observation.recorded` (journey 2 step 1), `triage.graded` indirectly through `triage_events` (step 3), `pages` rows (step 4).
Event-map findings F-3, F-10, F-11 are decisions for the founder: emit the dead names, retire them, or accept the old bus.

## Screens exercised
Web: `/login`, `/patient/vitals` (`vitals-form.tsx`), `/onboarding` (intent step). Mobile: Vitals, symptom sheet, emergency
guidance sheet, sync banner.

## Safety rules the tests check
- INV-01: grade comes from a versioned rule set row, no model in the path. Structural check only; F-8 recommends a repo scan.
- INV-05: a red, non-shadow grade creates a page row, not only a task. While the rule set is an unsigned draft (OQ-88) a
  shadow red must create NO page, and the spec asserts exactly that, so the test is correct before and after the CMO signs.
- INV-06: guidance with the radio off (Maestro, Android).
- INV-07: neutral notification wording; the helper constant exists, the assertion needs the Care Circle supporter helper.
- INV-13: all fixtures is_test. INV-16: rule set code and version recorded on every triage row.

## Environment needed to run
`supabase start` and `supabase db reset`; `NEXT_PUBLIC_SUPABASE_URL`, anon and service keys from `supabase status -o env`;
optionally `PROCESS_EVENTS_SECRET` with `supabase functions serve process-events` for the bus-driven steps; an Android emulator
or device for the Maestro flow. Paystack steps need an `sk_test` key, never a live key.

## Blocked, by cause
- Unbuilt modules: symptom checker S59/S60 (journey 3), employer console S79 (journey 4), Health Points S58, mood S56/S57,
  pregnancy S66 to S68, wearable events S70.
- Missing producers (spec gaps, not test gaps): follow-up booking after red, day-three check-in, care-pack offer,
  silence and dose events on the new bus.
- Helpers to build next: supporter (Care Circle) session, seeded clinician and rota (OQ-212), approved test rule set.
- External: no active pharmacy partner, Paystack test key, Android device.
