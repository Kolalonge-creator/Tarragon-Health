# S55 design note: Health Learning Centre (Module 9)

Branch `s55/health-learning-centre`. Research: `docs/research/S55.md`. Stage 1 gate (S40) is NOT closed; the founder said build everything and switch nothing on, so the creator programme ships dormant and every clinical sign-off is left to the CMO.

## Reconcile (what existed, reused)
`health_education_content` (status lifecycle, versions, review columns, drip week, audio_url), `health_education_progress`, programmes and modules, translations, feedback, embeddings, the weekly drip, the web and mobile library, the admin manager. S33 (live, PR #982 open) already added `audio_clip_id`, `next_action`, `learning_course`, the lesson and course events through the outbox, and the course gate. Reused, not rebuilt. D1: mapped onto live tables; `content_items` and `course_progress` are not created.

## Data model
- `health_education_content` gains `clinical_owner_id` (verified clinician link), `next_step_kind`, `next_step_target_code`, `series_tag`, `is_public`, `members_only`, `creator_id` (and `audio_clip_id`, `next_action` with `if not exists`, so replay works with or without S33).
- New `health_education_search_aliases` (9.3) and `creators` (9.7). New platform module `learning_creators` (dormant).
- New category value `when_to_seek_care`.
- `private.health_education_review_in_date()` is the one date rule (D4). `private.health_education_items()` derives every patient column once; library, feed, detail, programme detail, counts, search, this-week and offline re-check read it.

## Rules enforced in the database
Publish needs a next step (not for a row returning from review_due). Programme lessons are 1..5 minutes (module insert and content update). Public needs a review record and is never Members. Alias review is CMO only and an edit sends it back to draft. Creator content is Members-only, publishable only from approved or review_due, reviewer must be a different verified clinician, and it is hidden when the creator stops being verified. D4: out-of-date content is never returned by any patient or AI-retrieval path (NULL date fails open, justified in the migration header; the CMO can flip it in one place).

## Events
`lesson.completed` and `course.completed` come from S33's `health_education_progress` trigger (codes and counts only, INV-07). S55 adds none.

## Screens
Web: library search, review credit and sources, next-step footer, share buttons, FAQ and infographic views, Members lock, this-week card on Today, public page `/health-library/[code]`, admin editor fields, `/admin/settings/health-education/aliases` and `/creators`, `/clinician/learning-creator`, `/clinician/learning-governance` (CMO). Mobile: the same credit, footer and search, audio port with fallback, FAQ and infographic blocks, Downloads screen, this-week card on Today. Every new page has a search entry.

## Safety and go-live
No model call anywhere. No AI output enters a record. Nothing is marked reviewed or approved by this session. Guards: creator programme module off; aliases draft; content authored is draft. Audio engine is a port: the native module needs a new build and a `runtimeVersion` bump (OQ-201).
