# S45 design note: risk, screening calendar, packages (3.1 to 3.10)

Founder waiver for the S40 gate recorded 2026-10-07 (this session only). Invariants in play: INV-04, 07, 10, 12, 13, 14, 15, 16.

## 1. What exists (extended, not rebuilt)
- Questionnaire: `risk_questionnaire_configs` (versioned, CMO-signable) and `lib/rules/risk-scoring.ts`. Kept.
- `cv_risk_config` (lipid targets) and `cvd-risk-afro.ts` (labelled "not the official chart"). The AFRO estimate stays only as a fallback while the WHO guard is off.
- `screen_types` (global catalogue), `screening_schedules` (already has `declined`), `screening_completions`, `panel_bundles` (SYNLAB-priced), `lab_orders`, S27 `lab_results` release rules, S37 `go_live_guards`, S10 outbox.
- Gaps: no nightly scheduler (schedule rows come from app actions only); no `not_applicable`; rules not versioned or signed; no `risk_assessments`; no `screening_packages`.

## 2. Data model (migration `s45a` adds the enum value, `s45` the rest)
- `risk_instrument_versions`: code, version, config jsonb, `approved_by` (CMO) and `approved_at`, `is_active` only when signed. Seed `who_cvd_2019_wssa` v1 UNSIGNED with no coefficients. `sign_risk_instrument` refuses to sign while coefficients are absent.
- `risk_assessments`: `instrument_version_id NOT NULL` (INV-16), model, inputs, band low/high, tier, status (scored or a named not-scored reason), trigger, source, recorded_by, is_test. Insert only through the service-role `record_risk_assessment`; a patient reads their own; staff read through an audited, tie-checked function (INV-10, INV-12).
- `screening_rule_sets`: versioned, CMO-signable, seeded v1 as a verbatim copy of the live catalogue, unsigned. `screening_schedules` gains `rule_set_id`, `not_applicable_*`, `closed_reason_code`.
- `screening_packages`: code, `panel_bundle_id`, eligibility, `requires_positive_pathway`, `guard_key`, `name_status`.
- Events: `risk.assessed`, `risk.reassessment_due`, `screening.due` (ids only, INV-07).
- Guards (all off): `risk_instrument_who2019_enabled`, `screening_scheduler_enabled`, `hpv_dna_enabled`, `home_kit_sensitive_enabled`.

## 3. Logic
- `private.screening_due(patient, rule_set)` and `private.run_screening_scheduler()` (nightly pg_cron job `screening-scheduler`, same style as the S19 sweeps). It uses a signed active rule set only, and does nothing while the guard is off.
- `private.risk_reassessment_reasons(patient)`: yearly plus configured major changes.
- `set_screening_state(...)`: declined or not_applicable with a reason; later runs never re-create them.
- Trigger on `lab_orders`: a home-collected order whose bundle holds hiv, hep_b, hep_c, syphilis or chlamydia_gonorrhoea is refused unless the guard is on (test pair exempt). Live count of such orders: 0.
- WHO engine: pure TypeScript in `packages/clinical`, coefficients passed in from signed config. Refusals: age outside 40 to 74, known diabetes, established CVD, BP at or above 160/100, missing inputs, instrument off.

## 4. Screens and seams
Server action and loader for the assessment; the calendar form offers "not applicable"; a package list function for the S25 checkout. S46 seams: `risk_assessments` feeds the yearly report, schedule states feed pathway suppression, package contents feed hep B logic.

## 5. Not done on purpose
No coefficient invented; nothing signed; no HPV DNA sales; no imaging or genetic tests; production untouched.
