# S13 Design: Notifications framework with the INV-07 lint

Spec 4.9 and Section 10. Invariants touched: INV-07 (neutral text on push, email and in-app), INV-08 (SMS only for codes; D-12 for clinician paging), INV-13 (`is_test`), INV-16 (rule versions). Founder decisions applied: OQ-05 (SMS = codes and paging only), OQ-06 (generic copy everywhere, sponsor nudge rewritten), OQ-71 (S13 owns every template that still names a medicine). Research: `docs/research/S13.md` (36 platforms, mostly thin evidence).

## What already exists (extended, not rebuilt)
- `notifications` (channel, status, template, payload, priority, delivered/opened/failed timestamps, `send_after`), the critical-notification escalation engine, `notification_templates` plus `notification_template_locales` (97 and 151 rows), `patient_notification_preferences` (category by channel, 0 rows), `profiles.discreet_mode` (S02, read by nothing), `push_subscriptions` (web and Expo), `send-pending-notifications` (80 renderers, digest folding, preference gate), web `/patient/notification-settings`, the bell's `describe()` (102 in-app renderers).
- Live problems found: 30 of 79 sender renderers and 32 of 102 in-app renderers named a medicine, test, vaccine, condition, reading or result; 20 registry rows did too; a routine push failure fell back to SMS (INV-08); `discreet_mode` and quiet hours did nothing; no record of Expo tickets or receipts, or Resend outcomes.

## Data model (one migration)
- `notification_forbidden_terms` (term, kind `term|param`, active, version): the lint list as data. A trigger on `notification_template_locales` refuses an active row whose subject or body names a term, a forbidden placeholder, a clinical number or unit. Existing offending rows are rewritten in the same migration; non-clinician SMS rows are deactivated (OQ-05).
- `notification_settings` (profile, quiet hours on/off, start, end, timezone): own row via `set_my_notification_settings()`; default when absent comes from `notification_rules_config`. Discreet mode stays `profiles.discreet_mode`, written by the same RPC.
- `notification_rules_config` (versioned, PROPOSED, mirrored as `notifications.rules`): quiet hours 21:00 to 07:00 Africa/Lagos, routine push cap per day, receipt check delay, retry limits.
- `notification_delivery_events` (append only): accepted, receipt_pending, delivered, opened, failed, bounced, complained, deferred_quiet, suppressed_cap, blocked_inv07, token_dead. Detail never holds content. Admin read; service role writes.

## Behaviour
- Sender: renders, then re-lints the final text (term, number, unit); a violation is `blocked_inv07`, never sent. Routine push and email are deferred to the end of quiet hours (`send_after`), never dropped; critical rows and in-app are not deferred. Routine push is capped per recipient per day (excess stays in the inbox). Discreet mode sends a fixed title and body with no brand or topic. Routine push failure no longer falls back to SMS; the in-app copy stands. Expo tickets are stored and `expo-push-receipts` checks receipts after 15 minutes: `DeviceNotRegistered` disables the token. `resend-webhook` (signature checked) records delivered, bounced, complained; a hard bounce or complaint suppresses that address.
- Lint (`supabase/functions/_shared/notifications/neutral.ts`, shared by Deno and Jest): terms and stems, forbidden placeholders, clinical numbers and units, body emoji. The test renders every sender template and every in-app case with a payload where each key reads back a canary, so `payload.drug_name` anywhere fails even though the source is code.
- Not offered: a "show details on lock screen" switch (shared phones, partner-privacy risk). In-app inbox is always on.

## Screens
Web `/patient/notification-settings` and the phone's Settings get quiet hours and discreet mode (en, pcm). Clinician push says only "New priority case".

## Safety rules and tests
Safety case 20 (an amber task notification has no condition or reading), the full lint over all renderers and registry rows, a drift test between the code and database term lists, DB proof with RLS (patient own row only, admin reads events, anon none) and a sabotage (trigger dropped, clinical locale accepted), sender unit tests for quiet hours, cap, discreet mode and receipts.

## Recorded, not changed
OQ-91 (the lab request and care plan emails still attach a PDF that names the request), OQ-92 (critical rows still use SMS in the ladder; INV-08 vs D-12), OQ-93 (Pidgin templates and local terms such as "sugar", "pressure").
