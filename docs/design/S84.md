## 2. Shared three-kind label component (G-02b)

The three kinds from spec D.4: `automated_information`, `clinician_reviewed_guidance`, `clinician_decision`.

Types (packages/shared): `type OutputKind = "automated_information" | "clinician_reviewed_guidance" | "clinician_decision"`.

Component: `apps/web/src/components/output-kind-label.tsx` (and a React Native twin in `apps/mobile/src/components/`), props `{ kind: OutputKind; reviewer?: { name: string; at: string } | null }`. All copy comes from `packages/i18n` (en, pcm) under `outputKind.*`; no em dashes; never "your doctor".

Rules, enforced in the component and a unit test:
- `automated_information`: neutral badge, text "Automated information. Not reviewed by your care team." No reviewer allowed.
- `clinician_reviewed_guidance`: requires `reviewer`. If null the component renders nothing for the reviewed claim and falls back to `automated_information`. This is the same null-gating principle as `ReviewedByDoctor` and wraps it rather than replacing it.
- `clinician_decision`: requires `reviewer` and a signed timestamp; otherwise falls back one level down. Used for prescriptions, signed notes, released and reviewed results.
- The kind is derived server-side from data (`reviewed_by`, `reviewed_at`, signature columns), never passed from a client as a literal.

Adoption: replace the ad hoc badges in `case-brief-card`, `result-explainer`, `ai-summary-card`, `ai-ecg-summary`, `ai-imaging-summary`, `draft-reply-card`, `meal-plan-section`, `service-navigation-assistant`, `appointment-prep-helper`, `vaccination-card-import`, and the coach chat bubble. Scan test: any component file importing a result from a `generate*`/`explain*` action must import `OutputKindLabel`; sabotage snippet proves detection. Education items: map `clinician_reviewed = true and reviewed_at is not null` to guidance, else automated information (this makes G-03 visible to users while content review catches up).

No schema change except an optional generated column on AI result tables (`output_kind`) only if the surfaces need to query it; start without it.

## 3. Monthly accuracy audit schema (G-04b)

Reuses `public.triage_accuracy_report(p_from, p_to)` (S38e: age band, sex, state, small-cell suppression via `private.outcome_rule('min_cell')`, excludes test and shadow rows, admin or CMO). Adds a stored, signed monthly record so the audit is a dated artefact.

```
triage_accuracy_audits
  id uuid pk
  period_start date not null, period_end date not null   -- calendar month, Africa/Lagos
  rule_set_version_id uuid not null                      -- INV-16: version audited
  protocol_version text not null
  report jsonb not null                                  -- output of triage_accuracy_report, already suppressed
  total_reviewed int not null
  final_diagnosis_agreement_pct numeric                  -- null until triage_reviews records final diagnosis
  undertriage_count int not null, overtriage_count int not null
  worst_group jsonb                                      -- group with largest gap, by age band / sex / state
  generated_at timestamptz default now()
  generated_by text not null default 'cron'
  reviewed_by uuid references profiles(id)               -- CMO, null until signed
  reviewed_at timestamptz
  review_note text
  unique (period_start, rule_set_version_id)
```

- Created by a monthly cron `/api/cron/triage-accuracy-audit` (first day, Africa/Lagos) calling a SECURITY DEFINER `private.snapshot_triage_accuracy(p_month date)`; idempotent per period and version; empty months store a row with `total_reviewed = 0` so a missing audit is visible, not silent.
- RLS: admin and CMO read; only the snapshot function inserts; only `sign_triage_accuracy_audit(id, note)` (CMO) sets `reviewed_*`; no UPDATE or DELETE policy otherwise. Explicit `grant select ... to authenticated` (fresh table rule).
- Alerting: if unsigned 14 days after month end, raise an `ops` task for the CMO (INV-07: the notification names no clinical content).
- Extension: add `final_diagnosis_code` and `agreement_with_final` to `triage_reviews` (append-only, completing clinician only, like S38e's agreement field) so the audit can compare against the clinician's FINAL diagnosis as D.5 states, not only reviewer agreement.
- Tests (`packages/db/tests/s84_triage_accuracy_audit.sql`, registered in `ci.manifest`): snapshot idempotent; small cells suppressed; test accounts excluded; non-CMO cannot sign (42501); patient and clinician cannot read. Sabotage: remove the test-account filter, expect the exclusion check to flip.

Non-goals here: no model is called, nothing is signed or seeded by the build session, and the CMO signs from the sign-off hub.
