## 1. What changes and what is reused
Reused unchanged: the S15 state machine, `clinician_checks` (one row per application and kind), the document bucket and access log, the maker-checker rule (`separate_verifier_and_approver`), the `credential_notice` renderer, the expiry sweep, the S20 audit tables and scoring. Extended: the check kind enum, the eligibility function, three S15 functions, the S20 sampler, the work list. New: two tables, six functions, one daily job.

## 2. Q14: primary-source verification before independent contact
- Migration `20261013223014_p5_primary_source_check_kind.sql` adds enum value `primary_source` (alone, because a new enum value cannot be used in the transaction that adds it).
- `begin_credential_checks` already loops over the enum, so every NEW application gets a seventh check. `record_credential_check` passes it only with: a route in `credentialing_config.primary_source_routes` (DataFlow, written MDCN confirmation, register check), a reference of 4 to 80 characters not used by anyone else, a date no later than today and within `primary_source_max_age_days` (365), and an uploaded `mdcn_confirmation` document on the application. `approve_clinician_application` refuses without a passed check and copies it into `clinician_primary_source_verifications` for the new clinician (route, reference, date, verifier, evidence file).
- `private.psv_satisfied(staff)` is true when the rule is off, or the clinician is a test account, or a verification record exists, or they are still grandfathered. `clinician_is_eligible` now requires it, so a new clinician cannot be offered a task, page or rota slot until it holds.
- Grandfathering: `clinical_staff.psv_grandfathered` is set only by this migration, for the clinicians active at that moment (2). A trigger lets it be switched OFF only. It ends when evidence is recorded (`record_primary_source_verification`) or when the CMO sets `grandfather_ends_on` in a new config version and that date passes (the sweep and the nightly removal then treat them as ineligible). No evidence and no date was invented.
- Test clinicians (`is_test`) are exempt so every existing proof and QA fixture keeps working. A real clinician cannot be flagged test except by an admin or service context (`guard_is_test_flag`). Recorded in the closeout as a deliberate trade-off.
- Existing clinician evidence: the clinician uploads the DataFlow report or MDCN letter under Training and profile (the staff branch of `register_clinician_document` now accepts `mdcn_confirmation`); a reviewer who is not that clinician records route, reference and date against that file on the credentialing page. Recording ends grandfathering and closes open work items.

Review additions: care coordinators are exempt from the gate (no registration to verify, and the queue offers them logistics tasks); \`consult_availability_slots\` has a BEFORE INSERT trigger so the older patient-facing video-visit route also needs a verified clinician; applications already past the start of checks are backfilled with a pending check, which may be recorded in training or test passed.

## 3. Q15: mid-year spot re-check
`private.credential_recheck_sweep()` runs daily at 05:37 UTC (cron `37 5 * * *`; the expiry sweep is 05:01, the ladder 06:48). For each active non-test clinician: no record opens a `primary_source_missing` item; a record older than `recheck_months` (6) opens a `credential_recheck` item (one open per clinician and kind). Reviewers (admins and the CMO) get one `credential_notice` per new item, with catalogue keys `credential.recheck_due`, `credential.recheck_overdue`, `credential.primary_source_missing` (English catalogue, edge catalogue and `CREDENTIAL_MESSAGE_KEYS` all updated; INV-07 lint test added). Overdue is `recheck_overdue_days` (14) after due: flagged once, shown on the CMO hub as an attention line linking to `/clinician/credentialing`. Nothing in the sweep touches `status` or `active`.

## 4. Q16: new-clinician full review
`quality_config` v2 adds `sampling.new_clinician_full_review_cases = 20`. `consider_task_for_audit` order: red event, titration, level 1 first tasks, then `new_clinician_review` (the clinician's n-th red or prescribing case, n at most 20, counted by completion time then id), then the random sample. Reason `new_clinician_review` is added to the `clinical_audits` check. The TypeScript mirror `auditReason(facts, rate, newClinicianFullReviewCases)` and its tests cover the boundary (20, 21), off (0) and precedence. Tier language follows F-05: there is no Medical Officer tier; the rule is per clinician, not per tier, and an established clinician past 20 is never swept in.

## 5. Q17: patient-facing verified profile
`public.clinician_licence_verified_on(uuid[])` returns `staff_id, profile_id, verified_on` only for active clinicians in the caller's organisation with a stored record and a licence date on file that is in date; `public.consultation_clinician_licence_verified_on(encounter)` answers the date only to that encounter's patient. `LicenceVerifiedBadge` renders nothing without a valid ISO date and accepts no other prop but a class name. Wrappers: server (`LicenceVerifiedFor`), client (`LicenceVerifiedForClient`). Placed: doctor profile page (the page every doctor name links to), care message author line, booking (below the chosen slot), consultation room. The folio is never selected. A grandfathered clinician with no record has no badge though they may work.

## 6. OQ-109 work list
`public.credentialing_work_list()` (reviewers and CMO only) returns three lists: clinicians with no record (with their uploaded evidence files), re-checks due or overdue, and clinicians with a missing licence or cover date. The page shows them with the form that clears each. `record_clinician_credential_dates` fills a null date only (never overwrites; renewals keep their own flow), refuses the clinician themselves, a past date, and a note shorter than 10 characters, and audits the note. Document purge stays off (`document_purge_enabled = false` unchanged). Note: the evidence document foreign key is RESTRICT, so a future purge job must treat verification evidence as retained.

## 7. Identity vendor interface (no vendor)
`supabase/functions/_shared/integrations/identity.ts` (`IdentityVerificationProvider`, NIN or BVN, optional selfie), `identity-mock.ts`, `identityFromEnv` (returns null: the one-line change point), `selectIdentity` in `runtime.ts` (mock only outside production). Contract tests in `packages/integrations/src/contracts/identity.contract.ts`. Nothing calls it yet.

## 8. Safety rules this keeps
No new patient notification. No SMS. Reviewer notices carry a name and a date, never a patient fact (INV-07). Nothing auto-suspends on a missed re-check. Verification evidence is only ever written by a reviewer who is not the clinician. The badge cannot be fed a free-text claim.
