# S53 design note: medicines (1 of 2): catalogue, add flow, interaction check, side-effect notes, supporter notice

Scope: spec Module 8 rows 8.1 to 8.8 (USSD parked, D3). Research: `docs/research/S53.md`. Founder instruction: build everything, switch nothing on (Stage 1 gate S40 not closed, recorded as OQ-290). Reconciled against live (`koiplnmbgnqnbywhpjlf`) read-only on 2026-10-07.

## 1. What existed (extended, not rebuilt)
Medications, schedules, dose logs, supply, weekly adherence, refill reminders and the clinician `prescribe_medication` path (S08, S24); the pack reader `pack-vision.ts` and stateless `checkMedicationPack` (AI-007 governed, never writes to `medications`); the curated rule engine `drug-safety.ts` (clinician panel plus a patient note on the medicines list); supporter weekly adherence (S29 `adherence_summary`); neutral reminder and notification templates (S08, S13); `go_live_guards` (S37). `packages/medicines` already existed (schedule, adherence, supply, reminders).

## 2. Data model (migration `*_s53_medicine_catalogue_interactions_side_effects_supporter_notice.sql`)
`medicine_catalogue` (brand, generic, strength, form, `nafdac_number` nullable, source, version, `is_verified` needs a number, `needs_pharmacist_review`); `interaction_dataset_versions` + `interactions` (drug_a, drug_b by therapeutic group, severity, `advice_key`, source, version; v1 inserted as an unsigned draft, 85 rules; frozen once signed; `sign_interaction_dataset(version, hash, note)` is the only door, CMO only, recomputes the hash); `medication_side_effect_notes` (patient and acting guardian write, staff read only through the audited `care_team_side_effect_notes`); `supporter_missed_dose_notices` (dedupe ledger) and a trigger on `medication_logs` for missed rows; guard `interaction_check_enabled` (off) with conditions added to `private.go_live_conditions` by editing the live definition in place. A separate pre-fix migration (8.16) narrows `pharmacy_medications` commission columns and the `commissions` ledger.

## 3. Where logic lives
`@tarragon/medicines` (web and phone, pure, offline): `searchCatalogue`, `prefillFromPackReading`, `canSubmitAddForm`, `checkMedicineOnAdd`, `checkMedicineList`; the moved rule engine under `src/safety/` (web `rules/drug-safety.ts` and `diabetes-drug-safety.ts` are one-line re-export shims); `interaction-dataset.ts` turns the same rules into the signable rows and a test fails if the checked-in seed file differs. Justification for a shared function and not an edge function or RPC: the check must work offline on a phone, sends no health data anywhere, has no model in the path, and is identical on both platforms by construction.

## 4. Screens
Web and phone add form: catalogue suggestions; web only: pack-photo prefill with the "I have checked" tick (phone has no pack reader, it keeps the typed "check my pack"); a warning panel before the add when the guard is open (advice only, "Message your care team", "Add it anyway"); the NAFDAC prompt after an add (web and phone) and in the collection form (phone). Medicines list: side-effect note per medicine; the old patient interaction note now uses the patient wording and is behind the guard. Clinician chart: a side-effect notes panel (audited read).

## 5. Safety rules
Nothing the check does changes a medicine, dose or schedule (INV-02). Patient sentences never say stop; they say "your care team". No LLM in the check. Unsigned clinical content is not shown to patients: the guard is off, the dataset is a draft, `sign_interaction_dataset` has never been called. A catalogue row is never `is_verified` without a number and no number was invented. Supporter notice: explicit consent (both permissions named; an unrestricted grant does not count), in-app only, one a day, no medicine or reading in the payload or text, failure never blocks a dose log (proved with a forced failure).

## 6. Go-live guard and signing
`interaction_check_enabled`, switch role CMO, conditions: a signed dataset exists (data) and a pharmacist review attested. The human sign-off summary and the exact SQL are in `docs/clinical/interaction-dataset-v1.md`; the machine-readable rows in `docs/clinical/interaction-dataset-v1.seed.json`.

## 7. Acceptance tests
