## Naming
`programmes` and `programme_enrolments` collide with 13 existing tables, and the existing `therapy_sessions` is the S56 therapist booking table. New tables: `therapy_programmes`, `therapy_programme_versions` (review gate, INV-16), `therapy_programme_sessions` (content: ordinal, version, text, `audio_clip_id`, duration, bytes), `therapy_enrolments` (version started on, state, baseline and current score, exclusion result, source, `recorded_by`, `is_test`), `therapy_session_progress`, `therapy_share_consents`, `therapy_exclusion_list_versions` and `therapy_exclusion_rules` (CMO-editable, versioned), `therapy_programme_config` (PROPOSED).

## Engine
- Entry screen and red flags are rows, not code. `private.therapy_evaluate_screen` fails closed: a missing or wrong-kind answer is a positive, a programme with no list admits nobody. Routes: `crisis`, `same_day_clinician`, `medical_review_first`, `education_only`. A TypeScript twin (`packages/shared/src/therapy-programmes.ts`) gives the phone the same rule offline, and tests run the same cases.
- Run at entry (`enrol_in_therapy_programme`) and again at the start of every session (`start_therapy_session`). A positive stops the programme, raises a `clinical_tasks` row (never only a notification) and, for crisis, a class 1 task, an urgent `programme.flag` event and the on-call page. No phone number or helpline anywhere.
- Content is versioned and frozen once approved; an enrolment reads the version it started on. Real patients see only approved content; test accounts also see drafts (flagged).
- Scores at checkpoint sessions; worsening against PROPOSED thresholds pauses the programme and raises a review task, inline at completion and again from the bus (`programme.assess_progress`, the `programme-progress` handler), both idempotent.
- Progress reaches a clinician only through `read_therapy_progress_audited`: tied non-coordinator clinician, active revocable consent, audited success and denial (INV-10, INV-12). No policy uses the organisation-wide staff function; sponsors and employers have no access at all (I9).

## Events
`programme.session_completed` (enrolment_id, ordinal) and `programme.flag` (enrolment_id); ids only. Edge function `programme-progress` is realised as the bus handler `supabase/functions/_shared/programme/progress-handler.ts`, registered in `process-events` (redeploy that function; none done here).

## Screens
Web `/patient/programmes` and `/patient/programmes/[code]`; mobile `therapy-programme-screen.tsx`. Entry questions, guidance cards, session player (text first, low data, audio only once a signed recording exists, opened session cached and completions queued offline), scores at checkpoints, diary kept on the device, share-consent card. All inside the shared-phone gate. No navigation entry is added until a guard is switched on.

## Programmes
