## 3. Data model
S36a and S36b add functions only: no table, no column, no data change (so no count is needed in the header). S36c adds none: it calls S20's.
- `admin_patient_search(query)`: admin only. Name, patient number, phone digits (a typed 0801 matches a stored +234801) or exact email. At most 25 rows of minimal identity (name, patient number, masked phone, birth year, active, test). One audit row per search holding the query LENGTH and hit count, never the text.
- `admin_open_patient_record(patient, reason)`: admin only. Reason 10 to 500 characters. One audit row carrying the reason. Returns support facts only (contact, account state, last 20 purchases). Reads no clinical table; clinical views stay behind `support_view_sessions` and the clinician ties.
- `go_live_guard_status`: same signature (so no overload ambiguity), gate widened to also admit `private.has_permission('ops.console.view')`.

## 4. Screens
`/admin/patients` (search box, results, "Open record" asks for a reason, record shows, closing it drops it so a second look is a second reason and a second audit row; links to the existing duplicates and merge tools). `/admin/ops/go-live` (the S37 component with `viewer="ops"`: no form, no button, no sign-off list). `/clinician/quality` and `/clinician/quality/audits/[id]` (CMO only via `canAssignCases`). All strings in `packages/i18n` (en and pcm); nav and search entries added.

## 5. Safety rules
1. The query and the reason travel in a POST body, never the address.
2. Server actions use the signed-in admin's own session, never the service role, so the database sees the real caller.
3. A failed read shows a load failure, never an empty list.
4. The audit form's score and outcome are computed by `submit_clinical_audit`; the page decides nothing. A half-filled form never reaches the database (an unanswered safety item is not a pass).
5. Opening an audit is a logged clinical read, and the page shows the task, never the patient's identity.
6. Notices in the address are fixed tokens, so a link cannot put its own words on the page.
