# S08y design note: medicine-safety gaps (same ingredient, governed interaction rules, brand map, NAFDAC note, supporter's doses, low-supply handoff)

Scope: the six gaps left after S08, S08x and S53. Everything is born OFF or UNSIGNED. Nothing is signed or switched on by the build. Research and sources: `docs/research/S08y.md`.

## 2. Data model (one migration, `20261021111233_s08y_medicine_safety.sql`)

- `medicine_interaction_rule_sets` (id, version, config jsonb `{"rules": [...]}`, approved_by/at, is_active). Shape enforced by `private.interaction_rules_valid` (a CHECK; twin of `validateRuleSet`): code, two different normalised ingredient names, severity in (contraindicated, caution, info), a source of at least 5 characters. v1 is `{"rules": []}`, unsigned, inactive. `public.sign_medicine_interaction_rule_sets` is CMO-only and **refuses an empty set**; the supersede trigger refuses re-activating a version older than a signed one. The table is staff-only; patients reach the signed set only through the guarded RPC. A rule's source must contain an https link. `public.active_medicine_interaction_rules()` returns rules only while the guard is open for the caller.
- `medicine_brand_generic_map` (brand, generated `brand_key`, ingredients, https citation, created_by, reviewed_by/reviewer_name/reviewed_at, is_active). CHECKs: active requires a named reviewer; the reviewer is not the author. A trigger clears the review when brand, ingredients or citation change. No direct writes: `save_medicine_brand_map`, `import_medicine_brand_map` (skips brands already on file), `review_medicine_brand_map` (active clinical staff only; an admin or a pharmacist account may enter rows but not review). Patients read published rows only through `public.published_medicine_brands()` (no author or reviewer ids); the table is staff-only. Approval carries the `edited_at` the reviewer saw (`p_seen_edited_at`), so a stale page cannot approve changed content; the reviewer must be a doctor (not a care coordinator) who neither entered nor last changed the row.
- `medication_pack_numbers` (one row per medicine, NAFDAC format CHECK; a look-alike letter that had to be corrected is refused, not stored guessed; a value that is not a NAFDAC number never blocks the add). Written only by `set_medication_nafdac_number` (the person or someone acting for them). Read by the person, someone acting for them, a supporter holding the medicines category. No staff policy, so no `staff_read_scope` row; listed in `data_registry` (unreviewed). Follows an amended medicine.
- `public.supporter_todays_doses(patient)`: today's scheduled slots (not as-needed) with the latest answer; audited through `private.audit_patient_read` (so the person's own access log shows it; a repeat inside ten minutes adds no row), and carries `active_medicines` so an empty day is not read as an empty list.
- Guards, all off: `medicine_duplicate_ingredient_check`, `medicine_interaction_rules`, `supporter_todays_doses`. Conditions added to `private.go_live_conditions` through the documented anchor.

## 3. Safety rules kept

1. Warn only, in the existing add panel. "Add it anyway" is always there; no function can stop, edit or remove a medicine (INV-02). The sentences say "your care team" and never "stop".
2. No model anywhere (INV-01). No outbound call to NAFDAC; Tarragon sends no SMS (INV-08).
3. No clinical content was written: no rule, no brand mapping. Test fixtures use fictional ingredient names (`exampleone`).
4. The supporter door is category-scoped and written fresh: it does not look at `profile_access.clinical_access` or the `permissions` array, so a supporter with `clinical_access` and `view_medication` but no medicines category is refused (proved with a control, then a sabotage that removes the check).
5. Failed reads never read as a pass: the add form separates "closed" from "could not find out"; the supporter list shows "could not load" rather than an empty list; the parse of the supporter answer treats any unexpected shape as unreadable.

## 4. Tests

`packages/medicines` (100 percent branch coverage kept): ingredients, brand map (publish gate, CSV), interaction rules, combined add check, NAFDAC store, supporter doses, refill handoff. Shared-case drift: a test fails if a case name in `ingredients.fixtures.ts` or `interaction-rules.fixtures.ts` is missing from the SQL proof. DB proof `packages/db/tests/s08y_medicine_safety.sql` (registered in `ci.manifest`) with a sabotage phase. Web: add-form tests (switches, warning, NAFDAC), sign-off queue (empty draft is not outstanding work). Governed-config supersede guard test lists the new table.

## 5. Known limits

- Ingredient matching is names only: salts, synonyms and spelling variants are not matched, and doses are ignored.
- The brand map and the rule set are empty until people fill and sign them; until then the features show nothing and the switches have nothing to switch on.
- The mobile supporter view reads the profile_access model; Care Circle (S29) supporters are on a different table and are not covered (OQ-S08Y-2).
- Nothing was run on a device, an emulator or a real browser session against signed-in data; see `docs/BUILD-PROGRESS.md`.
