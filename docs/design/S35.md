# S35 design note: clinician area and patient summary

Decision (founder, 2026-10-06): build the screens in `apps/web` under `/clinician`, as thin routes over shared components and package logic. Extracting the clinician area into `apps/console` stays a later step (S01d section 5, step 8; OQ-99, OQ-209). Nothing here widens the console to the `clinician` role.

## Reconciled with what exists
Reused as is: S17 `queue_next`, `queue_summary`, `queue_handback`, `queue_extend_claim`, `queue_complete`; S19 on-call page and alarm; S18 rota page; S21 consultation room; S22 notes; S23 scribe panels and `attach_scribe_draft_to_note`; S24 prescribing and care plan changes; S30 earnings view; S15 credentials page; `read_patient_chart_audited` and friends.
Missing and built here: a next-task queue page, a generic task view, one audited patient summary, my lead patients, an always-visible safety concern button, scribe controls inside the consultation view.
Not built here (recorded as follow-ups): weekly statements, payout status and bank details (S31); extraction to `apps/console`.

## Data model
One migration, no new tables.
- `public.clinician_patient_summary(p_patient, p_reason) returns jsonb`: active clinician only, reason of 10+ characters, each section gated by its access category through `private.can_staff_read_clinical` (tie, break-glass or support view), ONE `audit_log` row per open (INV-10), `denied` when nothing is readable. Sections: readings (14 days) with target band, triage events (last 5 non-shadow in 30 days, the only staff read path to `triage_events`), medicines with adherence, care plan, pending proposals, signed notes, results metadata, allergies, conditions, care circle count. `reproductive_health` is never surfaced.
- `public.my_lead_patients() returns jsonb`: my active leads with last BP, adherence percent, pending proposals, tasks due in 24 hours; one audit row per patient (bounded by lead capacity).
Both are `authenticated` only; `anon` is refused (`revoke ... from public`). Proof: `packages/db/tests/s35_clinician_patient_summary.sql`, two sabotages.

## Safety rules
- Every clinical read goes through the audited functions above; no new direct table read from a page.
- A claim is the tie (INV-12); a task you do not hold shows nothing about the patient.
- Hand-back and complete are single server actions that call the existing RPCs; errors map through `mapQueueError` and show a plain message, never a raw code.
- No model call in any new path; scribe drafts stay drafts until `finalize_encounter_note` (INV-11).
- Strings through `packages/i18n` (`queue.*`, `summary.*`), en and pcm, no em dashes. Clinician pages render in English today (layout passes `en`); keys are still used so the catalogue is complete.
- Notifications are not touched (INV-07).

## S35c: scribe safety (branch `s35c/scribe-safety`)
Built from the plan in `docs/research/S35.md` (fourth pass). Everything below keeps INV-11: no AI text reaches the record without a clinician's signature, and nothing stores the AI's text.
- **Facts to confirm** (`supabase/functions/scribe-draft` modes `facts` and `facts_draft`; pure logic in `_shared/scribe/facts.ts`, copied byte for byte to `apps/web/src/lib/scribe/facts.ts` and held in step by a test). Stage one lists typed facts with a verbatim quote; the server drops any fact whose quote is not in the text it sent and reports how many. The clinician decides every fact (no confirm-all), can correct wording, and can add a fact the model missed; negations and safety items list first. Stage two writes from confirmed facts only, must cite fact ids, and the server returns deterministic grounding warnings (uncited text, unknown ids, numbers not in the facts). No model is asked whether something was omitted.
- **Consent gate**: the clinician screen reads the patient's own answer (`scribe_consent_state`: no_consultation, not_asked, given, declined) and offers Start only when it is given and `scribe_may_start` is true; the clinician-click consent dialog is gone (S21g already refuses it). Not built: a live recording indicator, because nothing records (OQ-216).
- **Review record and hash** (migration `*_s35c_scribe_review_record_hash_and_quality.sql`): append-only `scribe_review_events` (model, prompt version, hash of the draft as generated, per-section outcome, no text) written just before signing, fail closed; `signed_content_hash` stamped on finalize with `note_content_matches_hash` to re-check (a tamper check, OQ-215).
- **Quality**: CMO-only `scribe_edit_rates` and `scribe_audit_sample`, and `/clinician/scribe-quality`.
- **Governance**: new suite "AI-017 facts-to-confirm golden transcripts" (migration `*_s35c_ai017_facts_stage_eval_suite.sql`, 6 cases, deterministic scorers in `run-scribe-facts-eval.ts`), wired into the existing runner. No run exists, nothing is approved, AI-017 stays off (OQ-213).
- **SLA warning**: `queue.sla_warning` is a PROPOSED registry value (30 minutes, CMO), used by the amber badge (OQ-217).
- **Measurement**: `pnpm scribe-wer` (OQ-214).
- **Found, not fixed here**: `private.may_work_on_note` fails open for a caller with no clinical_staff row; the new functions check for an active clinician themselves, and the shared fix is its own task.
