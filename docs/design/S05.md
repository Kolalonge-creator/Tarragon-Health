## 2. Idempotency

`vitals_readings` already had `client_reading_id` with a unique `(patient_id, client_reading_id)` index, so it is reused (the view exposes it as `client_id`). `symptoms` and `medication_logs` get `client_id` with the same partial unique index. A retried insert fails 23505; the offline client (S06) treats that as already done.

## 3. Access model built (INV-10, INV-12, INV-02, INV-11)

- `private.clinician_has_patient_access(patient)`: **the one stub for INV-12.** Staff are tied by care-team assignment, an open escalation or an unresolved alert routed to them, or a live appointment with them. S16 to S19 add active task, lead assignment and on-call page here and nothing else changes. `private.can_staff_read_clinical(patient, category)` adds break-glass (per category, `reproductive_health` excluded by `has_emergency_access`) and an active support-view session.
- `public.read_patient_chart_audited(patient, sections[], reason)`: one call, eleven sections (vitals, symptoms, medications, dose_events, prescriptions, conditions, allergies, family_history, documents, notes, referrals), each gated by its own care-access category. One `audit_log` row per call carrying the sections; a refusal is audited as `denied`; a patient caller raises and writes nothing. `reproductive_health` is not a section.
- `public.open_patient_document_audited(document, reason)`: gate, audit row, returns the storage path; the server signs the URL. The bucket policies stay patient-only (no staff storage policy exists), so a staff download is always this audited call plus a server-side signed URL.
- `prescriptions`: no staff SELECT policy at all. Reads: the patient (non-draft), the author, the named pharmacy partner (sent / dispensed), a Care Circle supporter holding the `medications` category (explicit `::care_access_category` cast, the overload trap in CLAUDE.md), and staff only through the chart function. Insert and update need `private.has_prescribing_authority` **and** the tie. A session cannot create one past draft; leaving draft stamps `signed_by = auth.uid()`, `signed_at = now()` (only a prescriber can be stamped); the CHECK `prescriptions_signed_before_send` refuses anything else, so a service context cannot send an unsigned prescription either.
- `specialist_referrals`: the clinician's act of leaving `draft` is the signing act, stamped as herself; CHECK `specialist_referrals_signed_before_send`. 0 rows existed, so nothing to convert.
- `clinical_encounter_notes`: a trigger validates amendments (same patient, original finalized); the `notes` view reports `amended` for a note a later finalized note supersedes. **The patient reads no clinical notes** (OQ-58, founder decision): she sees the published `consultation_patient_summaries`; an interim policy giving her finalized notes was dropped the same day. INV-11 holds: no draft or AI draft is patient-visible.

## 5. INV-10 final state: direct staff access closed on all ten health-record tables (S05 to S05f, 2026-10-01)

The founder ruling was "audited reads on ALL live clinical tables now". S05 built the audited path and could close only two tables with no live callers; the other eight needed their screens moved first (about 100 call sites, 4 invoker views and several shared hooks, with no way to run the staff UI locally). S05b to S05f moved them one table at a time, each as an additive migration applied before the code shipped, then a closing migration applied after the deployment. Every table now has only the patient's own policies (plus the family paths below); staff read through audited, tie-gated functions and write through tie-gated functions.

| Table | Rows when closed | Staff reads now | Staff writes now | Closed in |
|---|---|---|---|---|
| `patient_documents`, `family_history` | 0 | `read_patient_chart_audited` | none | S05 |
| `patient_allergies`, `patient_conditions` | 0 | `read_patient_chart_audited` (sections `allergies`, `conditions`), `search_patient_ids_by_condition` | none (FHIR acceptance writes through a definer function) | S05c |
| `clinical_encounter_notes` | 0 | `read_patient_encounter_notes_audited` | `create_encounter_note`, `update_encounter_note_draft`, `finalize_encounter_note` | S05d |
| `specialist_referrals` | 0 | `list_referrals_audited`, `get_referral_audited`, `list_patient_referrals_audited`, `referral_worklist_count` | `create_specialist_referral`, `submit_draft_referral`, and the other S05e functions | S05e |
| `medication_logs`, `symptoms` | 0 / 1 | `read_medication_dose_log_audited`, chart section `symptoms` | none | S05f-B |
| `medications` | 0 | `read_patient_medications_audited`, `read_medication_embeds_audited` (the 8 embedded lists), `patient_record_counts_for_merge` | `prescribe_medication`, `confirm_medication_refill`, `amend_medication` (definer) | S05f-C |
| `vitals_readings` | 12 | `read_patient_vitals_audited`, `patient_monitoring_latest_readings` (per-patient tie, `visible` flag), `patient_vitals_adherence`, the `hypertension_quality_metrics` view (org-level aggregate) | none (nothing in the app writes a vitals row from a staff session) | S05f-D |

Paths that deliberately keep direct table access, because they read or write the patient's own rows, a granted family path, or run as the service role: the patient's screens and actions, the mobile app, a caregiver with the matching category grant (and, for medications, a `view_medication` supporter), an acting supporter's writes, device and wearable ingestion, cron, the AI coach, the data export, and the emergency card.

**INV-10 closed table.** After S05f-D every one of the ten tables satisfies: no RLS policy admits `is_org_staff`, `has_emergency_access` or `can_support_view`; the staff-facing screens call a function that checks the tie (INV-12) or break-glass or an active support-view session, writes an audit row (`staff.chart_read` with its basis, or one summary row for a list), and returns `denied` rather than an empty list; the refusal is audited too. Each table's closing migration ends in an assertion block and has a proof in `packages/db/tests/` registered in `ci.manifest` with at least two sabotages.

**Decision recorded for lists that cross patients (OQ-02).** A list that shows one patient's clinical data to a clinician applies the same tie as the chart: the monitoring roster lists every patient the caller may see in the organisation but returns readings only for tied ones (`visible = false`, never an empty-looking row). Aggregate figures that expose no individual (the hypertension quality KPIs, the care-team outcome report) stay organisation-level for organisation staff.

**Things found along the way that other tables will hit again.** A closed table does not fail loudly: RLS filters rows, so a staff read returns nothing, a staff `.update()` matches zero rows and reports success, a head-count returns 0, and an embedded select returns `null`. Each of those was found and replaced by a function that raises or returns a visible `denied`.

## 6. Reconciliations that needed a name or a judgement

- v5 `referrals` is the live invite / reward table. The clinical one is the view **`clinical_referrals`**.
- v5 `observations.type` "accepts new types without schema change": the live `vital_type` is an enum, and the red-flag triggers key off its values. Adding a type is one `ALTER TYPE ... ADD VALUE`; the view passes an unknown type through and reads `value_numeric` / `value_unit`. OQ-55.
- v5 `dose_events` has `pending`; live rows exist only once logged. S08 computes pending from `schedule_times`. OQ-56.
- v5 prescription states start at `signed`; the live model needs a `draft` so the signature is a transition. OQ-57.
- OQ-54 to OQ-58 were answered 2026-10-01 (see docs/OPEN-QUESTIONS.md).
