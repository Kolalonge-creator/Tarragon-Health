# S28 Design: pharmacy partner, prescriptions to a chosen pharmacy, dispensing

Spec 9.6 (pharmacy row), 8.9 to 8.12, Part C.2 (collection only), D.6 (licensed pharmacies only). Depends on S24 and S27. Invariants touched: INV-02, INV-07, INV-10, INV-13, INV-16. Research: `docs/research/S28.md`. Built on the S36h branch (PR #987) so the flags table and the pharmacist list are reused.

## 1. What exists (extended, not rebuilt)
S05 `prescriptions` (state machine signed, sent, dispensed; `pharmacy_partner_id`; INV-02 CHECK), S24 signed prescribing, S36h flag-a-problem (`prescription_pharmacy_flags`, `pharmacist_prescriptions`), the pharmacy partner and location tables with PCN licence fields, the QR and phone-desk supply path (`record_prescription_supply_public`, desk functions) writing `pharmacy_order_dispenses`, refill reminders. Nothing ever set the pharmacy, the code or the `sent` state; the partner could flip a prescription to dispensed with a raw update and read prescriptions directly, unaudited.

## 2. Decisions taken (founder, 2026-10-07)
1. Branch from the #987 branch. 2. One shared supply count across the QR, desk and partner paths. 3. A pharmacy sees the prescription, the patient's name and number and her allergies only, and every read is audited. 4. Scope: send, collection code, dispense, flags. Price comparison, verified batches and pharmacist chat go to open questions (OQ-273).

## 3. Data model (one migration, `*_s28_pharmacy_collection_and_dispensing.sql`)
- `pharmacy_config` (versioned, one active row, mirrored as `pharmacy.collection_rules` with a drift test): code length 8, valid 14 days, 5 wrong tries lock it. PROPOSED, CMO and pharmacy lead.
- `prescriptions` gains `pharmacy_location_id`, `chosen_by_patient_at`. The old `collection_code` column is no longer written.
- `prescription_collection_codes` (one row per prescription): the code, expiry, wrong-try count, lock, used time. RLS: the patient reads her own; nobody else; no write grant.
- Events `prescription.sent`, `prescription.dispensed` (ids only); three neutral in-app templates (INV-07: no medicine, condition or patient).
- The prescription trigger lets the patient's own choice change routing for one statement (a transaction flag set only inside `patient_choose_pharmacy`); everything else stays the prescriber's. The two direct partner policies on `prescriptions` are dropped.

## 4. Functions (all SECURITY DEFINER, search path pinned, anon refused)
Patient: `patient_collection_pharmacies`, `patient_choose_pharmacy` (verified active pharmacies only, changeable until a supply starts, new code each time), `patient_prescription_collection`, `patient_new_collection_code`. Pharmacy: `pharmacist_prescriptions` (audited, no code), `pharmacist_verify_collection` (wrong tries counted and committed, fifth locks, allergies shown, audited), `pharmacist_dispense_prescription` (full or partial; partial needs a written note; row-locks the medicine like the QR path; refuses beyond the permitted supplies; full supply moves the prescription to dispensed once, uses the code, tells the patient neutrally, emits the event, audits).

## 5. Screens
Patient (web): `/patient/pharmacy/collect/[prescriptionId]` (choose, show the code, new code, change pharmacy), linked from the prescription card; English and Pidgin. Pharmacy (web): the S36h list now links to a counter page (`/pharmacist/prescriptions/[id]`) to check the code and record a supply; English only (staff page, as OQ-102). No mobile screen (OQ-277). No delivery, no payment.

## 6. Safety rules
1. The code is never in a notification, a URL or the pharmacy's reach; a pharmacy can only test a guess, and five wrong guesses lock it.
2. A pharmacy can only touch a prescription sent to it, and only through audited functions.
3. A signed prescription's items are never altered by routing (INV-02).
4. One prescription cannot be supplied twice by two doors (shared lock and count).
5. Only licensed, verified pharmacies appear (D.6); none is active today (OQ-274).

## S28c. What was added on top of the live collection-code migration (founder, 2026-10-07)
- **Base**: the live S28 (`prescription_collection_codes`, `pharmacy_config`, `patient_choose_pharmacy`, `pharmacist_verify_collection`, `pharmacist_dispense_prescription`). A first, separate S28 build (PR #990) was set aside; nothing of its schema is carried over.
- **Go-live**: `private.pharmacy_collection_on()` is the S37 `prescribing_enabled` guard, closed by default. Every patient choice, pharmacy list, counter check and supply, and every question refuses while it is off. Taking a prescription back, the downloadable form and the QR and phone-desk paths are never behind it. The guard's conditions gain a licensed pharmacy with a verified location, the collection rules confirmed, and the notification sender deployed.
- **Questions, not chat**: six fixed questions and "cannot supply" from the pharmacy, three fixed answers from the signer. They ride on S36h's flag table (`question_code`) and its `pharmacy_flag_review` task. No free text anywhere. An answer never changes a signed prescription.
- **Batch and expiry** are required for any supply (`batch_required`, `batch_expired`); the screen never says a batch is verified or genuine.
- **Caregiver**: `private.rx_patient` lets a holder of `manage_pharmacy` act for the patient on every patient function; the patient is told and her access log records it.
- **Repeat**: a collected prescription can be sent again while `private.supplies_remaining` is at least one; the code is new and the old one dies. `dispensed` to `sent` and `sent` to `signed` are allowed only through the patient's own functions (the `tarragon.rx_route` flag).
- **Withdraw**: `patient_withdraw_from_pharmacy`, not once a supply has started.
- **Prescriber**: `/clinician/pharmacy` (`prescriber_pharmacy_overview`), one audited read; S36h's page redirects to it.
- **S28d**: the directory view loses its delivery columns; `is_test` on three legacy tables; five older pharmacist reads audited; the pharmacy order alert is neutral and in-app.
