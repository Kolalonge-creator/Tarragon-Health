# S28 Design: pharmacy partner (prescriptions to a chosen pharmacy, dispensing)

Spec 9.6 (Pharmacy), Module 8 rows 8.9 to 8.12, Part C.2 (no home delivery). Invariants: INV-02, INV-07, INV-08, INV-10, INV-12, INV-13, INV-14, INV-15. Research: `docs/research/S28.md`.

## 1. What exists (extend, do not rebuild)
- **Two prescription chains, not joined to a pharmacy.** The live chain is the `medications` row (rx_number, 6-char code, 64-hex public token, repeats): it feeds the PDF, the QR, the public verify, the supply record and the phone desk. The S05/S24 `prescriptions` table has `pharmacy_partner_id`, `collection_code`, state `draft/signed/sent/dispensed/cancelled`, signing CHECKs and a frozen-items trigger. Nothing ever sets `sent`, the partner, the code or `dispensed_at`. S28 adds that.
- Partner RLS on `prescriptions` (select when sent or dispensed and it is your pharmacy; update sent to dispensed) exists but returns whole rows (patient_id, items). It is replaced by narrow functions; the direct policies are dropped.
- Price list `pharmacy_medications` (price_kobo, stock_status), directory view, `pharmacist` role with `profiles.pharmacy_partner_id`, `medication_dispense_flags`, `pharmacy_order_dispenses` (the supply record), S08 refill reminders. All reused.
- Legacy `pharmacy_orders` (sold goods) is a different, older commerce path and is untouched (OQ-23).
- Delivery remnants (`pharmacy_partners.delivery`, delivery fee, order delivery columns) exist and are exposed to patients through the directory view. S28 builds none of it and **stops exposing it**: the new patient function returns no delivery field (OQ-209).

## 2. Decisions
1. **The collection code lives on `prescriptions`; the supply record stays the source of truth for repeats.** Dispensing through a partner writes the `pharmacy_order_dispenses` row for the linked medicine (source `pharmacy`, recorded_via `partner`) in the same transaction, so the repeat limit, the QR verify and the phone desk keep agreeing (OQ-208).
2. **The patient sends; no clinician or coordinator step.** Direct patient to pharmacy, with recorded consent ("share my prescription with this pharmacy"). A caregiver may not send in S28 (OQ-214).
3. **Only a pharmacy with a verified, unexpired licence and an active account can be chosen**, checked again at send time in the database (partner quality rule, 8.11). Quality thresholds are PROPOSED config (`pharmacy.quality`), not code.
4. **Re-routing** (pharmacy cannot supply, patient picks another) is allowed while `sent`, by the patient, never after `dispensed`. Each change keeps an event row. The forward-only trigger gets one narrow allowance, a transaction-local flag only the definer functions set, because the trigger refuses anyone but the prescriber to change routing.
5. **Partner reads are minimal and audited.** The pharmacy inbox shows collection code, medicine lines, a first name and age band, and "allergies recorded: yes/no". The detail view (name, allergies) writes an `audit_log` row (INV-10) and refuses a prescription for another pharmacy.
6. **Flags**: `out_of_stock` (patient told neutrally to choose another pharmacy), `query_to_prescriber` (neutral in-app notice to the signing clinician; the pharmacist's note is stored, visible to staff only). One new table `prescription_pharmacy_events` holds sends, re-routes, flags and dispenses, append-only.
7. **Neutral notifications (INV-07, INV-08).** Pharmacy: "A prescription is waiting for you." Patient: "Your pharmacy has an update." Prescriber: "A pharmacy has a question." No drug, name or code in any text; no SMS.
8. **Gate**: the whole flow sits behind `platform_modules` key `pharmacy_collection` (dormant, INV-14, OQ-18 pattern); functions refuse while off. Nothing goes live without the founder.
9. **Events**: `prescription.sent` and `prescription.dispensed` (ids only) registered with S10.
10. **Test data** (INV-13): the new event table carries `is_test`; the pharmacy inbox hides test prescriptions from non-test pharmacies' statements and a proof checks it.

## 3. Data model (one migration, real timestamp, live `list_migrations` checked)
- `prescription_pharmacy_events(id, organisation_id, prescription_id, event_type [sent, rerouted, flagged_out_of_stock, flagged_query, dispensed, withdrawn], pharmacy_partner_id, actor_id, note, is_test, created_at)`; RLS on, staff and the owning patient read through functions only, no direct writes.
- `prescriptions` stays as is; the trigger allows routing changes and the `signed -> sent` step only when `tarragon.rx_routing = 'on'`.
- `patient_pharmacy_preference(patient_id pk, pharmacy_partner_id, updated_at)`: the pharmacy last used, so a refill defaults to it. Not a stored balance, not a wallet.
- Config `pharmacy.quality` (PROPOSED): licence must be verified and unexpired; minimum days of licence left (30).
- Functions (all `security definer`, `search_path=''`, `revoke ... from public`, grants checked with `has_function_privilege`): `pharmacies_for_prescription`, `send_prescription_to_pharmacy`, `reroute_prescription_pharmacy`, `my_prescription_pharmacy`, `pharmacy_inbox`, `pharmacy_prescription_detail`, `pharmacy_mark_dispensed`, `pharmacy_flag_prescription`.

## 4. Screens
- Patient web and mobile Medicines: "Choose a pharmacy" sheet (name, area, price for the signed items, stock status, no delivery), consent line, then the collection code and pharmacy name; "Choose a different pharmacy" while it is waiting; the downloadable form stays beside it ("Take it to any pharmacy").
- Pharmacist web `/pharmacist/prescriptions`: waiting list with collection codes, detail, "Mark dispensed" (types the code back, batch and expiry optional), "Flag a problem".
- All strings in `packages/i18n` (en, pcm), no em dashes, "your care team".

## 5. Safety rules
1. A prescription reaches a pharmacy only after signing; items never change after (INV-02, existing CHECK).
2. A controlled medicine never reaches the partner path (S24 hard stop, re-checked at send).
3. A pharmacy sees nothing of a prescription not sent to it; no other pharmacy ever sees a code.
4. Dispensing needs the code the patient shows, and cannot exceed the repeat limit.
5. No notification text carries a drug, a name or a code.
6. No home delivery field is read or returned anywhere in this build.

## 5b. What was built beyond this note's first draft
- `pharmacy_collection_available()` so the patient screens know whether to offer the card at all.
- Patient web and mobile cards, the pharmacist `/pharmacist/prescriptions` screen and navigation entry, three neutral in-app templates with INV-07 lint tests, a `pharmacy.quality` registry entry mirrored to the migration seed, the mobile bell line.
- Proof `packages/db/tests/s28_pharmacy_collection.sql` (73 checks, two sabotage steps), Jest for web actions, parsers, loader, both components and mobile.

## 5c. Changes after the review pass
- A prescription is offered, priced and sent only while its medicine is still current (`private.prescription_is_current`): an amend or a stop leaves the OLD prescription row signed, so state alone was not enough.
- A partial supply no longer uses up a permitted supply; only complete supplies count.
- A pharmacy that is switched off or whose licence has lapsed sees nothing (`pharmacy_not_active`).
- The patient can take a prescription back (`withdraw_prescription_from_pharmacy`): consent to share is revocable. The forward-only trigger allows `sent` to `signed` only through the definer functions, which clear the pharmacy and the code.
- The Medicines card keeps a held code visible even if collection is later switched off (`my_collection_prescriptions`, no module check, own rows only).

## 6. Not built here
Pharmacist chat (OQ-213), NAFDAC authentication and batch verification (OQ-211), caregiver sending (OQ-214), repeat supplies through the partner path and a refill reminder that opens the chosen pharmacy (OQ-215), the S37 go-live guard (OQ-216), the prescriber's view of collection status (OQ-217), a mobile pharmacist app, price data quality tooling (OQ-212), dropping the dormant delivery schema (OQ-209, extends OQ-16).
