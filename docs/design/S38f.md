# S38f: sponsor staff read their programme's monthly figures (mobile)

Decision (founder, 2026-10-07): a sponsor's own staff get access in the mobile app and see their group figures there (OQ-258).

## Who
The existing institution logins `hmo_admin`, `corporate_admin`, `ngo_admin`. They are already kept out of every patient table (`private.is_org_staff` excludes them, spec I9) and that is untouched. A login counts as sponsor staff only when it is active and its role matches the type of its own organisation. They see only programmes whose `sponsor_org_id` is that organisation. No new account role (CLAUDE.md: never re-split `profiles.role`) and no link table.

## What
Never the live report. A daily job writes one snapshot per programme for the month that has just closed, after the grace days, once. A snapshot is never changed or deleted and no user can read the table. Sponsor staff read snapshots only, through two functions. The snapshot is the same aggregate as the admin report: only members who agreed under the current consent text, never a test account, small groups withheld whole with complementary suppression.

Only the latest closed month is ever written, and only from the grace days until a week later, for programmes that existed and were valid in that month. After that window a gap is left rather than a figure built from data that no longer describes the month; a failing run opens an incident daily. Older months are never rebuilt from today's consents.

A refused read (another sponsor's programme, or one that does not exist) returns `{ok:false}` and is itself written to the audit log; listing programmes is audited too.

## Threat notes
- Two live runs a day apart cannot be subtracted: there is no live run for sponsors.
- Figures across months can still be differenced. The minimum group size (the larger of the platform minimum and the sponsor's own) and one figure a month limit this; it is documented, not closed.
- A programme that is not yours and one that does not exist get the same refusal.
- Every read is in the audit log. The sign-up code is visible while a programme is open because the sponsor hands it out; it is hidden once closed.
- Sponsor staff never see a member, a list, a name or a count below the minimum.

## Mobile
After sign-in the app reads the role. Sponsor staff land on a figures-only screen; the patient shell, health sync, push-token registration, offline vitals queue, reminder top-up and review prompts do not run for them. The one exception is the outbox flush on the sign-in event itself, which fires before the role is known and finds an empty queue.

## Not built
Web page for sponsor staff; file export for them; a mobile join screen for patients; changes to how an admin creates a sponsor staff login.
