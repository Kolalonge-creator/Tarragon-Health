# S38f: sponsor staff read their programme's monthly figures (mobile)

Decision (founder, 2026-10-07): a sponsor's own staff get access in the mobile app and see their group figures there (OQ-258).

## Who
The existing institution logins `hmo_admin`, `corporate_admin`, `ngo_admin`. They are already kept out of every patient table (`private.is_org_staff` excludes them, spec I9) and that is untouched. A login counts as sponsor staff only when it is active and its role matches the type of its own organisation. They see only programmes whose `sponsor_org_id` is that organisation. No new account role (CLAUDE.md: never re-split `profiles.role`) and no link table.

## What
Never the live report. A daily job writes one snapshot per programme for the month that has just closed, after the grace days, once. A snapshot is never changed or deleted and no user can read the table. Sponsor staff read snapshots only, through two functions. The snapshot is the same aggregate as the admin report: only members who agreed under the current consent text, never a test account, small groups withheld whole with complementary suppression.

Only the latest closed month is ever written, and only from the grace days until a week later, for programmes that existed and were valid in that month. After that window a gap is left rather than a figure built from data that no longer describes the month; a failing run opens an incident daily. Older months are never rebuilt from today's consents.

A refused read (another sponsor's programme, or one that does not exist) returns `{ok:false}` and is itself written to the audit log; listing programmes is audited too.

## Threat notes
- Two live runs a day apart cannot be subtracted: there is no live run for sponsors.
- Figures across months cannot be subtracted to expose a few people: a month that differs by a small number of people from the last published one is held back (above). A larger change is published; the people in it are at least the minimum group size.
- A programme that is not yours and one that does not exist get the same refusal.
- Every read is in the audit log. The sign-up code is visible while a programme is open because the sponsor hands it out; it is hidden once closed.
- Sponsor staff never see a member, a list, a name or a count below the minimum.

## Closing the month-to-month weakness
Each snapshot stores (privately, never returned) the set of people its figure was drawn from. If that set differs from the one behind the last published figure by a small number of people (more than none, fewer than the minimum group size), the month is published as held back and the comparison stays with the last published figure, so the difference builds up until it is large enough to publish. Two published months can therefore no longer be subtracted to expose a few people.

## Web and files
Sponsor staff with a web login (corporate and HMO admins) get a "Programme figures" tab under their own dashboard with the same figures and a download as a file. The download is a POST, writes the access to the audit log first and gives no file if it could not be logged; another sponsor's programme and a missing one get the same answer. NGO partner staff get the same page and download in the staff console at /ngo/programme-figures (the NGO area lives there), so a partner can use the phone app, the web console or both on the one account: the phone app signs in with a phone number or an email, the console with an email. The pages and the download rules are shared code in packages/staff-core (sponsors/), so web and console cannot drift. The ngo_funded_cohort module gate moved from the NGO layout to the overview page, so the figures do not depend on that module being switched on.

## Patients on the phone
A Programmes screen in the patient app: join with a code, see the programmes joined, turn sharing of group figures on or off, leave. Same rules as the web page; nothing changes while acting for someone else.

## Staff logins
A Super Admin creates a sponsor staff login at Admin, Settings, Members by choosing hmo_admin, corporate_admin or ngo_admin and the sponsor's organisation (the existing flow; delegates cannot create these roles). The organisation's type must match the role or the login sees nothing.

## Mobile
After sign-in the app reads the role. Sponsor staff land on a figures-only screen; the patient shell, health sync, push-token registration, offline vitals queue, reminder top-up and review prompts do not run for them. The one exception is the outbox flush on the sign-in event itself, which fires before the role is known and finds an empty queue.

## Not built
An email notice that a month's figure is ready (not asked for; the figure is on the page and in the app). Sponsor staff cannot change anything; they only read.
