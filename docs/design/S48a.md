## The gate

Inputs: red and amber `triage_events` (shadow rows count, because the gate only restricts), active conditions, and pregnancy.
Output: `allow | restrict | rest`, a reason code, the most intense level allowed (`gentle | moderate | vigorous`, or `none` for rest), and the kinds blocked.

- A red event inside `red_hours` (48) is rest, whatever else is true. No workout is offered and no programme can be started.
- An amber event inside `amber_hours` (48) is gentle only.
- Pregnancy, high-risk pregnancy, hypertension that is not settled, arthritis and back pain each lower the allowed level and block kinds.
- No config row, an unreadable clock, or an answer a client cannot parse fails closed to gentle only. It never fails to allow.
- Every number, pattern and blocked kind is in the versioned PROPOSED config (`activity_safety_config`, registry key `activity.safety_rules`). The CMO signs it on the sign-off hub. The gate enforces the unsigned rows as they stand because it can only make activity gentler; signing records review.

## Where it is enforced

1. Database function `public.activity_gate()` (self only) and `private.activity_gate_for()` (not callable by any client).
2. `private.enforce_exercise_readiness()` on programme enrolment: rest refuses every programme, restrict refuses a programme above the allowed level. The trigger now also fires when an enrolment is flipped back to active by UPDATE (it was insert-only, so a patient could re-activate an abandoned row past the screen).
3. `my_workout_plans()` filters plans by the gate and by each plan's `conditions_safe_for`.
4. Web `patient/exercise` and mobile `ExerciseScreen` read the gate; they only decide what to show. Logging an activity that already happened is never blocked.

Pregnancy status is read only inside the definer function, for the signed-in person about themselves. The refusal wording names no reading, condition or pregnancy.

## Routes (5.7) and decision S48-1

`activity_routes`: owner-only select, insert and delete; no update policy; no staff, admin or caregiver policy; not in the patient export registry; go-live guard `private_route_recording` born off plus a per-person switch born off. No UI records a route in this PR. A scan test asserts no application code references the table. Emergency location is a separate feature (S48-1) and is not built here.

## Not built

- Recorded or written audio for plans (the `audio_clip_ids` column is empty by design). The three starter plans are written text, `clinician_reviewed = false`, inactive, and invisible to patients until a clinician reviews them.
- A platform pedometer fallback: `expo-sensors` is not installed, and `Pedometer` needs a new native dependency plus `NSMotionUsageDescription` on iOS and `ACTIVITY_RECOGNITION` on Android. That is a new EAS build and a `runtimeVersion` bump, so it was left. Steps still arrive through the existing HealthKit and Health Connect bridge.
- Mobile activity-kind picker and distance field, and a mobile weekly-goal editor (the mobile Movement screen shows the week against the goal).
- Training load, recovery and readiness (S48b); challenges (S69).
