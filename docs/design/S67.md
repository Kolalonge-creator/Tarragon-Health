# S67 design note: pregnancy (module 16, 16.5 to 16.8)

Invariants in play: INV-01 (no model in triage), 02, 05 (a red pregnancy event pages), 06 (works offline), 07 (neutral notifications), 09 (no balance), 10 (audited staff reads), 12, 13 (`is_test`), 14 (guard), 15 (kobo), 16 (versions). Research: `docs/research/S67.md`. Decisions: CMO selections A1 to A5 in `docs/plans/S66-S70-cmo-signoff-pack.md` (selected, **not signed**). Nothing in this session is signed, approved or switched on, and no migration was applied to any database.

## 1. What already existed (extended, not rebuilt)
`patient_pregnancy` (one row per patient, current state), `antenatal_visits` (zero caregiver access, patient and staff), the pregnancy card and form, `gestational-age.ts` (web and mobile, kept), the BP rule set `bp_care_triage` v1 to v3 (BP-P1, P3, P4, P5 already pregnancy and postpartum rules), `pregnancy-red-flag-check` writing `emergency_events` (source `pregnancy_symptom_checklist`), `refreshObstetricStatus` on the phone (OQ-90 option a, flag only), the S10 outbox, the S37 guards, the S06 phone outbox, `PREGNANCY_DANGER_SIGNS`. Reproductive-health category and break-glass exclusion unchanged.

## 2. Data model (migrations `20261007163117`, `163243`, `163405`, `163526`; none applied)
- `pregnancies` (history): state `active|delivered|loss|ended_unspecified`, `risk_flags text[]` (care team only), `lmp`, `edd`, `outcome`, `source`, `recorded_by` (ON DELETE RESTRICT), `is_test`, `organisation_id`. One active per patient (partial unique index). `patient_pregnancy` stays as the **current-state projection** the triage context, phone and web card already read; two triggers keep them in step (each acts only on a direct write, so no loop). Backfill moves live rows (0 today: patient_pregnancy 0, antenatal_visits 0, read-only on 2026-10-07).
- `pregnancy.recorded` registered in S10 (`event_types`, version 1, ids only), emitted when a pregnancy starts or its state changes. No subscriber is registered: the BP rule set, content and danger signs switch because every reader looks at the current state when it grades or renders (a subscriber with no handler would only sit dead).
- `antenatal_visits` gains `pregnancy_id`, `target_week`, `schedule_version`, `source`, `recorded_by`, `is_test` and a unique `(pregnancy_id, visit_number)`; `generate_antenatal_schedule()` (security invoker, so RLS applies) inserts contacts from a week list the server passes from the versioned config, `on conflict do nothing`, never overwriting a row a person touched. `antenatal_schedule_review_prompt()` (staff only, audit-logged) returns reasons an earlier contact may be wanted (risk flag, amber BP-P1 in 14 days). It is a prompt to a person; the schedule is never changed automatically (A5).
- `kick_counts`, `contractions` (one row per session; `client_id` unique per patient so an outbox replay is a no-op), `birth_plans` (one per pregnancy, `money_plan_kobo bigint` as a note, no balance or wallet column, E.164 phones).
- `pregnancy_content` (kinds week, nutrition, medicine_safety, danger_signs): `review_state` `draft_pending_cmo` or `cmo_reviewed`; patients read only reviewed rows; no write grant, **no row seeded**; `audio_clip_id` is the S32 manifest seam.
- Symptom values `convulsion`, `loss_of_consciousness`, `sudden_face_hand_swelling` added to `symptom_type` (own migration, spliced into `packages/shared` types by hand: a regeneration would import other branches' schema).

## 3. RLS (fresh, reproductive_health category; not copied from a sibling)
SELECT: the patient, org staff (`private.pregnancy_staff_may_read`, one helper so the S39b tied-staff rule changes in one place, OQ-345), or a caregiver with an explicit `reproductive_health` category grant AND the adolescent guardian gate. **No** emergency branch (`has_emergency_access` refuses the category; a policy calling it would be dead text). Sponsor, employer, unrelated person and another organisation's clinician have no policy and read nothing. WRITE: the patient or staff only; a caregiver never writes (stricter than the menstrual tables, deliberately). Sessions are insert and read only. Explicit `grant ... to authenticated`, `revoke` from public and anon, helper functions revoked from public (not just anon) and granted to authenticated, every literal passed to `can_read_clinical` is cast, no overload added. A patient cannot set risk flags or reopen an ended pregnancy (trigger).

## 4. Rules (`packages/clinical`)
Rule set **v4 draft** = v3 plus `sudden_face_hand_swelling` in `preeclampsiaFlag` and a new group `obstetricEmergency` with rule **BP-P6** (a fit or loss of consciousness while pregnant or postpartum is red, pages on-call, no reading needed; a rejected reading still shows the guidance, engine change). A1 is confirmed unchanged: BP-P4 (>=140/90 with a danger sign, red), BP-P3 (either value >=160/110, red, page), BP-P1 (pregnant, amber, routed). Finding: BP-P1 routes every pregnant reading (task de-duplicated to one a week), wider than the wording of A1, left as is (OQ-340). Seeded as a draft row derived from the code object (test pins them equal); not approved. Acceptance tests: 150/100 at 30 weeks with headache red; 139/89, 140/90, 159/109, 160/110, 161/90, 120/111; not-pregnant falls to adult rules; sabotage (BP-P6 removed) fails 5 tests.
`packages/clinical/src/maternal/` (pure, config passed in): gestation, antenatal schedule, kick counter (10 in 120 minutes, personal normal = median of the latest 5 finished sessions once 3 exist, a clear drop at 2 times her normal, "less movement" button), contraction timer (5-1-1, 7-1-1 from the birth plan, instant-go signs, any contraction before 37 weeks). All numbers in registry keys `maternal.rules` and `maternal.bp_rule_set` (PROPOSED, CMO), mirror tested.

## 5. Offline (INV-06)
The phone caches the pregnant flag **and the dating** (`lmp`, `edd`) with the obstetric status, so the week is worked out offline; the bundled draft rule set is now v4, so BP-P3, P4 and P6 fire with no signal (tests: 150/100 with headache, 160/110, a fit, swelling with 140/90 are emergencies offline; without the cache they are not, which is the gap the cache closes). Kick and contraction sessions are decided on the phone, written to the one S06 outbox as new kinds (danger-flagged when the card says go) and replayed idempotently by client id. The danger-sign guide is bundled data outside any lock.

## 6. Escalation
A kick result `contact_today` or a contraction instant sign or before-37-weeks result inserts an `emergency_events` row (existing path: Priority 1 clinician alert, patient safety net), at most one an hour per patient. A 5-1-1 labour pattern is a go-now card but not an emergency alert. Red BP pages through the existing triage path (INV-05). Notifications: no template names pregnancy, BP or a condition; the one reminder string is generic and linted by test (INV-07).

## 7. Go-live guard
`maternal_enabled` inserted OFF into `go_live_guards`; conditions added by patching `private.go_live_conditions` in place: an approved obstetric protocol, an approved `bp_care_triage` carrying BP-P6, the NAFDAC and MDCN replies attested, and the CMO pressing the switch. The migration asserts it wrote no log, attestation, sign-off or approval row. It is not enforced in any screen yet (the guard says so on the dashboard).

## 8. Seams left clean
- **PIN lock:** `PregnancyPrivateSection` (mobile) is a pass-through wrapper; replace its body with S66's `PrivateSection` when it lands. The danger guide and emergency cards stay outside it.
- Audio: `pregnancy_content.audio_clip_id` and `DangerGuideEntry.audioClipId` (null until the S32 manifest has a signed clip).
- Screens for the counter, timer, birth plan, week card and schedule are not built (OQ-346); every piece of logic and storage they need is.
- S68: state `loss`, `delivered` and the transitions (16.11) set the same `pregnancies.state`.
