# S85-D1: blood pressure at or above 180/120 asks the emergency-symptom question

Status: DRAFT, unsigned. The Chief Medical Officer has not read or signed this. The migration is not applied to production.

## Decision (founder, binding, 2026-10-07)

A reading of 180/120 or more (either number) asks the emergency-symptom question. Today the line is 200/130.

- A symptom ticked, including "severe or new headache": RED. Offline emergency guidance, nearest facility, on-call page, consented Care Circle alert, follow-up task.
- No symptom: AMBER. A clinician makes contact the same day. Recheck after 2 hours (the existing reminder and backup push). The amber same-day task if the recheck is still high, or was never done.
- Pregnancy and the 6 weeks after a birth: unchanged.
- Deterministic only. No model in the path (INV-01).

## What the repo said before this work

The engine (`supabase/functions/_shared/clinical/engine.ts`) reads `params.extreme` and `params.extremeRecheck` and holds no 200/130 of its own. - So the whole change is data: version 4 = version 3 with `params.extreme` set to 180/120. No engine change, no rule change.

## What a reading now does (version 4, once approved)

| Reading | No answer yet | Symptom ticked | Answered "none" |
|---|---|---|---|
| 179/119 | 5 minute repeat (unchanged) | amber with emergency guidance and a task (BP-A6, unchanged) | n/a |
| 180/119, 179/120, 180/120 | ask the question (BP-X1) | RED (BP-R1) | recheck after 2 hours (BP-X2) |
| 190/120 | ask the question | RED | recheck after 2 hours |
| 200/130 | ask the question (unchanged) | RED (unchanged) | recheck after 2 hours (unchanged) |

Recheck after 2 hours (window up to 4 hours): still at or above 180/110 gives the amber same-day task (BP-A1, due in 4 hours); lower is graded on its own; no recheck in time gives the amber task. Pregnancy, postpartum, under 18 and low-reading rules are untouched.

Readings with a systolic of 180 to 199 and a diastolic below 120 are the ones that change. Seven old fixtures (SC-03a, b, c, d, f, g, h, all 181/111 or 182/112) change as a result: they now reach the question first. A property test sweeps 60/30 to 260/140 across symptoms, pregnancy, postpartum and age 16 and proves a red under version 3 is a red under version 4 with the guidance and the on-call page, and that no symptomatic grade falls.

## Where the phone and the server get the line

- Phone: `apps/mobile/src/lib/triage-device.ts` grades with the cached APPROVED rule set and shows the question only when that set is approved (`shouldAskSymptomQuestion`). It holds no 200/130; only comments mentioned it, now updated. The bundled fallback stays version 2 (a draft), deliberately: an unsigned version 4 must never be what a phone falls back to. A new test (`s85d1-bp-180-120-device.test.ts`) proves the same reading asks under a cached version 4 and not under version 3.
- Server: `triage_rule_set_for_grading` and `get_approved_triage_rule_set` prefer the approved row, so while version 3 is approved the draft is never used. The older alert path (`private.handle_bp_reading_red_flag`, `handle_symptom_red_flag`, S11g) reads `params.severe` only (unchanged) and the fixed `classify_bp_level` bands, where any reading from 160/100 already raises the Priority 1 clinician alert. That is the "clinician contact the same day" for the no-symptom case, and it needs no change. The DB proof asserts neither function reads `params.extreme` and the bands are unchanged. No S11g-style change is needed, so nothing was added to the legacy path.
- Web: there is no web question sheet; the web side of this is the CMO's review screen, `/clinician/triage-rules`, which lists the newest draft from `triage_rule_sets` once the migration is applied. Nothing more to register: it is the sign-off route for this item.

## Hazards worth knowing

1. Applying the migration adds a draft row and nothing else. While nothing is approved (a fresh local replay), the grader takes the newest draft (shadow only, OQ-88), so on a fresh stack version 4 is the shadow set. Live, version 3 is approved and wins.
2. Approving version 4 retires version 3. That is the CMO's signature, by `approve_triage_rule_set`. The S11c guard that refuses an older version does not stop it (4 is newer).
3. One notch stricter than the founder wording: at the 2 hour recheck, the amber task still fires at 180/110 (`params.urgent`), not only at 180/120. This never lowers a grade. It is the CMO's open decision 2.
4. The first reading is amber only after a failed or missed recheck; the same-day clinician contact comes from the existing Priority 1 server alert (plan-gated by `vitals_red_flag_doctor_escalation`, as before; on Free the patient gets the self-care suggestion and emergency safety net).
5. **Phones that have not synced.** Approving version 4 changes what a phone does only once it has refreshed its cached approved copy (online, `refreshApprovedRuleSet`). A phone that is offline, new, or whose cache was dropped grades with the bundled version 2 (200/130) and the older on-device check, so between 180/120 and 199/129 it shows no question until it syncs. `rulesMayBeStale` only warns. Before approving, the founder should decide how long to wait (or whether to force a refresh through an OTA) before relying on the new line. The bundled fallback is deliberately not moved to version 4: an unsigned set must never be a fallback.
6. **Same-day contact depends on the plan.** The Priority 1 clinician alert is raised only when the patient has `vitals_red_flag_doctor_escalation` (paid plans); on Free the patient gets the self-care suggestion and the emergency safety net, as before. Its text still says "rest 5 minutes and re-check", which now disagrees with the 2 hour recheck the phone shows. Changing that legacy text means rewriting `handle_bp_reading_red_flag`; it was not done here (S11g precedent: legacy changes only when needed, and this one is wording, not a grade). Flagged for the CMO and founder.
7. **Channels with no question.** The server grades every reading as "symptoms answered" (`triage_context_for_observation`), and only the phone has the question sheet. A reading from the web, a BLE device or a wearable between 180/120 and 199/129 with no symptom logged is graded BP-X2 (2 hour recheck) where version 3 gave the 5 minute repeat. A symptom logged within 10 minutes of the reading still gives RED. This gap existed from 200/130 in version 3; version 4 widens it to a more common band. Not closed here (no web question sheet exists).
8. **The open question is not persisted.** The phone keeps the question in memory; if the app is killed with the sheet open, the saved reading is not re-asked (the server's unconditional "answered none" path and the Priority 1 alert still cover it). Pre-existing; the wider line exposes more readings to it.
9. **Rule text is neutral.** The rule JSON records the open decisions without the words "unsigned" or "draft", because an approved row is immutable.
10. **Registry.** `triage.bp_rule_set` gains a version 4 entry (proposed) so the go-live guards screen lists this item as waiting for the CMO. It names the newest rule set, not the live one; version 3 is the live one until version 4 is signed.
11. Under 18: BP-P2 still routes to a clinician with the same task; the adult repeat prompt that rides along at 180/120 and above becomes the symptom question. Pre-existing additive behaviour, pinned in the test.
