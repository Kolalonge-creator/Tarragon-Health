## Data model

### New table: `scribe_consents`

Per OQ-38, this table needs a source-of-truth encounter reference. OQ-38 recommends building it against whichever table S21/S23 makes authoritative. Since `clinical_encounter_notes` already exists with video/async/escalation links and is the signed record, `scribe_consents` references the note itself (the note IS the encounter documentation, and the consent must exist before the note's AI draft is generated).

```
scribe_consents
  id                  uuid PK
  organisation_id     uuid NOT NULL FK organisations
  patient_id          uuid NOT NULL FK profiles
  encounter_note_id   uuid FK clinical_encounter_notes  -- nullable: consent may be recorded before the note exists
  clinician_staff_id  uuid NOT NULL FK clinical_staff    -- who asked
  clinician_profile_id uuid NOT NULL FK profiles         -- server-derived
  granted             boolean NOT NULL                   -- true = patient consented, false = declined
  language            text NOT NULL CHECK (language IN ('en-NG', 'pcm'))
  recorded_at         timestamptz NOT NULL DEFAULT now()
  revoked_at          timestamptz                        -- patient can revoke mid-session
  created_at          timestamptz NOT NULL DEFAULT now()
```

**RLS:** staff-only SELECT (same org), clinical-tier INSERT, no UPDATE of `granted` after creation (immutable consent record), no DELETE.

**Key invariant (INV-11):** a `SpeechToText.startStream()` call requires a `scribe_consents.id` where `granted = true` AND `revoked_at IS NULL`. The adapter checks the id is present and well-formed; the calling edge function proves the consent row exists and is valid before asking.

### Existing table changes: `clinical_encounter_notes`

Add (S23 migration):
```
scribe_consent_id    uuid FK scribe_consents  -- which consent authorised the AI draft
patient_summary      text                     -- plain-language summary in the patient's language
patient_summary_language text CHECK (... IN ('en-NG', 'pcm'))
```

`patient_summary` is generated by the same Claude call as the structured note. It is visible to the patient only after the clinician finalises the note (the existing RLS + `ai_drafted` column already enforce this). The `patient_summary_language` records which language variant was generated.

### New table: `scribe_transcripts`

Stores the STT output, encrypted at the column level, linked to the consent and encounter.

```
scribe_transcripts
  id                  uuid PK
  organisation_id     uuid NOT NULL FK organisations
  scribe_consent_id   uuid NOT NULL FK scribe_consents
  encounter_note_id   uuid FK clinical_encounter_notes
  segments_encrypted  bytea NOT NULL          -- encrypted JSON of TranscriptSegment[]
  duration_ms         integer NOT NULL
  language            text NOT NULL
  created_at          timestamptz NOT NULL DEFAULT now()
  expires_at          timestamptz NOT NULL    -- retention-governed, default 90 days
```

**RLS:** staff-only SELECT (same org, clinical-tier). No patient access ever. DELETE governed by retention (a cron or trigger after `expires_at`). `segments_encrypted` uses `pgcrypto` with a key from Vault, not a column in the table.

**Why store the transcript at all:** the clinician may need to re-review what was said (Abridge's "Linked Evidence" pattern). The retention period is a PROPOSED value (default 90 days, configurable by the founder via `packages/shared/src/proposed-config`).

## AI governance registration

New system: `scribeDraft` with code `AI-017`.

```typescript
// system-codes.ts addition
scribeDraft: {
  code: "AI-017",
  failClosedIfGovernanceUnavailable: true,
},
```

**Rationale for fail-closed:** the scribe draft writes clinical content that a clinician will sign into the patient record. If governance is unreachable, the fallback is the existing manual note editor (which is the pre-existing path and costs nothing). Risk class: `high`. Autonomy level: `assistive` (clinician reviews and edits every output before it enters the record).

**Registration migration:** inserts into `ai_systems` with `is_enabled = false`, `runtime_governed = false`. The system stays disabled until OQ-96's STT vendor scoring is complete and the founder enables it. The edge function call site must consult `ai_runtime_config()` before proceeding.

## Event flow

```
1. Consultation starts (video, in-person, phone)
   └─ Clinician sees "Start AI Scribe" button

2. Clinician presses "Start AI Scribe"
   └─ Patient sees consent screen (CON-001)
      ├─ Patient grants → scribe_consents row (granted=true)
      │   └─ Clinician sees "Recording..." with pause/stop controls
      │       └─ Audio streams to STT adapter via edge function
      │           └─ Segments arrive in real time
      └─ Patient declines → scribe_consents row (granted=false)
          └─ Scribe controls disabled. Clinician writes note manually.

3. Clinician presses "Stop recording" (or call ends)
   └─ STT adapter returns full Transcript
       └─ Transcript encrypted and stored in scribe_transcripts
       └─ scribe-draft edge function sends transcript + structured context to Claude API
           ├─ Context: patient demographics (age, sex), active conditions, current medications, reason for encounter
           │   (read from the patient record by the edge function, never by the AI)
           ├─ Fixed prompt with prompt caching enabled
           ├─ Output: structured note (history, examination as reported, assessment, plan, safety-net advice)
           │          + patient summary in patient's language
           ├─ No medication changes ever written by this function (INV-02)
           └─ Draft written to clinical_encounter_notes with ai_drafted=true, status='draft'

4. Clinician sees draft labelled "AI draft, not saved to record"
   └─ Clinician edits freely (text fields)
   └─ Clinician presses "Sign and save"
       └─ status → 'finalized', finalized_by_staff/finalized_at stamped server-side
       └─ Note + patient summary become visible to the patient (existing RLS)
       └─ ai_interaction_log row recorded (governance audit trail)

5. If patient revokes consent mid-session
   └─ scribe_consents.revoked_at stamped
   └─ STT stream stopped
   └─ Any partial transcript deleted from scribe_transcripts
   └─ Clinician notified, continues with manual note
```

## Screens

### Clinician side (within consultation view)

1. **"Start AI Scribe" button** -- visible only when `ai_systems.is_enabled` is true for AI-017 and the patient has not already declined consent for this encounter.
2. **Recording indicator** -- "Recording..." with pause/resume/stop controls. Shows elapsed time. A "Patient revoked consent" state disables all controls.
3. **Draft review panel** -- after recording stops and Claude returns the draft. Each field (history, examination, assessment, plan, follow-up, patient summary) is an editable text area. Header: "AI draft -- not saved to the patient record". Footer: "Sign and save" button.

### Patient side

1. **Consent screen (CON-001)** -- shown when the clinician initiates the scribe. Copy (PROPOSED, in `packages/i18n`):
   - en: "Your care team would like to use an AI tool to take notes during this consultation. The tool will listen to the conversation and create a draft summary, which your clinician will review and edit before it becomes part of your record. You can say no, and your care will not be affected."
   - pcm: "Your care team wan use AI tool take note for this consultation. The tool go listen the conversation and create draft summary, wey your clinician go review and edit before e enter your record. You fit say no, e no go affect your care."
   - Two buttons: "I agree" / "No, thank you"
2. **Patient summary** -- visible on the patient's health record only after the clinician finalises the note. Labelled "Summary of your visit on [date]".

## Safety rules

### Safety case 14: consent declined

- `scribe_consents.granted = false` recorded.
- STT adapter's `startStream()` cannot be called (requires a valid `scribeConsentId` where `granted = true` and `revoked_at IS NULL`).
- The "Start AI Scribe" button disappears for this encounter (or shows "Patient declined" disabled state).
- Clinician proceeds with the manual note editor (the existing `clinical_encounter_notes` INSERT/UPDATE path, unchanged).
- **Proven by:** RLS test inserting a `scribe_consents` row with `granted = false`, then attempting to call the STT function with that consent id -- must fail.

### Safety case 15: AI draft never visible to patient before signing

- `clinical_encounter_notes` SELECT policy already restricts to `private.is_org_staff(organisation_id)`. No patient-facing SELECT policy exists.
- `ai_drafted = true` notes in `draft` status are invisible to the patient by construction.
- After `finalized`, the note (including `patient_summary`) becomes visible to the patient through the existing patient-record SELECT policies added by S05.
- **Proven by:** simulated patient session attempting to SELECT a `draft` + `ai_drafted = true` note -- must return zero rows. Same patient session after `finalized` -- must return the note.

### INV-11: AI scribe drafts never written to patient record until clinician signs

- The `enforce_clinical_encounter_note_attribution` trigger forces `status = 'draft'` on INSERT and stamps `finalized_by_staff`/`finalized_at` only on the explicit `draft → finalized` transition.
- The edge function writes with `status = 'draft'`, `ai_drafted = true`. The trigger enforces this regardless of what the client sends.
- Already enforced. No new code needed for this invariant.

### INV-02: no medication/treatment change without clinician signature

- The `scribe-draft` edge function's Claude prompt must never include instructions to write medications, doses, or treatment changes. The prompt explicitly instructs: "Do not include specific medication names, doses, or prescribing instructions in the plan section. The plan describes the clinical reasoning and next steps; actual prescriptions are entered separately by the clinician."
- The edge function writes only to `clinical_encounter_notes` text fields; it has no access to `medications`, `prescriptions`, or any treatment table.
