## 3. Logic
- Exclusions: active serology rule first (hep_b, hep_c annual, `repeat_not_due:<date>`; hep_b stops on recorded immunity); a live override lifts `owned_by_pathway` only. `screening_due` (calendar) agrees.
- Immunity: AFTER INSERT trigger on a lab item `anti_hbs` (positive flag, or a titre once the threshold is confirmed) and doctor RPCs; never overwrites chronic HBV.
- Report: SQL collector (facts only, released non-sensitive results, no sensitive screening item) -> pure TypeScript composer in `packages/clinical` -> service-role writer behind the guard -> sign-off queue. DB honesty guard re-checks every rule. Signing wipes `ai_draft`; signed rows are immutable; a correction is a new version with a note.

## 4. Events, services, screens
Events `health_report.generated`, `health_report.signed` (ids only). Service: `GET /api/cron/health-report-build` (bearer secret, not scheduled, builds nothing while the guard is off). AI-019 drafts the paragraph through `runGovernedAi` (registered disabled). Screens: patient `/patient/health-report` and A4 black-and-white PDF (`?variant=shared`), clinician `/clinician/health-reports`, per-result guidance and the standing disclaimer on results, calendar, risk check.

## 5. Safety rules (each has a test)
No on-target without a value inside the window; BP below the minimum count says too few readings; max three priorities; borderline never on target; no optimal, biological age, healthspan or percentile; no HIV or hepatitis word anywhere in a report; an unsigned report is invisible to the patient; AI text never reaches the patient before signature; an override never lifts a terminal state.
