# S69b Design: Care Circle presets, weekly digest, shared jobs and a gentle nudge

Branch `s69b-care-circle-presets`. Built on S29 (`docs/design/S29.md`), S29c, S29e and CGJ. Patterns taken from Medisafe Medfriend, Apple Health Sharing and Lotsa Helping Hands (the reference details are U, not re-verified in this session). Open questions: OQ-S69b-1 to OQ-S69b-6.

## What changed, in the order the brief listed it
1. **Presets and the preview.** `packages/shared/src/care-circle-presets.ts`: "Can see" (adherence_summary, weekly_bp_trend, appointments, red_alerts) and "Can see and help" (the same plus pay_for_care). A preset is only shorthand for the existing permissions; "Choose one by one" leaves the tick-boxes. `previewForPermissions` builds the plain-language lines from the real permission list, so the preview cannot promise more than the database shows. It is shown to the patient before an invite is made and to the invitee on the join screen before Accept (web `PermissionSummary`, phone `PermissionSummary`), including the line that the other person can see each time they look. A supporter in another organisation sees the list without payment and jobs.
2. **Waiting for them.** `decline_care_circle_invite(token)` ("Not now") kills the link for the invitee and tells nobody. It changes no column the sender can read: the invite stays `pending` (so the cap and the daily limit count it as before) and is made dead by using up its wrong-try allowance. `my_care_circle` returns it as "waiting" until it expires. The sender can still cancel it. The word "declined" is not in anything the sender can read (a test checks the copy and the web screen).
3. **Weekly digest.** `circle_weekly_digest(patient)`: computed on read through the one gate `circle_member_for`, so a paused or ended circle gets the same not-found. A block exists only if its permission is held; it carries days (doses taken on N of M days, readings logged on N of 7 days, next appointment, job counts), never a value. A weekly cron (Monday 07:00 Lagos) sends one generic notice, "Your circle has an update" in push and email text, "Your Care Circle weekly update is ready" in the inbox. Module `care_circle_digest`, OFF.
4. **Shared jobs.** `care_circle_tasks`: a fixed list of kinds and an optional date, no free text, no chat. Post: the patient or a helper (pay_for_care). Claim: a helper, first one wins. Complete: the claimer or the patient. Release: the claimer. Remove: the poster or the patient. A supporter reads through `circle_tasks` (logged, pause-aware) and never the table. The hourly sweep returns a removed helper's job to open and cleans up. Module `care_circle_tasks`, OFF.
5. **Gentle nudge.** `private.sweep_circle_missed_doses` every 5 minutes: for a supporter the patient opted in (and who still holds adherence_summary), a dose slot (from `private.medication_slots_on`, so dates, weekdays and tapers apply) with no answer after the grace period (PROPOSED 30 minutes) and inside the next 60 minutes gets one routine-priority notice per slot, at most 3 a day, dedupe in `care_circle_missed_dose_alerts`. It holds back the extra window minutes while `care_circle_checkin_window` is on. It never reads a page or triage event; `private.notify_circle_red_alert` is not touched and a proof step checks a red event still reaches supporters at once. Module `care_circle_missed_dose_alert`, OFF.
6. **Who looked.** The digest, the job list (and posting by a helper) and the nudge list each write a `record_viewed` line in `care_access_events` (scope `care_circle`), which is the list the patient already sees. The patient changing the nudge switch writes `permission_changed`.

## Rules kept
INV-07 (no name, reading, dose or condition in push or email; the inbox line for the nudge says only that someone may like a call), INV-01 (no model anywhere), no SMS or WhatsApp, everything visible in the app, reproductive_health unchanged, every module born OFF, no signed rule, new tables RLS-on with grants checked in the migration, `from public` revoked on every new function.
