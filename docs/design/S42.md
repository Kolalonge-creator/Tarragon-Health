## 3. Screens
Web: privacy page gains the consent matrix (simple bundles, "every choice" view, two-tap off, "switch off everything optional", history), the proxy arrangements card, the privacy summary with the audio seam; data-rights panel offers PDF and data-file downloads once an export is fulfilled; the patient layout shows the hand-over card; the family page shows guardians a heads-up. Mobile: the same matrix on the privacy screen, set-up/confirm/end for a parent, and the hand-over, on Home and Family.

## 4. Safety rules
- A needed-for-care consent cannot be withdrawn through any path (trigger). Withdrawing an optional one never changes access to care: no care access function mentions the matrix (proof scans their source).
- Hand-over: the 18th birthday, the young person's own login and their own choice; every guardian not ticked loses access; the kept one is view only.
- Proxy: nothing before the parent confirms; the parent always sees who set it up and can end it in one tap.
- Reproductive data: category checks written fresh, proven with simulated sessions and a control that the gate opens.
- Events carry ids and counts only. No notification text was added. No language model anywhere.

## 5. Go-live guard
No clinical content. The wording is draft (`wording_status = 'draft_pending_counsel'`, a visible notice on every matrix screen) and must be approved by counsel before the matrix is presented as legal consent (OQ-330). Account deletion is admin-initiated only. The research roster is the single door for any future research export (none exists yet).
