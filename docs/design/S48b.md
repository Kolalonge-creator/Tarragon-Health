# S48b: phone parity, workout plans, private routes, device readiness (v5 Module 5: 5.2 to 5.7)

Builds on `docs/design/S48a.md`. What S48a left, and what this closes:

| S48a gap | S48b |
|---|---|
| No activity-kind picker, distance field or weekly-goal editor on the phone | Built in the Movement screen; a workout is saved on the phone first (outbox kind `activity`, `activity_log_entries.client_id`) |
| Plans UI | Already shown on web and phone by `my_workout_plans()`; now ordered (chair-based first from the older-adult age), 10 to 20 minute rule in the database, text steps, DRAFT audio slots only |
| Route recording had no UI | Pure recorder + stubbed-source tests + owner-only store + a card shown only when the guard AND the person's switch are on |
| Training load / recovery / readiness | `assessReadiness` (pure), config `activity.readiness_bands`, cards that stay silent without device data |

## Rules kept
- The gate decides what is allowed; readiness and plan ordering never change it and never say "push harder".
- Routes: owner-only, three policies, no share/export/map/send path anywhere; `routes-private.test.ts` scans for one.
- Nothing recorded or generated (audio, video). Nothing signed. No guard turned on.
- Native: private route recording needs `expo-location` (new EAS build, permission text, `runtimeVersion` bump). Not done here.
