# S61 design note: condition pathways (Module 13, pathway half)

Branch `s61-s62/pathway-engine`. Built on the S62 engine (see `docs/design/S62.md`); S61 is config + rule sets + tests. All values PROPOSED from `docs/plans/S61-S65-cmo-signoff-pack.md` (decisions Q1 to Q12); nothing signed.

## Fix-first set
- Glucose thresholds moved out of `apps/web/src/lib/vitals/glucose-red-flags.ts` and `apps/mobile/src/lib/glucose-red-flags.ts` into PROPOSED config `diabetes.glucose_thresholds` v1 (same numbers). A guard pattern in the repo scan stops them being typed again; parity tests pin web, mobile and the config together; the served threshold version is now the config version.
- Inputs added: confusion, seizure, unresponsive, needed help (`vitals_readings.glucose_events`). Legacy classifiers: any event below the low line is an emergency. The legacy classifier still treats 3.0 to 3.9 as "urgent" (alert tier) and is unchanged for that band; the new rule set follows Q5 (amber, 15 g advice, `hypo_follow_up` task). Recorded as an open question.
- Q6 (a red pages on call for every plan): delivered by the diabetes rule set, not by changing the live Free-plan code path. Until the CMO approves the rule set, the draft grades as shadow and pages nobody; the live emergency handler is untouched.

## Pathways (packages/clinical/src/pathways)
- Diabetes `diabetes_care_triage`: triage and insights only, no titration proposals and no insulin, no medicine named in any rule (tested). Hypo: red below 3.0, or a danger event below 3.9, pages; 3.0 to 3.9 amber; insulin or sulfonylurea (or unknown) tightens the task due time; two Level 2/3 events raise a medication review task. DKA, very high, ketones, persistent high, recurrent low retained from the old classifier.
- Reporting only (Q7): time in range, HbA1c vs target (8% flags review), prediabetes screening label (never a diagnosis), weight BMI 25/30 and waist-to-height 0.5 (Q10).
- Cardiometabolic: runs each rule set, most urgent wins (Q9), property tested.
- Hypertension: severe BP tiering (Q3), targets (Q2), home validation (Q4) as pure helpers on PROPOSED config; DRAFT step table (Q1) as `pathways.hypertension_step_table`, seeded as a `protocols` row with status draft; the existing evaluator walks it one signed change at a time. "Start at step 2 for 160/100 to 179/109" needs a two-drug proposal the one-item format cannot express: open question.
- Asthma/COPD (Q11), heart failure and CKD (Q12) rule sets; sickle cell and post-stroke are registry scaffolds, guard off, no thresholds.

## Tests
Acceptance "glucose 2.8 mmol/L with confusion is red and pages on-call" (engine, web, mobile and DB), with sabotage steps; property tests; JSON round trip; migration-seed mirror tests; RLS and lifecycle DB proof.
