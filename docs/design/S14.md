# S14 design note: provider adapters

Spec: sections 3.1 and 10, decisions D-07 and D-08 (video: OQ-22, founder 2026-09-30, a Zoom adapter and a mock), invariants INV-01, 07, 08, 09, 11, 15. No new table, no migration, no screen.

## What exists
- `packages/integrations` is an empty placeholder written for this (its header says "Not yet built").
- `apps/web/src/lib/paystack/*` is a working Paystack REST client for the live subscription, booking and refund paths. `supabase/functions/paystack-webhook` verifies HMAC-SHA512 in Deno. `apps/web/src/lib/zoom/*` creates Zoom meetings for the existing video visits. `send-pending-notifications` calls Resend directly; S13 added the Svix check in `_shared/notifications/resend.ts`.
- None of that is touched. Live money, video and email paths keep working exactly as they do. The adapters are the seam later sessions move onto (S25 checkout and webhook, S31 transfers, S21 video, S23 scribe).

## Where the code lives
Edge functions cannot import a workspace package (same constraint as S10 and S13), so the source is plain TypeScript with no Node or Deno globals in `supabase/functions/_shared/integrations/`, and `@tarragon/integrations` re-exports it. Tests and contract suites live in the package. Web code, the console and edge functions all use one implementation.

## Shape
Every call returns `ProviderResult<T>` and never throws (the `ml-client` rule): `{ ok: true, data }` or `{ ok: false, error: { code, message, retryable } }`. Network, timeout, bad JSON and a vendor error all land there. `fetch`, clock and ids are injected so tests need no network.

- **PaymentProvider** (`payment.ts`): `initializeTransaction`, `verifyTransaction`, `refund`, `listBanks`, `resolveAccount`, `createTransferRecipient`, `initiateTransfer`, `verifyTransfer`, `parseWebhook` (signature check plus a normalised event). Integer kobo only, NGN only, references validated. There is no balance, wallet or top-up method, and a test fails if one appears (INV-09, INV-15). `paymentMatchesOrder` is the pure amount, currency and reference check that a "paid" decision must pass after verify.
- **VideoProvider** (`video.ts`): `createRoom`, `joinToken(role)`, `endRoom`, `subscribe` (device-side events such as connection quality) and `parseWebhook` (vendor presence and room-end events, signature checked). Rooms and tokens are opaque and carry no patient detail. `evaluateAudioFallback(samples, policy)` is the pure decision for audio-only mode; the thresholds are PROPOSED values in `video.audio_fallback` (registry), never constants.
- **SpeechToText** (`speech.ts`): `startStream({ encounterId, language, scribeConsentId })`, then `push`, `stop`, segments with `startMs`, `endMs`, `text`, optional `speaker`. A stream cannot start without a consent id (INV-11). No language model here (INV-01).
- **EmailProvider** (`email.ts`): `send` with a required idempotency key, `parseWebhook` reusing the S13 Svix check and event map. Patient email passes the S13 `lintText` at the adapter boundary, so a call site cannot send a clinical word (INV-07).
- Each has a mock (in memory, deterministic, can inject failures and quality drops). Paystack and Resend have real HTTP adapters (both already the chosen vendors). Video has a Zoom adapter, as decided in OQ-22: a scheduled meeting with the waiting room on, a Meeting SDK token (host for a clinician), and ending a room also deletes the meeting so it cannot be rejoined. Speech to text is the interface and a mock only: no vendor is chosen (D-08, OQ-96).
- `selectProvider` refuses a mock when `environment` is production, so a mock can never answer "paid" for real.

## Contract tests
`contracts/*.ts` export one suite per interface (`runPaymentContract`, and so on). The same suite runs against the mock and against the real adapter over a fake `fetch` that replays vendor-shaped responses. A live run is gated on a test key being present and skipped otherwise, so the later wiring session adds one line.

## Safety rules
Never throw. No secret in a result, error or log. No transcript text and no email address in an error. Mock refused in production. Provider choice is not made here; it goes in DECISIONS.md and OPEN-QUESTIONS.md.

## Out of scope
Termii SMS (S03, auth hook only, INV-08), Expo push (S13), Claude (S23), Paystack checkout, webhooks and transfers as product flows (S25, S31), and any migration of live code onto the adapters.
