# S10y Design: partner endpoint admin screen

Builds on S10x (`docs/design/S10x.md`). S10x shipped signing-key rotation, auto-disable and `partner_event_map` as database functions with no screen. This adds the screen: `/admin/ops/event-bus/partners`, admins only (`profile.role === "admin"`), linked from the event bus page, found by admin search.

## Screens
1. **Endpoints.** One card per endpoint: name, URL host only (never the full URL), environment, on/off, last success, last failure, failures in a row, switched-off time and reason, signing key version, queued events, and the grace end when a rotation is still in its window. Read through `admin_list_partner_webhook_endpoints()`, which never returns a secret.
2. **Rotate key.** Grace hours (1 to 168, default 24) and a confirm tick. On success the new secret appears once in a copy-once panel with the grace end. It is not in the address, not in a toast, not in the audit log, not logged. Leaving the page or pressing "I have saved it" removes it for good; to see a secret again, rotate again (refused while a previous grace window is still open).
3. **Switch back on.** Only for an endpoint that is off. A typed reason (10 to 300 characters) is required and goes to the audit log. Text states what happens next (below). Reason box warns not to paste secrets.
4. **Mappings.** Table of event types from `event_types` (active ones) with their current mapping. Create or change: pick the event type, the partner-facing type, and the id keys allowed through (must end in `_id` or `_ids`; person ids are refused by the database). Remove a mapping with a confirm. Starts empty and stays empty until a person adds one: 0 mappings is the intended launch state. A reminder says events carry ids only and that `process-events` must be deployed before the first mapping.

## States
Loading is the server render (no spinner needed; each read failing shows a `LoadFailure` card, never an empty "all fine" list). Empty: no endpoints ("Nothing is set up yet"); no mappings ("No event is sent to partners"). Errors after an action are a fixed sentence per cause (not authorised, still in grace window, invalid input, generic), never the database message. All controls are native form elements, labelled, keyboard reachable; results use `role="status"` or `role="alert"`.

## Safety rules
- Admin check in every action before any database call, and the database functions check again (`private.is_admin()`); a clinician is refused in both places.
- The new secret exists only in the action result and the browser memory of the admin who rotated. It is never revalidated into a page, never put in a redirect, and the actions do not log. The audit row carries version and grace hours only.
- **In-flight deliveries when a key rotates.** A delivery already claimed was signed with the old key; the partner still accepts it because the old key stays valid for the grace window. Retries and new sends are signed with both keys during the window (`X-Tarragon-Signature` v1 and v2 support), then the new key only. The partner must install the new secret before the grace end. Rotation never drops or re-queues a delivery.
- **Switching an endpoint back on.** Events emitted while it was off were queued (the enqueue function still writes rows for an auto-disabled endpoint), so they all send as soon as it is on, oldest first. The failure counter is reset to 0; if the endpoint is still broken it is switched off again after the same number of failures in a row (config `partner_disable_after_failures`, PROPOSED 20, floor 5), not on the first failure. The screen says exactly that. The open incident, if any, is not closed by this screen.
- Removing a mapping stops new events only; rows already queued still send.
- No mapping, endpoint or event type is created or changed by this build; `event_types.ordered` is untouched.

## Database
Additive migration `s10y_partner_endpoint_admin`: `admin_list_partner_webhook_endpoints`, `admin_list_partner_event_mappings`, `admin_reenable_partner_webhook_endpoint(id, reason)`, `admin_disable_partner_event_mapping`. Existing `rotate_partner_webhook_secret` and `set_partner_event_mapping` are used as they are. Proof: `packages/db/tests/s10y_partner_endpoint_admin.sql` (admin session, clinician control, sabotage of the reason check).
