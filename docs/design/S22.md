# S22 Design: written questions and clinical notes

Spec 8.5, 9.2, 4.3 (`notes`), 7.3 (`async_question`), 23.16; invariants INV-01, 07, 08, 10, 11, 12, 13, 15, 16. Founder decisions for this session (2026-10-06): written questions are a **Member benefit** with a monthly allowance; the patient sees the **published summary by default and may open the signed note once a clinician releases it**; the window is **24 hours** and a missed window credits the allowance; **no text-based diagnosis, ever** (a patient who needs one is called); adults only; build on `clinical_encounters`, not on S21's unmerged `encounters`. Research: `docs/research/S22.md`.

## 1. What exists (extended, not rebuilt)
`async_consults` (question, answer, status, `sla_due_at`, forge-proof answer stamp, entitlement-or-credit gate, auto-draft note trigger, `clinical_encounters` sync); `care_message_attachments` (private bucket pattern, server download route); S16 `async_question` task type (24 h, tier 1, `adult_general`); S17 `queue_next` / `queue_complete`; S10 event bus; S13 notification registry and lint; S05d audited note functions; the S05 `public.notes` view (draft, signed, amended derived from `status` and `amends_note_id`). Conflicts with the spec are recorded in OQ-150 to OQ-155.

## 2. Written questions
**Data.** `async_consults` gains `task_id`, `is_test`, `window_minutes`, `answer_kind` (`guidance` | `needs_more_information` | `needs_call`), `follow_up_until`, `window_missed_at`, `allowance_returned_at`, `no_diagnosis_attested`. New append-only `async_consult_messages` (the thread: patient or care team, 7 day follow-up) and `async_consult_attachments` (private bucket `async-consult-attachments`, patient folder, staff only through the server route). `status` keeps its four values (adding enum values mid-migration is unsafe); "needs more information" is `in_review` plus `answer_kind`.
**Config.** `async_question.behaviour` v1 (PROPOSED, CMO): `monthlyAllowance 4`, `windowMinutes 1440`, `followUpDays 7`, `maxPhotos 3`, `maxPhotoBytes 8 MB`, question length bounds, `timezone Africa/Lagos`. Live copy in `async_question_config` (versioned, one active row) mirrored by a drift test, the S16/S17 pattern. Each question stores the config version it used (INV-16).
**Intake gate (one function, one place).** BEFORE INSERT trigger: adult only (OQ-154); Member via the single seam `private.patient_is_member()` (OQ-150), or a grandfathered paid credit; allowance counted per Lagos calendar month, a question whose window was missed does not count. Free tier gets a neutral "members" message, no price shown to a non-member (INV-09).
**Red-flag screen (INV-01, INV-06).** The patient apps run the deterministic `packages/clinical` red-flag rules on the typed question and the structured symptom answers before sending; a hit shows the bundled "go to the nearest hospital now" guidance and blocks sending. The server repeats the existing deterministic care-message keyword screen on insert and, on a hit, raises the same `message_safety_flag` alert and creates the question as urgent guidance-needed, never silently queued. No model anywhere.
**Task.** AFTER INSERT creates the S16 task through `private.create_clinical_task(patient, 'async_question', window, 'async:<id>')` and stores `task_id`; emits `async_question.submitted` (ids only, INV-07). The clinician reaches it only through `queue_next` and the atomic claim; the claim is what lets them read the question (INV-12) and every read goes through an audited function (INV-10). The old direct staff reads of `async_consults` close in this session for the written-question path.
**Answering.** `public.answer_written_question(consult, kind, body, no_diagnosis_attested)`: needs the live claim and an eligible clinician. There is no diagnosis field; the clinician must attest "I have not diagnosed" (stored). `guidance` completes the task and opens the 7 day follow-up; `needs_more_information` keeps the task claimed or hands back with `needs_information` and asks one clarifying message; `needs_call` completes the written task and creates an `async_question_call` task for a call (due from config), so a diagnosis happens only in a call and its encounter note. Structural backstop: a CHECK that a note of type `async_consult` carries no `diagnosis`.
**Window (the thing no competitor publishes).** `private.sweep_written_question_windows()` (every 5 minutes, each row isolated): reminder to the claimer at 75 percent; at 100 percent the claim is released to the pool and the CMO alerted (event `async_question.window_missed`, `window_missed_at` set once); the allowance is returned (`allowance_returned_at`) and the patient is told neutrally. Never closes or drops the question.
**Patient.** Care tab "Ask your care team": allowance left, the published 24 hour window, structured fields, photo guidance, offline draft that survives a dead battery, compressed photos with metadata stripped, no photos of intimate areas (routed to a call), the thread, the follow-up window, the answer, "we will call you". All strings through `packages/i18n` (en, pcm), "your care team", no em dashes.
**Notifications (INV-07, INV-08).** New keyed templates, in-app and push and email only, no content: `written_question_received`, `written_question_answered`, `written_question_info_needed`, `written_question_window_missed`, `written_question_call_scheduled`; staff: `written_question_claim_reminder`. The old SMS `async_consult_answered` template is retired (INV-08).

## 3. Clinical notes (live `clinical_encounter_notes` wins, OQ-23)
**States.** The stored column stays `status` (`draft`, `finalized`); the S05 `public.notes` view is the spec surface (`draft`, `signed`, `amended`). No second stored state, no `body jsonb` (the history, examination, assessment, diagnosis, plan columns are the structured sections); both recorded in OQ-152. Signed is immutable (existing trigger).
**Amendment.** `public.create_note_amendment(original, kind, reason)` makes a linked draft (`amends_note_id`, `amendment_kind` addendum | late_entry | correction, `amendment_reason` required); finalizing it uses the existing signing path. The patient sees the original with a "corrected on" marker. `entered_in_error` is a flag on the original that is shown, not hidden.
**Release (founder decision).** New `note_releases`: `requested` | `released` | `declined`, who, when, `withhold_reason`. Nothing is released automatically. The patient may request it; the author or lead releases or declines with a reason; a note flagged `is_protected` (reproductive health and similar) is released only by the CMO. `my_released_notes()` and `read_released_note()` are the only patient routes and return `status = finalized` and `released` only (row-level security on the table has no patient policy; INV-11 enforced in the function and tested). The summary remains the default view.
**Patient correction request.** `note_correction_requests`: the patient's text sits beside the note; a clinician accepts (starts an amendment draft), annotates, or declines with a reason. Nothing is deleted. NDPA deadlines are unconfirmed (OQ-153); the response target is config.
**Unsigned notes.** `sweep_unsigned_notes()` reminds the author after a configured number of hours (PROPOSED 24, then 72 to the lead); the deadline is config (research found no authoritative figure).
**Events and audit.** `note.signed`, `note.amended`, `note.released` (ids only). Reads stay on S05d's audited functions (INV-10); a patient read of a released note is audited too.

## 4. Out of scope (logged as follow-ups)
Scribe, speech to text and AI drafting (S23); prescriptions and referrals (S24); S21's `encounters` swap-over; the same direct-read closure for `care_messages` and the existing summaries; real Member entitlement (OQ-150); minors (OQ-154).

## 5. Proof (Step 5)
`packages/db/tests/s22_written_questions_and_notes.sql` (registered in `ci.manifest`): grants (nothing for anon); allowance and member gate; task creation and claim-only reads; answer rules and the call path; the window sweep and allowance return; the notes release, amendment and correction rules; **patient RLS returns signed and released only, drafts never**; events carry ids only. Sabotage: widen the patient function to drafts and the check must flip; switch the allowance off and the gate check must flip. Jest for the shared config mirror, the red-flag gate and the notification lint.
