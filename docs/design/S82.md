# S82 design note: what the fix pass would change

Scope: fix gaps in `docs/audit-D1-D2.md`. No new features, no new tables, no new migrations, no new tiers. English only. Every number that is a threshold (reading grade ceiling, text caps) goes into `packages/shared/src/proposed-config`, not code.

## Reused, not rebuilt
Outbox (`lib/outbox.ts`), drafts (`lib/drafts.ts`), offline mirror (`lib/offline-store.ts`), low-data budget and media policy (`lib/offline-budget.ts`, `lib/media-policy.ts`, `lib/use-low-data.ts`), `ListenButton` and `packages/audio` screen maps, kit `Badge`, `MIN_TARGET`, `MAX_FONT_SCALE`, the a11y scan test.

## Changes, in order
1. **Drafts everywhere (M).** Add `useDraft(key)` over `saveDraft/loadDraft/clearDraft`; apply to wellbeing, lifestyle trackers, cycle, exercise screen, glucose and other vitals forms, medicine schedule, profile and family forms. Cleared when the entry is queued or saved.
2. **Queue the remaining questionnaires (M).** Extend `OutboxKind` for wellbeing check-in, lifestyle log and cycle log, reusing the idempotent client id rule. Check each target insert is append-only or idempotent first. Booking, ordering and payment stay online with a plain "needs a connection" message. Nothing that changes a medicine or dose is queued (INV-02).
3. **"What is this?" and tab tours (M).** One shared top-bar control resolves a screen key to an `HLP_CLIPS` clip: text help plus `ListenButton`. First open of each tab offers (never autoplays) the walkthrough via `tourOffer`; seen tabs kept in SecureStore; reachable again from Help. Test: every registered screen key has an HLP clip or a listed exemption.
4. **Wire ListenButton by clip family (M).** Results (RES), reminders (REM), onboarding (ONB), consent (CON), lessons, labs. Sensitive positive results are never spoken (INV-04). Assistant replies: record the decision as an open question; no new call site. Hidden automatically until a clip is recorded, so this is safe to ship ahead of the recordings.
5. **Low-data wiring (S).** Add `<RemoteImage>`/`<MediaPlaceholder>` that call `mediaDecision`; scan test forbids a raw remote `<Image>`. Route any audio download through `mediaDecision({kind:"download"})` with a mobile-data switch. On toggle, best-effort write `profiles.low_data_mode` (already patient-editable, RLS proven in `packages/db/tests/s02_identity_consent_audit_baseline.sql`); never block on it; read it as the default on a new phone. No schema change.
6. **Touch targets and text (S).** `minHeight: MIN_TARGET` on legacy `SecondaryButton`, `ChoiceChip` and `SmallGhostButton`; extend the scan to flag `paddingVertical` under 10 with no `minHeight`. Raise the 1.2 text caps in top bar, drawer and tab labels where the layout allows; lift literal font sizes under 12. Web shell icon buttons to 44px.
7. **Screen readers (M).** `accessibilityRole="header"` on screen titles in the kit; one-sentence text summary on each chart; add an axe check to a web patient smoke test. The TalkBack and VoiceOver pass stays a device task.
8. **Status icons (S).** Add icon beside the word on legacy pills and web meters, or swap to kit `Badge`.
9. **Strings and plain language (L, last).** Move hard-coded strings into `packages/i18n`; add a reading-grade report script and a deny-list test for internal names over `packages/i18n/src/en.ts`. Report first, gate later once the CMO agrees a ceiling.

## Safety rules for the fix pass
- No change to triage, thresholds, or anything in the INV-01 to INV-06 path. Emergency content stays bundled.
- Queue only what the patient entered; the server keeps its own validation and dedupe.
- Notifications never name a condition or reading (INV-07); no copy change may break that.
- Never say "your doctor", "cure", "instant doctor", "free healthcare". No em dashes.
- Audio recording and sign-off are not code; the fix pass makes the app ready and reports the count.
